## Что проверил и счёл верным

- Сводка свёрнутого блока больше не берёт `quotes.length` как номер версии: и строка, и карточка зовут `quoteVersionMap` / `pickActiveQuote`; «заменён» — предыдущий по `created_at asc` (`v{N}−1`), вход сортируется внутри и не мутируется. Юнит-тесты на desc-вход, тай-брейк по `id`, ветки accepted/sent/last покрывают правило.
- «Принято» шлёт только `{ id, status: 'accepted' }` — не `amount`, не `stage_id`, не `budget`. Подсказка «Перевести на Договор» открывает штатную `useTransitionStore.open`, и только если стадия с именем «Договор» в этой воронке строго впереди текущей и сделка не won/lost. Бюджет по-прежнему отдельной кнопкой в `QuotesTab` за `canUpdateDealBudget`. Триггер `stamp_quote_status` по-прежнему пишет только `sent_at`/`accepted_at`.
- Второе accepted: партиал-уникальность `quotes_one_accepted_per_project` на месте (053); при текущем `pickActiveQuote` (accepted перебивает всё) `canAccept` на уже принятом выключен через `QUOTE_STATUS_TRANSITIONS['accepted'] = ['sent']`. Кнопки собраны из этой таблицы, не из второго списка.
- Без права правки кнопок нет: `canEditQuotes` — `owner|admin|manager`, тот же конъюнкт, что `quotes_update` в 053; viewer/пусто роли не видят блок решения. Миграция 131 RLS не расширяет.
- Срок: `valid_until` — колонка `date`, счёт через `mskDateKey` + `diffDaysKey`, `now` — аргумент. `null` → «срок не задан» / `level: 'ok'`, без тревожного тона. Последний день (`daysLeft = 0`) ещё `soon`, не `expired`. Просрочка — «истекло {formatCalendarDate}». Порог 3 дня живёт в одном месте (`QUOTE_EXPIRY_SOON_DAYS`). Тесты на полдень МСК и на границу 23:30/00:30 МСК в одном UTC-дне есть.
- Раскладка: `@container` по ширине блока, не вьюпорта; по умолчанию одна колонка, две с `40rem`; `border-left` только внутри `@container`. Без поддержки контейнеров остаётся стопка без вертикальной черты.
- `QUOTE_COLS` намеренно без `rejection_reason` — SELECT до apply 131 не падает. Номер 131 свободен (последний файл в дереве — 130). `DealWaitingList` при пустых колонках `paused` возвращает `null`. Хуки в новых компонентах стоят до early return. `isPending` реально `disabled` на «Принято»/«Отклонить».

## Чего не смог проверить

- Живую БД и apply 131: что PostgREST после add column принимает PATCH с `rejection_reason` и что schema cache не отдаёт PGRST204.
- Браузер: двухколоночный `@container` на реальной ширине зоны «Работа» (~600px рядом с рельсой 356px) и отсутствие черты в одноколоночной стопке.
- `tsc` / runtime на ветке: рабочее дерево сессии на `main`, файлов ветки на диске нет; совместимость `QuoteRejectionPatch` с `useUpdateQuote` проверена по типам `QuoteUpdate`, не прогоном.
- Гонку двух вкладок на «Принято» (ожидаемый 23505) и отображение тоста глобального `mutationCache` рядом с инлайн-ошибкой карточки.
- Как в проде называют задачи колонки `paused` — содержит ли `text` «от кого»; отдельного поля «ждём от» в строке списка нет, и это не заведено в находки: воспроизводимого отказа без договорённости, что `assigned_to`/`contact_id` и есть «от кого», нет.
