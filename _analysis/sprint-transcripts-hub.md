## ЗАДАЧА 1: страница `/transcripts`

`src/app/(dashboard)/transcripts/page.tsx` — серверная обёртка по образцу `calls/page.tsx`
(проверка сессии + редирект), компонент — `src/components/transcripts/TranscriptsView.tsx`.

Список поверх существующей таблицы `transcripts`, **новой сущности в БД не появляется**.

Колонки:

| Колонка | Содержимое |
|---|---|
| Дата | `created_at`, формат как в остальных списках |
| Источник | `call` / `meeting` — с иконкой, как в ленте |
| Компания · контакт | из связанного звонка/встречи |
| Объём | `formatCharCount(char_count)` — функция уже есть |
| Способ | `paste` / `audio` / `file` — тихим текстом |
| Начало текста | первые ~120 символов, `truncate` + `title` |

Клик по строке — модалка просмотра: полный текст, кнопка «Копировать», кнопка «Скачать»
(Задача 3), ссылка «Открыть звонок» → та же `AiWorkspaceModal`, что и по Sparkles.

⚠️ Запрос обязан тянуть связанные звонок/встречу **джойном в одном запросе**
(`transcripts.select('*, call:calls(...), meeting:meetings(...)')` — по факту схемы FK
может не быть, тогда два запроса и склейка на клиенте, но **не запрос на строку**).

⚠️ `content` в списке — тяжёлый: час разговора это ~45 тыс. символов. В выборку списка
брать **обрезанный** превью-фрагмент, а полный текст грузить точечно при открытии
модалки. Если обрезка на стороне БД недоступна — тянуть `content` целиком, но тогда
записать это как долг с порогом пересмотра.

## ЗАДАЧА 2: поиск по тексту

Поле поиска над списком (`DataTable` его уже умеет — свериться с разведкой №1).

Поиск идёт по `content` через `ilike('%…%')` **на сервере**, не фильтрацией уже
загруженной страницы: смысл поиска в том, чтобы найти разговор, которого нет на первом
экране.

⚠️ Полнотекстового индекса в проекте нет, и заводить его в этом спринте не нужно:
на десятках транскриптов `ilike` отрабатывает мгновенно. **Записать порог пересмотра
в комментарии** — по образцу `segment-eval.ts`: ориентировочно несколько сотен
транскриптов либо заметная задержка ответа; тогда нужен GIN-индекс по
`to_tsvector('russian', content)` отдельной миграцией. Без записанного порога это
станет «забыли», а не «решили».

Поиск и фильтры (источник, способ, компания) комбинируются по «И».

## ЗАДАЧА 3: выгрузка файлом

Кнопка «Скачать» в модалке просмотра и в строке списка.

- Формат — **Markdown** (`.md`): расшифровка после вычитки уже размечена репликами по
  строкам, markdown это сохраняет, а `.txt` теряет.
- Имя файла: `<дата>-<компания>-<звонок|встреча>.md`, недопустимые в имени символы
  заменять; кириллицу **оставлять** — она в именах файлов работает.
- Шапка файла: дата, компания, контакт, источник, объём — чтобы файл, вынутый из папки
  «Загрузки» через полгода, объяснял себя сам.
- BOM для кириллицы — как в `csv-export.ts` (разведка №5), иначе Excel и часть редакторов
  прочитают кракозябры.

⚠️ Скачивание — **дополнение к хранению, а не замена**: файл в «Загрузках» теряется
быстрее, чем запись в CRM. Никакого «скачал и удалил из базы».

## ЗАДАЧА 4: сводный AI-блок на карточке компании

Сейчас на компании AI живёт двумя разрозненными кусками: чип «AI» в ленте активности и
отдельная модалка брифа. Собрать в один блок под лентой — `src/components/companies/`,
новый компонент, монтируется в `CompanyDetail`.

Содержимое:

1. **Расшифровки компании** — все транскрипты по её звонкам и встречам: дата, источник,
   объём, начало текста. Клик — та же модалка просмотра, что в Задаче 1.
2. **AI-прогоны** — оба источника, как в `fetchAiRuns` после S-AI-VIS-1: по звонкам и
   встречам плюс собственные прогоны компании (брифы). Человеческое название пресета
   (`presetTitle`), статус, дата. Клик — `AiRunResultModal`.
3. Пусто — честное пустое состояние: «Расшифровок пока нет» + одна строка, как их
   получить (вкладка «Аудио» в AI-анализе звонка).

⚠️ Логику сбора прогонов **не дублировать**: `mergeAiRunRows` и оба источника уже есть
в `use-entity-timeline.ts`. Если переиспользовать напрямую нельзя — вынести общую часть,
а не копировать запрос.

⚠️ Блок не должен утяжелять первый экран карточки: грузить по появлению или сворачивать
по умолчанию, если записей больше десяти.

## ЗАДАЧА 6: тесты

`tests/unit/`, чистые функции:

1. Имя файла выгрузки: кириллица сохраняется, запрещённые символы (`/ \ : * ? " < > |`)
   заменяются, пустое имя компании не даёт двойных разделителей, длина ограничена.
2. Шапка md-файла: содержит дату, компанию, объём; пустые поля не дают пустых строк
   вида «Компания: ».
3. Превью текста: обрезка по границе слова, не по середине; текст короче лимита не
   трогается; пустой текст даёт пустую строку, не «undefined».

⚠️ Тесты в `tests/unit/` — `vitest.config.ts` включает только его.
