# «Сегодня» v3 — спека эпика S-TODAY-V3

**Дата:** 2026-10-04 · **Макет:** `_analysis/mockup-S-TODAY-V3.html` (статичный снимок апрувленного холста, 11 кадров).
**Аудит и история решений:** Claude Project «CRM Design auditor» — `today-audit-redesign-2026-10-03.md` (F-01…F-15), `today-v3-audit-2026-10-04.md` (X-01…X-12), `today-redesign-v3-2-2026-10-04.md` (C-01…C-21).
**Спринты эпика:** `sprint-S-TODAY-V3-DOMAIN-1.md` → `sprint-S-TODAY-V3-SCREEN-1.md` → `sprint-S-TODAY-V3-ACT-1.md`. Каждый следующий стартует от `main` после мержа предыдущего.
**Схема:** миграций в эпике нет.

## 1. Что меняется

Экран `/` перестаёт быть объединением таблиц (звонки, лиды, задачи, сделки, контакты, встречи). Единица экрана — открытая клиентская сделка. Сверху — до трёх ходов дня, ниже — сделки по типу решения, которое по ним нужно принять. Всё, что к открытой сделке не относится, — в чипах под списком.

Решение первых пяти секунд: какие три сделки двигаю сегодня и у скольких сделок нет шага впереди.

## 2. Термины и правила

**Сделка экрана** — `projects.type = 'client'` и `useIsProjectActive()(project) === true`. Экран личный: `projects` отдаёт только сделки, где пользователь участник.

**Сегодня** — для `date`-колонок ключ `localDateKey(now)`, как у `getDealHealth`; день события из `timestamptz` — `mskDateKey`. `now` всегда приходит аргументом.

**Срок шага** — `projects.next_action_date`. Шаг впереди — `getDealHealth(project, now) === 'ok'`.

**Касание** — действие по сделке с нашей стороны. Отсечка — по дню: касание с днём позже сегодняшнего не учитывается.

| Источник | Что считается | Вид |
|---|---|---|
| `notes` (`deleted_at is null`, `project_id` задан) | заметка с `kind = 'note'`; `stage_comment` отдельным касанием не считается — это часть смены стадии | `note` |
| `activity_log.event_type = 'stage_changed'` | смена стадии | `stage` |
| `activity_log.event_type = 'task_completed'` | закрытая задача | `task` |
| `activity_log.event_type = 'call_logged'` | звонок | `call` |
| `activity_log.event_type = 'meeting_scheduled'` | встреча | `meeting` |

Не касание: `project_updated` (правка полей), `comment_added` (заметки живут в `notes` с миграции 134, мост в журнал снят в 135; иначе дубль), `task_created`, `entity_deleted`, `automation_fired`, `stage_transition_committed`, `lead_status_changed`, любой неизвестный тип.

**Отскок стадии не касание.** Две смены стадии одной сделки, где вторая возвращает первую (`A→B`, затем `B→A`) и между ними не больше 30 минут, не считаются обе. Пара — только при непустых id стадий. Случай: «Зерде Фито» 03.10, 17:56 и 18:07 МСК.

**Окно касаний.** Касания загружаются с дня «самый ранний просроченный срок шага минус 30 дней», но не глубже 120 дней от сегодня. Касание старше окна для экрана не существует.

**Группы.** Порядок на экране: `fresh`, `risk`, `stale`, `decide`, `plan`.

| Группа | Название | Правило |
|---|---|---|
| `fresh` | Сорвано недавно | срок шага прошёл, прошло не больше 14 дней, после дня срока касаний нет |
| `stale` | Обновить шаг | срок шага прошёл, после дня срока есть касание; либо шага или даты нет, а последнее касание (или создание сделки) не старше 14 дней |
| `decide` | Решить судьбу | срок шага прошёл больше 14 дней назад, после дня срока касаний нет; либо шага или даты нет и тишина дольше 14 дней |
| `risk` | Под риском | шаг впереди, и есть сигнал риска |
| `plan` | По плану | шаг впереди, сигналов нет; либо шага нет, но по сделке стоит встреча или звонок с датой сегодня или позже |

Касание в сам день срока «после срока» не считается. Порог 14 дней — `decideDays`.

**Сигналы риска** (только они переводят сделку в `risk`):

- `quote_expired` — активное КП (`pickActiveQuote`) в статусе `sent`, `quoteValidity(...).level === 'expired'`;
- `task_overdue` — задача сделки с `lane !== 'done'` и днём дедлайна раньше сегодня;
- `call_overdue` — звонок сделки в статусе `pending` с днём раньше сегодня.

Норма стадии группу не определяет: на снимке 03.10 она превышена у 12 сделок из 17, сигнал горел бы всегда. Норма, дедлайн сделки и задачи показываются в раскрытой строке как контекст.

**Сумма сделки** — `dealHeaderAmount(quotes, budget)`: активное КП с суммой, иначе бюджет, иначе суммы нет.

**Вес.** Сравнение `compareByWeight`: фаза стадии (`closing` 3 → `approval` 2 → `working` 1 → `attraction` 0) → сумма по убыванию, без суммы в конце → `order_index` стадии по убыванию → просрочка по возрастанию → `id`.

**Ходы дня** (лимит 3):

1. Назначенное на сегодня — шаг с датой сегодня, встреча или звонок сегодня. Попадает всё, даже сверх лимита. Порядок: со временем по времени, затем без времени по весу.
2. Свободные слоты, кроме последнего, — сделки `fresh` по весу.
3. Последний свободный слот — сделка с наибольшей суммой среди `fresh`, `stale`, `decide`, ещё не взятая в ходы. Сумм ни у кого нет — следующая `fresh` по весу.
4. Остались слоты — `stale` по весу, затем `decide` по весу.

Отложенные сделки (`queue_snoozes`) в ходы и в группы не попадают, они в блоке «Отложено».

Набор ходов дня фиксируется при первом открытии экрана за день и хранится в `localStorage` (ключ `today-moves-<день>`), как «Фокус дня» раньше. Вместе с набором хранится слот каждого хода — для строки «почему здесь». Сделанный ход остаётся карточкой с отметкой. Это спринт ACT-1; в SCREEN-1 набор пересчитывается при каждом рендере.

**Главное число** — «у N из M нет шага впереди»: N — сделки групп `fresh`, `stale`, `decide`, включая взятые в ходы и отложенные; M — все сделки экрана, включая отложенные.

**Выходные** — обычный день без назначенного. Быстрые даты в форме хода пропускают субботу и воскресенье.

**Не сделки** — чипы под списком. Правила отбора — существующие, из текущего `TodayView`, без изменений: звонки (мои, `pending`, сегодня и просроченные) и встречи сегодня (мои) без открытой сделки; лиды (`getLeadHealth`); задачи `lane = 'now'` без открытой клиентской сделки, отдельно — задачи закрытых сделок; остывающие контакты.

Задачи в работе, просроченные задачи, звонки и встречи открытой сделки показываются внутри неё — в блоке «Сейчас» раскрытой строки, с прежними действиями «Готово» и «Выполнен».

## 4. Где макет расходится с живыми правилами

Макет собран по снимку 03.10 и местами упрощён. В коде действует правило проекта, не число из макета.

| В макете | В коде |
|---|---|
| Лоренц снек — 14,5 млн (бюджет) | `dealHeaderAmount`: активное КП-черновик 14 326 976 ₽ |
| «у 12 не указана сумма» | считается на живых данных; на 03.10 — 11 (у «Лид #001» бюджет 1 000 ₽) |
| Чип «Остывающие контакты 5» | существующее правило `useLastTouchMap` даёт другое число (на 03.10 — 26); смена определения касания контакта — отдельная задача |
| Чип «Лиды без шага 1» | существующее правило очереди лидов (`getLeadHealth`, статусы `new`/`contacted`); на 03.10 — 0, чип скрыт |
| Время «11:00» у Стройпарка | время хода берётся только у встречи и звонка; у шага сделки времени нет |
| «Скрыть до завтра» | существующее действие и подпись — «Отложить» |
| «Ждём клиента» | нет в эпике |
| Порядок строк внутри группы | `compareByWeight` |
| Полоса «Было» в теме `t-cobalt` | цвет смены стадии — `--info`, проверяется во всех темах |
