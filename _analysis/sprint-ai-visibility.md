# Claude Code Prompt — S-AI-VIS-1: транскрипт не теряется и AI видно там, где ищут

Расшифровка стала самостоятельной ценностью, а хранится и показывается так, будто она
всё ещё черновик для пресета. Спринт это исправляет.

**Ветка:** `feat/ai-visibility` от свежего `main`.

## Что показала живая БД (2026-08-08, гейт — не выяснять заново)

```
transcripts: всего 4 · source='audio': 1 · последний 2026-08-08 08:05
ai_runs: 19 · из них preset_key='company_brief' (entity_type='company'): 7
```

**Один** аудио-транскрипт на все прогоны расшифровки — при том что владелец прогонял
39-минутный файл, часовой и повторы. Причина в коде: транскрипт пишется ТОЛЬКО внутри
`useStartRun` (`src/lib/hooks/use-ai-run.ts`), то есть в момент запуска пресета. Не нажал
пресет — расшифровка умерла вместе с состоянием компонента.

Три дыры доступа, все подтверждены кодом:

| Симптом | Причина в коде |
|---|---|
| Транскрипт не виден нигде | `useTranscript` вызывается ровно в одном месте — `AiRunPanel` |
| Клик по AI-событию ленты молчит | `open-event.ts`: `case 'ai_run'` попадает в `default: return` |
| 7 брифов компании не видны в её ленте | `fetchAiRuns` ищет по `entity_id ∈ (звонки, встречи)`; у `company_brief` `entity_id` — сама компания |

**Жёсткие рамки:**
- **Миграций нет.** `supabase/migrations/` не трогать. Схема `transcripts`/`ai_runs` достаточна.
- Edge-функции не трогать: ни `ai-run`, ни `transcribe`.
- `src/types/database.ts` / `supabase.gen.ts` не трогать.
- Никаких hardcoded-цветов; компоненты работают во всех 7 темах.
- Новой сущности в БД **не заводить** — `transcripts` уже полноценная сущность с RLS
  и историей версий. Здесь не хватает витрины, а не таблицы.
- Раздел «Транскрипты» в меню и скачивание файлом — **вне этого спринта** (фаза 2).

## ЗАДАЧА 1: транскрипт сохраняется сразу, без пресета

Главная задача. Всё остальное — доступ к тому, что и так должно существовать.

### 1.1 Вынести upsert из `useStartRun`

Сейчас логика «переиспользуем последний транскрипт, если текст совпал, иначе новый»
живёт внутри мутации запуска прогона. Вынести её в отдельную экспортируемую функцию
(`src/lib/hooks/use-ai-run.ts` или соседний модуль — решить по факту), которой пользуются
**оба** вызывающих: запуск пресета и новое сохранение.

⚠️ Правило «изменился текст → новый транскрипт, история сохраняется» **не менять**.
Человек правит расшифровку руками, и правка не должна затирать машинную версию.
Дублирования при этом быть не должно: тот же текст той же сущности — та же строка.

### 1.2 Мутация `useSaveTranscript`

Контракт: `{ entityType: 'call' | 'meeting', entityId, text, source }`.

- `entityType` — только `call`/`meeting`: политика `transcripts_insert` проверяет EXISTS
  по `calls`/`meetings`, для сделки и компании запись невозможна по построению.
- Пустой/пробельный текст не сохраняется вовсе.
- `org_id` **не писать** — его проставляет БД (конвенция проекта).
- После успеха инвалидировать ключи транскрипта и ленты — иначе признак «есть
  расшифровка» (Задача 2) появится только после перезахода.

### 1.3 Сохранять по факту готовности

`src/components/ai/AiRunPanel.tsx`, колбэк `onResult` из `TranscribeDropzone`: текст
кладётся в поле «Вставить» **и сразу сохраняется**. Не «после пресета», не по отдельной
кнопке — расшифровка готова, значит она уже ценность.

⚠️ Сохранять и **частичный** результат (`partial`: вычитаны не все блоки). Текст с
сырыми кусками лучше отсутствующего: за него уже заплачено, и человек может дочистить
его руками в поле.

⚠️ Автозапуска пресета по-прежнему НЕТ. Сохранение ≠ запуск: AI предлагает, человек
подтверждает.

Показать факт сохранения — короткой строкой рядом с полем («Расшифровка сохранена
в звонке»), а не только тостом: тост исчезает, а вопрос «сохранилось ли» остаётся
(урок S-FIX-VOICE-1).

## ЗАДАЧА 2: признак «есть расшифровка» на карточке звонка и встречи

Это первое место, куда человек идёт искать (проверено на владельце: он пошёл в карточку
компании → звонки, и ничего там не нашёл).

1. Хук: для списка звонков/встреч — какие из них имеют транскрипт. Одним запросом на
   список, **не по запросу на строку**: `transcripts.select('entity_id, entity_type,
   char_count').in('entity_id', ids)`. Нужен только факт наличия и объём, не содержимое.
2. `src/components/calls/CallLog.tsx` и `src/components/meetings/MeetingsList.tsx` —
   рядом с существующими действиями строки бейдж «Расшифровка» (иконка + объём вида
   «12 тыс. знаков»). Клик открывает ту же `AiWorkspaceModal`, что и Sparkles.
3. Бейджа нет — ничего не рисуем. Пустой бейдж «нет расшифровки» на каждой строке —
   шум: у большинства звонков её и не будет.

⚠️ Список звонков может быть длинным. Один запрос на весь список, результат — `Set` id.
Никаких `useTranscript` в цикле.

## ЗАДАЧА 3: клик по AI-событию ленты открывает результат

`src/lib/timeline/open-event.ts`, `case 'ai_run'` (сейчас падает в `default`):

1. Точечная выборка прогона по `event.sourceId` (`.eq('id', …).single()`), как сделано
   для call/meeting/task.
2. Новый колбэк `onAiRun?: (run: AiRun) => void` в `OpenTimelineEventCtx`. Хаб, который
   его не передал, работает как раньше — сигнатура остаётся обратно совместимой.
3. Хабы (`CompanyDetail`, `ContactDetailHub`, `ProjectDetail`) передают колбэк и
   открывают модалку просмотра результата.

Модалка просмотра — тонкая: заголовок (пресет + дата + статус), тело через
**существующий `AiResultRenderer`** (диспетчер по `preset_key`), кнопка «Копировать».
Новых рендереров не писать — их семь и они покрывают все пресеты.

⚠️ Прогон в статусе `error`/`pending` тоже кликабелен: показать статус и текст ошибки.
Молчащий клик — то, что чинится этой задачей, и он не должен вернуться через край.

⚠️ Заголовок события сейчас — `AI: analytic_note`, машинный ключ. Заменить на
человеческое название пресета из `src/lib/constants/ai-presets.ts` (`title`), с фолбэком
на ключ для пресета, которого клиент не знает.

## ЗАДАЧА 4: бриф компании — в ленту компании

`src/lib/hooks/use-entity-timeline.ts`, `fetchAiRuns`. Сейчас собирает прогоны только по
`entity_id ∈ (звонки и встречи сущности)`. Прогоны самой сущности (`entity_type='company'`
+ `entity_id` = id компании; то же для `project`) в выборку не попадают — у владельца
**семь готовых брифов невидимы**.

Добавить второй источник: прогоны, где `entity_type` = тип хаба и `entity_id` = его id.
Объединить с первым, отсортировать по дате, применить общий лимит.

⚠️ Комментарий про отсутствие батчинга `.in()` (остаток S-DEBT-TRUTH-1) — **сохранить**
и при необходимости дополнить: список не сократился.

⚠️ Не сломать контакт-хаб: у контакта своих прогонов не бывает (`ai_runs.entity_type` —
call/meeting/project/company), второй источник для него просто пуст.

## ЗАДАЧА 5: тесты

`tests/unit/` — что проверяемо без Supabase:

1. Выбор транскрипта для сохранения: тот же текст → переиспользование существующего;
   изменённый → новый; пустой → не сохраняем. Если логика упирается в запрос — вынести
   решающую часть в чистую функцию (`shouldCreateNewTranscript(lastContent, nextText)`)
   и покрыть её.
2. Маппинг `preset_key` → человеческое название: известный ключ даёт `title`,
   неизвестный — сам ключ, а не `undefined`.
3. Слияние двух источников `ai_runs`: дубли по id не возникают, порядок по дате убыванию,
   лимит применяется после слияния. Слияние вынести в чистую функцию.
