## ЗАДАЧА 3 — четыре урока в `references/learnings.md`

Добавь **в конец файла** новый раздел по образцу соседних дат:

```markdown
## Уроки 2026-08-12 (S-LEAD-CARRY-1 — конверсия переносит квалификацию, 123)

### ❌ Стаб в `database.ts` не покрывает рукописные интерфейсы
Конвенция «стаб колонки до применения миграции» (`type`, интерсекшеном к `Tables`)
работает только для тех, кто читает тип из `Database`. Но `Company` в проекте
**рукописный и живёт в `src/lib/hooks/use-companies.ts`**, а не алиасом в `entities.ts`
— и вся карточка компании (`CompanyDetail`/`Sidebar`/`Highlights`/`CompanyModal`)
импортирует именно его. Стаб до этого пути не доезжает вообще; поле пришлось добавлять
в ДВА места. Правило: заводя колонку, сначала `grep` по импортам — откуда потребитель
берёт тип. Рукописный интерфейс автогенерацией не наполняется и после регена, поэтому
поле в нём **остаётся**, снимается только стаб.

### ❌ Payload формы собирается из Zod-схемы, а не из интерфейса
Соблазн описать `CompanyInsert` как «фильтр полей, доезжающих до БД» — и это неправда.
`CompanyModal.onSubmit` строит `payload = { ...values }` из значений `companyFormSchema`
и отдаёт в `.insert(company as never)` / `.update(updates as never)`; каст снимает
проверку, и лишний ключ доедет до БД даже без записи в интерфейсе. Интерфейс нужен для
tsc, контракт держит Zod-схема. Практическое следствие: **новое поле в схеме формы
уезжает в запрос ВСЕГДА**, в том числе как `null` по умолчанию — поэтому ветка с новой
колонкой, смерженная до apply миграции, ломает не фичу, а **каждое сохранение сущности**
(PGRST204). Отсюда же жёсткость правила «мерж только после apply».

### ⚠️ Гейт Cowork не имеет сети — реген типов всегда за владельцем
`scripts/gen-types.sh` зовёт `npx`, мост к машине владельца сети не имеет, а MCP ходит
только в БД. Значит цепочка **apply → gen-types → снять стаб** физически разорвана между
двумя исполнителями: гейт делает первое, владелец/CC — второе и третье. Планируя
DB-спринт, закладывай этот стык в отчёт гейта явным пунктом, иначе стаб уезжает в `main`.
Побочный эффект в плюс: CLI-реген вернул блок `graphql_public`, которого не отдавал
MCP-реген, — дифф вышел строго аддитивным (+31/−0).

### ❌ `git` через Cowork-мост оставляет `.git/index.lock`
Даже `git status` из Cowork-сессии по смонтированной папке создаёт лок и **не может его
удалить**: мост читает и пишет, но не умеет `unlink` (`Operation not permitted`). Дальше
любой `git add` в CC падает на чужом стейл-локе нулевого размера. Правило: **git из
Cowork-сессии не звать вообще, даже на чтение** — состояние ветки спрашивать у CC
отчётом. Если лок всё же появился и живых git-процессов нет — снести руками.

### ✅ Два источника одного факта разводятся весом и подписью, а не слиянием
`companies.chz_groups` (подтверждено человеком) против `matchChzGroups(okved)`
(выведено из реестра). Схлопывать их в одно поле нельзя — потеряется либо ввод, либо
честность; сливать массивы автоматически тоже нельзя — молча смешаются профили разных
лидов. Рабочая форма: чистый резолвер в `lib/domain` возвращает `{ groups, source,
unknown }`, declared побеждает derived, **подпись источника на экране разная** («Подтверждено
вручную» против «Справочник … по основному ОКВЭД»), а имена вне справочника-снапшота
не проглатываются, а рендерятся нейтральным тегом. Проверено на «ЙУМИ»: ОКВЭД 10.85 даёт
пустой derived, и до 123 карточка не показала бы маркировку вовсе — при живом дедлайне
через две недели. Подробности решения — `claude/company-360-design-decisions.md` в проекте.
```
