# FIX S-GANTT-DEPTYPES — перемычка не-FS не должна ложиться на промежуточный ряд

**Статус: отложенный.** Не блокирует мёрж `feat/gantt-dep-types`. Брать, когда связи
SS/FF/SF реально пойдут в работу на проектах, либо попутно с любой следующей правкой
`GanttTimeline.tsx`.

Остаток после `1aab398` (роутинг стрелок не-FS). Тот фикс убрал перехват кликов по бару
**предшественника**; этот закрывает тот же эффект на баре **промежуточной задачи**.

**Оценка: ~40 мин. Риск низкий** — трогается одна координата в ветке не-FS.

---

## Что не так

Пятисегментный роут ведёт перемычку горизонтально на

```ts
const yMid = (from.y + to.y) / 2;
```

Ряды Ганта стоят равномерно через `ROW_H`, центры баров совпадают с центрами рядов
(`anchor` возвращает `y = r.top + r.height / 2`). Отсюда: если предшественник и
последователь разнесены на **чётное** число рядов, `yMid` попадает ровно в центр
промежуточного ряда, и перемычка идёт вдоль бара третьей задачи. Хит-путь ребра —
`strokeWidth={10}` при высоте бара 10px, то есть на участке от `exitX` до `entryX`
`pointerdown` снова достаётся пути ребра, а не бару: чужая задача не таскается, клик по
ней открывает поповер связи.

Условия срабатывания: не-FS связь + чётный разнос по рядам + бар промежуточной задачи,
попадающий в диапазон x между `exitX` и `entryX`. При нечётном разносе `yMid` приходится
на межрядный зазор и проблемы нет.

Это геометрический вывод, а не наблюдение: в смоуке `1aab398` пары стояли на соседних
рядах (нечётный разнос), поэтому случай не проявлялся.

## Что сделать

Сдвинуть перемычку в межрядный зазор, когда она пришлась бы на центр ряда. Высоту ряда
брать **измеренной**, а не из константы `ROW_H`: она в rem, а нужен пиксель на текущем
зуме шрифта.

1. `anchor` вернуть дополнительно `h: r.height` (высота обёртки бара = высота ряда, она
   лежит в grid-ряду фиксированной высоты).
2. Считать разнос в рядах и, если он чётный, сдвинуть перемычку на полряда:

```ts
const rowPx = from.h || to.h;                    // высота ряда, измеренная
let yMid = (from.y + to.y) / 2;
// Перемычка не должна лечь вдоль бара промежуточной задачи: при чётном разносе рядов
// середина между центрами двух баров — это центр третьего. Уводим в межрядный зазор.
if (rowPx > 0 && Math.round(Math.abs(to.y - from.y) / rowPx) % 2 === 0) {
  yMid += rowPx / 2;
}
```

3. `midY` у не-FS остаётся равным `yMid` (якорь бейджа едет вместе с перемычкой).

**FS не трогать** — у него перемычки нет, ветка `isFS` остаётся как есть, включая
`midX = Math.max(exitX, entryX)` и трёхсегментный путь.

Направление сдвига (вниз, `+ rowPx / 2`) выбрано произвольно и это нормально: любой из
двух зазоров одинаково свободен. Менять на `−` без причины не надо.
