## ЗАДАЧА 1 — «Открыть полностью» из peek лида не навигирует (хвост #11)

### Симптом

Клик по ссылке «Открыть полностью» в шапке `PeekPanel` для лида: URL остаётся `/leads`,
модалка не открывается, панель просто закрывается. **Прямой заход по `/leads?lead=<id>`
работает.** Дефект предсуществующий — воспроизводится на чистом `main` (проверено `git stash`
на спринте S-R2-D3), спринтами не внесён.

### Что уже исключено — не тратить на это ходы

1. **`PeekPanel.handlePointerDown`** (`src/components/shared/PeekPanel.tsx:27-33`) —
   не он закрывает панель: `<Link>` лежит внутри `<aside ref={panelRef}>`, обработчик выходит
   по `panelRef.current?.contains(target)`.
2. **`useChipFilter`** (`src/lib/hooks/use-chip-filter.ts`) — не переписывает URL на
   монтировании: `router.replace` вызывается только из `toggle`/`reset`, то есть по действию
   пользователя.
3. **`peekSuppressed`** — появился в S-R2-FIX-1, а баг старше.

### Главная гипотеза

`src/components/leads/LeadsView.tsx`, эффект deep link (~строки 431-453):

```ts
const target = leads?.find((l) => l.id === leadParam);
if (target) { setEditLead(target); setModalOpen(true); return; }
// Конвертированный лид или мусорный id — молча снимаем параметр
router.replace('/leads', { scroll: false });
```

Навигация по ссылке **происходит**, эффект отрабатывает, `leads?.find(...)` не находит лид —
и `router.replace('/leads')` возвращает URL назад. Снаружи это выглядит как «клик ничего не
сделал»: параметр появился и исчез быстрее, чем глаз заметил.

Почему `find` может не найти строку, которая только что рисовалась в панели:

- `leads` — результат `useLeads()`, а строки таблицы приходят из `filtered`; если хук
  фильтрует (например, прячет конвертированные), лид может быть в таблице и отсутствовать
  в `leads`;
- гонка: `leads` ещё `undefined`/старое на момент первого прогона эффекта. Гард стоит только
  на `isLoading`, а между «список загружен» и «список обновлён» состояние другое.

**Вторая гипотеза (если первая не подтвердится):** панель размонтируется между `mousedown` и
`click`, якорь исчезает и клик не доходит до `<Link>` — тогда навигации не будет вовсе и
`?lead=` в адресной строке не появится **ни на мгновение**. Эти две гипотезы различаются
ровно тем, мелькает ли параметр в URL.

### Шаги

**1.1. Разведка — сначала измерить, потом чинить.**

`converted_deal_id`, по чему-либо ещё) — то есть может ли строка быть в таблице, но не в
`leads`.

**1.2. Инструментировать и воспроизвести в браузере.** Временно, в эффект deep link:

```ts

  found: !!leads?.find((l) => l.id === leadParam) });
```

Открыть `/leads`, Space на строке (открыть peek), клик «Открыть полностью». Снять:

- появился ли `?lead=<id>` в адресной строке хотя бы на мгновение (вкладка Network: был ли
  RSC-запрос);
- что напечатал лог: сколько раз сработал эффект, каким был `found`.

**Логи убрать до коммита.** В отчёт вынести, какая гипотеза подтвердилась.

**1.3. Фикс под подтверждённую причину.**

Если подтвердилась **первая** (эффект снимает параметр, потому что не нашёл лид):

- не снимать параметр, пока список не «устоялся»: гард должен быть не только на `isLoading`,
  но и на «данные вообще пришли» — `if (isLoading || !leads) return;`;
- `handledLeadParam.current = leadParam` ставить **только когда лид найден**. Сейчас метка
  ставится до поиска, поэтому повторная попытка по той же ссылке уже не отработает — это
  вторая половина того же дефекта;
- снятие параметра для реально несуществующего лида оставить, но перевести на
  `window.history.replaceState(null, '', '/leads')` — тот же приём, что уже применён в
  `clearLeadParam` (S-R2-FIX-1), и заодно закрывается 🟢-хвост «в одном файле два механизма
  для одного действия».

Если подтвердилась **вторая** (панель исчезает до клика) — показать, что именно её
размонтирует, и **вернуть задачу**: правка будет в `DataTable`/`PeekPanel`, а это другой
blast radius, обсудим отдельно.

**1.4.** Проверить, что не сломан прямой заход: `/leads?lead=<id>` в новой вкладке
по-прежнему открывает модалку.

## ЗАДАЧА 2 — UPDATE-политика для `contact_company` (хвост #12)

### Почему

У таблицы три политики: `cc_select` (org), `cc_insert` (owner/admin/manager),
`cc_delete` (owner/admin). **UPDATE-политики нет вообще** — роль контакта в компании
отредактировать нельзя, только удалить связь и создать заново. Под RLS это не ошибка доступа,
а молчаливый ноль изменённых строк: UI покажет «сохранено», в базе не изменится ничего.

Найдено разведкой S-R2-D3 (2026-08-02) при сверке с новой `deal_stakeholders`.

### Шаги

**2.1.** Файл `supabase/migrations/093_contact_company_update_policy.sql`. Форму брать
дословно с `ds_update` из 092 — она свежая, прошла гейт и ролевые смоки:

```sql
-- ═══════════════════════════════════════════════════════
-- 093 — UPDATE-политика для contact_company (хвост #12).
--
-- У таблицы были только SELECT / INSERT / DELETE: роль контакта в компании нельзя было
-- отредактировать — под RLS это не ошибка, а тихий 0 изменённых строк.
-- Роли те же, что у cc_insert (owner/admin/manager): кто может завести связь,
-- тот может и поправить у неё роль.
--
-- WITH CHECK повторяет USING — урок 054: без него строку можно перенести в чужую org.
--
-- Откат: drop policy if exists cc_update on public.contact_company;
-- ═══════════════════════════════════════════════════════

drop policy if exists cc_update on public.contact_company;

create policy cc_update on public.contact_company for update to authenticated
  using (
    org_id = ( select public.current_org_id() )
    and ( select public.current_org_role() ) in ('owner','admin','manager')
  )
  with check (
    org_id = ( select public.current_org_id() )
    and ( select public.current_org_role() ) in ('owner','admin','manager')
  );
```

**Сверить перед записью файла** (память врёт, живая БД — нет):

```sql
select policyname, cmd, qual, with_check
from pg_policies where schemaname='public' and tablename='contact_company';
```

Имена существующих политик, наличие `org_id`, отсутствие `cc_update` — подтвердить, а не
предположить. Если `cc_update` вдруг уже есть — остановиться и вернуть задачу.

**2.2. UI в этом спринте не трогаем.** Редактирования роли контакта в компании в интерфейсе
сейчас нет; политика убирает блокиратор, интерфейс — отдельным решением. Не заводить его
попутно: получится непроверенная фича без спринта.
