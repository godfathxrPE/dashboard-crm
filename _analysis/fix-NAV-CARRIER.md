# Claude Code Prompt — fix: носителем состояния нава может быть бордер, а не только подложка

**Ветка:** `fix/nav-carrier`
**Размер:** один файл, `scripts/audit-contrast.py`. Темы и разметку НЕ трогать.

## Почему

После #49 скрипт даёт три FAIL — `t-frost` 1.24, `t-aurora` 1.20, `t-tidal` 1.26 на паре
`nav-active-bg / sidebar-bg` при пороге 3.0. **Это ложные срабатывания.**

У этих тем работает layered-дефолт `.nav-active { border-left: 3px solid var(--accent) }`
(`globals.css:1747`): полосу гасят только aura (`border-left: none`), lime (`none`),
minimal (`border-left-color: transparent`), washi и fuji (`none !important`). У тёмных тем
она остаётся, и её контраст к рельсу — **4.96 / 4.59 / 9.97**, то есть состояние
опознаётся с двукратным запасом. Скрипт меряет подложку и полосы не видит.

Ошибка того же класса, что чинил #49, слоем глубже: измеряется не тот элемент.

**Усиливать подложку нельзя — посчитано.** Чтобы пилюля дала 3:1 к рельсу frost, нужна
альфа ≈0.34; акцентный текст на такой пилюле падает с 5.37 до 2.37. Два требования
взаимно исключаются, поэтому тёмные темы и решают состояние бордером.

## ЗАДАЧА: носитель состояния — дизъюнкция трёх средств

В блоке, где сейчас вычисляется `text_carries_state_by_lightness`, добавить третье
средство и свести условие в дизъюнкцию. Состояние считается опознанным, если выполняется
ЛЮБОЕ из:

1. **текст** — актив против неактива ≥ 1.5 по светлоте (уже есть);
2. **подложка** — пилюля к рельсу ≥ 3.0;
3. **бордер** — левая полоса к рельсу ≥ 3.0.

Цвет бордера разрешать по факту каскада, как это уже сделано для пилюли:
- по умолчанию — layered `border-left: 3px solid var(--accent)`;
- гасится у тем из списка (`aura`, `lime`, `minimal`, `washi`, `fuji`) — там бордера нет,
  средство не засчитывается. Список оформить именованной константой с комментарием
  «источник — `globals.css`, проверять при правке `.nav-active`», по образцу
  `NAV_INK_HARDCODE` / `NAV_NO_PILL`.

Пару `nav-active-bg / sidebar-bg` оставить в выводе как есть (ratio полезен), но
`kind='decorative'`, когда состояние опознано любым средством, и `kind='ui'`, когда
не опознано ни одним. Добавить в JSON рядом с парой пометку, КАКИМ средством оно
опознано (например поле `carrier`: `text` / `pill` / `border` / `none`) — иначе
следующий читатель снова не поймёт, почему пара info-only.

**Ожидаемый итог: 0 FAIL на всех восьми темах**, и это будет честный ноль, а не
незаданный вопрос. Если какая-то тема осталась красной — не подгонять, сообщить.
