# Claude Code Prompt — P-BRIEF-MODELS: замер моделей и движков поиска для брифа

**Это проба, а не спринт.** Прод-код не трогаем: ни `ai-run/index.ts`, ни `_shared/llm.ts`.
Единственный изменяемый файл — `scripts/llm-probe.py`. Задача — получить числа, на которых
дальше принимается архитектурное решение.

## Зачем

Владелец переезжал на OpenRouter ради экономии, а получил тот же `anthropic/claude-sonnet-5`
по той же цене плюс комиссию площадки. Смена модели откладывалась дважды («модели не меняем»
в S-LLM-SEARCH-1) — сейчас её время. Параллельно вскрылась вторая, более важная причина
менять провайдера: **глубина поиска**.

Замеры по проду (`ai_runs` + лог `openrouter response:`, 19.08):

| Прогон | движок | annotations | вход, токенов | sources | chz_signals |
|---|---|---|---|---|---|
| было, прямой Anthropic (4–6.08) | native | — | **77 000–80 000** | 11–12 | есть |
| 06:05, движок не пинился | native + форс | — | 4 812 | 0 | 0 |
| 08:29, после пина | exa, `max_results=10` | **10** | **8 779** | 2 | 0 |

Каркас запроса без поиска — 4 812 токенов. Значит десять результатов Exa добавили
**3 967 токенов ≈ 400 на источник ≈ 1 600 знаков**. Документация плагина это подтверждает:
Exa отдаёт «highlights», выдержки ~2 000–4 000 знаков, а не страницы. Нативный поиск
Anthropic читал страницы целиком — отсюда 77–80К и живой бриф.

Вывод, который надо проверить числами: **дело не в `max_results`, а в том, что Exa даёт
сниппеты.** Native-движок на OpenRouter поддержан у OpenAI, Anthropic, Google, Perplexity
и **xAI**; всё остальное (DeepSeek, Qwen) падает на Exa — то есть дешёвые китайские модели
брифа не спасут в принципе, каким бы промптом их ни уговаривать.

Второе, что мешает: форс `tool_choice` не оставляет модели хода на нативный поиск — она
сразу вызывает инструмент. Именно это дало прогон 06:05 с нулём источников. Поэтому в
пробе поиск и структурирование разносятся по разным вызовам.

## ЗАДАЧА 0 — слаги и цены брать из API, а не из моего текста

Я приводил таблицу цен со страниц OpenRouter. Считай её **непроверенной**: слагов Grok
там шесть (4.20, 4.3, 4.5, 4.6, Build, Multi-Agent), они путаются, а цены на витрине
маркетинговые.

```bash
curl -s https://openrouter.ai/api/v1/models \
  | jq '[.data[] | select(.id|test("^(x-ai|deepseek|qwen)/"))
        | {id, in: .pricing.prompt, out: .pricing.completion,
           ctx: .context_length, params: .supported_parameters}]'
```

Отбери кандидатов по фактам: наличие `tools` и `tool_choice` в `supported_parameters`,
цена, контекст. **В отчёт — таблицу отобранных с ценами из API.** Если у модели нет
поддержки инструментов, она выбывает молча из тестов A–C, но остаётся кандидатом на
первый проход (там инструменты не нужны).

## ЗАДАЧА 1 — тест E «search» в `scripts/llm-probe.py`

Скрипт уже держит четыре теста (capture / summary / spin / cleanup) и общий каркас
запроса. Добавь пятый, `search`, тем же стилем — без зависимостей, только stdlib.

Вход теста **обязан быть настоящим**: system-промпт и `input_schema` инструмента
`submit_company_brief` возьми из `supabase/functions/ai-run/index.ts` (пресет
`company_brief`, ~строки 529–630). Скопируй их в скрипт с пометкой «зеркало, править
синхронно» — на игрушечной схеме замер не переносится на прод.

Подопытная компания одна, чтобы сравнивать с эталонами: **АО «ЭЙЧ ЭНД ЭН» (бывш. Данон
Россия), ОГРН 1057749126820**. По ней уже есть три прогона в `ai_runs`.

### Матрица — пять ячеек, каждая отвечает на свой вопрос

| # | модель | движок | инструмент | вопрос |
|---|---|---|---|---|
| A | `anthropic/claude-sonnet-5` | `exa`, max_results 10 | форс | база: воспроизводим прод |
| B | Grok (отобранный слаг) | `native` | форс | убивает ли форс нативный поиск и у xAI |
| C | Grok | `native` | **нет инструментов** | сколько глубины даёт native без форса |
| D | `anthropic/claude-sonnet-5` | `native` | **нет инструментов** | глубина — свойство движка или модели |
| E | DeepSeek Flash (или Qwen) | поиска нет | форс | годится ли дешёвая модель на упаковку |

Ячейка E работает не по вебу, а по **готовому тексту**: возьми вывод лучшей из C/D и
попроси уложить его в схему `submit_company_brief`. Это прямая проверка гипотезы
«дорогая модель ищет, дешёвая структурирует».

### Что мерить в каждой ячейке

- `usage.prompt_tokens` — **главное число**, это и есть глубина. Ориентиры: 4 812 без
  поиска, 8 779 на Exa, 77 000–80 000 на нативном Anthropic;
- `usage.completion_tokens`;
- длина `choices[0].message.annotations`;
- `finish_reason` и наличие валидного `tool_calls` (для A, B, E);
- время ответа;
- **фактическую стоимость** — `GET https://openrouter.ai/api/v1/generation?id=<gen_id>`,
  где `gen_id` — `id` из ответа. OpenRouter сам говорит, сколько списал, включая поиск.
  Считать по прайс-таблице не надо: у нас уже был заход, где таблица врала в полтора раза.

Ключ — из `OPENROUTER_API_KEY` в окружении. **В файл не писать, в отчёт не копировать.**

Прогонов: по одному на ячейку. Победителя C или D повторить ещё раз — два прода 07:20 и
08:29 дали побайтово одинаковый результат, но проверить стабильность на новом движке стоит.

## ЗАДАЧА 2 — качество, а не только числа

Числа скажут про глубину, но не про пригодность. По ячейкам C и D дополнительно выведи
в отчёт **сырой текст ответа целиком** (это черновик исследования, не структура) и ответь
своими словами на три вопроса:

1. Назван ли **настоящий сайт** компании — и не подсунут ли посторонний? Оба прода отдали
   `https://alev.ru/` (это «Алев», Ульяновск, чужая компания), причём детерминированно:
   URL реально был в выдаче Exa, модель приняла его за сайт Эйч энд Эн. Ошибка не в
   галлюцинации, а в отсутствии привязки URL к юрлицу.
2. Есть ли **признаки маркировки** с ссылками? Оба прода дали `chz_signals: []` для
   молочного холдинга — категории обязательной маркировки с 2021 года. Пусто здесь
   означает, что из сниппетов подтверждения не наскрести.
3. Нет ли **самопротиворечий**? Прод выдал «микропредприятие по реестру МСП» рядом с
   «доходы 112 845 441 000 ₽» — промах в тысячу раз, склейка двух источников без сверки.

## Чего НЕ делать

- **Не менять секреты Supabase и не деплоить.** Проба живёт целиком в скрипте.
- **Не править `PRICE_BY_SLUG`** по результатам пробы: цены придут из API, а вносить их
  в код — задача следующего захода, вместе с решением по модели.
- **Не менять две вещи разом.** Если Grok на нативном движке даст глубину, но развалит
  структуру — это два разных вывода, и в отчёте они должны стоять раздельно.
- Не переписывать существующие тесты A–D скрипта. Тест `search` добавляется рядом.
