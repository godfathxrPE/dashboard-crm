## П1 (⚠️ ДО ЗАПУСКА, действие владельца) — заполнить нормы стадий

**Без этого спринт пройдёт приёмку и не покажет ничего.** Спека честно помечает нормы
прошлых стадий в макете как ДЕМО, но следствие тяжелее, чем кажется. Замер живой БД
09.09: `organizations.settings -> 'stage_target_days'` содержит **ноль ключей**,
`stage_dwell_defaults` — пустой объект. Значит `resolveStageNorm` для КАЖДОЙ стадии
падает на порог группы `STALE_BY_PHASE`:

| Стадия (IIoT Продажи) | Группа | Норма СЕГОДНЯ | Норма — вписать |
|---|---|---|---|
| 1 Лид | attraction | 14 | |
| 2 Квалификация | attraction | 14 | |
| 3 Материалы | attraction | 14 | |
| 4 Подготовка КП | working | 21 | |
| 5 Документы | working | 21 | |
| 6 Согл. ЧЗ | working | 21 | |
| 7 Встреча 3х | approval | 21 | |
| 8 Эксперимент | approval | 21 | |
| 9 Защита КП | closing | 30 | |
| 10 Договор | closing | 30 | |
| 11 Запуск проекта | closing | 30 | |

**Сумма норм воронки по дефолтам — 237 дней, то есть 7,8 месяца.** В макете владельца
та же воронка проходится за ~34–40 дней. Следствия для карты: контуры внутри группы
одинаковой высоты, факты 1–4 дня рисуются 3-пиксельным огрызком на фоне нормы 14,
пересвет прошлой стадии физически невозможен (нужно просидеть на шаге дольше трёх
недель), а прогноз финиша уедет на полгода. То есть **ровно то, ради чего вариант 1b
выбран против гармошки — «видно, где просели» — не сработает ни разу.**

Кода это не требует: редактор написан (Настройки организации → «Нормы стадий»,
S-STAGE-NORMS-UI-3), ключ `stage_target_days` читается `resolveStageNorm` ПЕРВЫМ,
до порога группы. Заполнить одиннадцать чисел — и карта заработает как нарисована.

Если нормы на момент запуска не заполнены — спринт всё равно исполним, но **в отчёте
обязана быть строка «нормы не заполнены, карта проверена на дефолтах группы»**, иначе
приёмка проверит вёрстку вместо смысла.

## П3 — тултипа НЕ будет; вместо него раскрытие по клику

Спека (B, п.5) требует Radix Tooltip с delay 300. **В проекте нет ни одного `@radix-ui`
и нет компонента `Tooltip`** (`components/ui/`: Badge, BorderTrace, Bracket, Button,
CTAButton, ChipFilter, EmptyState, InlineConfirm, InlineEdit, Input, SavedViewChips,
SegmentedControl, Table — все примитивы свои). Решение гейта, утверждено владельцем:

**Тултип не вводится ни свой, ни библиотечный.** Причины по убыванию веса:

1. Его содержимое — список заходов «15 авг → 18 авг · 3 дн. · Олег» — **дословно
   повторяет вкладку «История»** (`DealStageStory` рисует ровно эти сегменты). Это F-01,
   второй носитель одного факта; тем же доводом отклонён вариант 1c.
2. Информация только по наведению недоступна с клавиатуры и с тача.
3. Карта живёт в `overflow-x: auto` — самописное позиционирование обрежется на границе
   скролла, а правильное требует портала с обработкой коллизий.
4. Вторая библиотека примитивов в проект не заходит: за `Tooltip` приходят `Popover`
   и `Dialog`, при том что `Modal`, `InlineConfirm`, `SegmentedControl` уже свои.

**Что вместо.** Клик по столбику раскрывает **строку деталей под картой** (аккордеон,
одновременно раскрыта одна стадия; повторный клик и `Escape` закрывают). В строке:
полное имя, «{факт} дн. при норме {норма}», список заходов из `StageStory.segments`
с актором, для будущих — «норма N дн. · вероятность p%».

**И туда же переезжает откат на стадию.** Сейчас в `StageRail` клик по пройденному узлу
откатывает сделку сразу — опасное действие одним кликом. В карте клик раскрывает, а
откат становится кнопкой внутри раскрытой строки, рядом с фактом «сколько длилась и кто
вёл». `onStageClick` из `StageRailProps` сохраняется как есть, меняется только то, что
его вызывает.

Полное имя усечённой подписи под столбиком — нативный `title` плюс `aria-label` по спеке
(они нужны в любом случае). Этого достаточно: «факт при норме» уже сказан числом над
столбиком и высотой контура, вероятность будущей стадии стоит в строке кокпита.

## П4 — `t-washi`: `--accent` и `--red` это один цвет

Спека (B, п.4) велит проверить `frost`/`aurora` на слишком светлый пунктир — верно
и остаётся. Но пропущена тема, где ломается смысл: **в `t-washi` `--accent: #C23B3B`
и `--red: #C23B3B`** (`globals.css:320` и `:322`), а спека кодирует ими
противоположные состояния — `ok` заливается accent, `over` заливается red. В этой теме
«идём по норме» и «просрочено» станут одним цветом на самом важном элементе карты.

Лечение то же, что уже применено на таймлайне дедлайнов: **состояние `ok` красить
`--mark-today`**, а не `--accent`. Токен уже есть, в washi уходит в нейтраль текста,
в остальных семи темах равен акценту. Имя историческое («сегодня»), смысл шире —
«акцент, не конфликтующий с danger»; это ВТОРОЙ потребитель. Появится третий —
переименовать в нейтральное (`--mark-focus`) отдельным заходом, в этом спринте НЕ
переименовывать.

`warn` остаётся `--yellow`, `over` — `--red`: они между собой различимы во всех темах.

## П5 — что берём из спеки без изменений

`buildStageProfile(stages, factDays, normDays, gauge)` → `{ pxPerDay, columns[],
groups[], footer }`, чистая функция, **`now` аргументом** (правило проекта). Вся
математика масштаба (H=90, `pxPerDay = H/maxDays`, минимум 3px, пересвет, линия
«сегодня»), все состояния и краевые случаи (пропущенная стадия, revisit ×N, locked,
allDone, `> 14` стадий, отсутствие норм) — по спеке, раздел B пп. 3 и 6.

Источники данных сверены и верны: `StageStory.totalByStage` (сумма по всем заходам),
`gauge.days` для текущей (текущий заход — согласовано с ячейкой кокпита), `ageDays`
вместо суммы сегментов (комментарий про floor в `stage-story.ts` спека учла верно),
`resolveStageNorm` для нормы, `stageNormDateKey` для дат.

⚠️ **Второго запроса не заводить**: `useStageStory` зовётся тем же ключом, что и вкладка
«История» — React Query дедуплицирует. Если вкладка не смонтирована, запрос инициирует
карта, и это законно (тот же случай, что описан в `DealWaitingList`).
