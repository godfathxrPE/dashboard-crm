## ЗАДАЧА 1 — порядок записи: `src/lib/domain/step-flow.ts`

**Зачем.** «Сделано» пишет до трёх строк в две таблицы. Порядок не произволен. Счётчик «перенесён N раз» (`countStepMoves`) идёт по аудиту от новых строк к старым и: считает только сдвиг даты вперёд (`to > from`); сдвиг назад пропускает; обрывает счёт на строке, где дата шага была снята (`to === null`) или назначена с нуля (`from === null`). Если новый шаг записать одним `UPDATE` поверх старого, шесть переносов старого шага повиснут на новом. Поэтому старый шаг сначала снимается, затем назначается новый — два `UPDATE`, как делает `markStepDone` в карточке сделки.

Чистый модуль: план записи отдельно от исполнения.

```ts
export type StepMode = 'done' | 'update' | 'revive' | 'move';

export interface StepPrev {
  next_step: string | null;
  next_action_date: string | null;
}

export type StepWrite =
  | { kind: 'note'; body: string }
  | { kind: 'project'; next_step: string | null; next_action_date: string | null };

export interface StepInput {
  /** Итог — заметка в ленту; пустая строка — заметки нет. */
  note: string;
  /** Текст следующего шага. В режиме `move` не используется. */
  nextStep: string;
  /** День следующего шага, 'YYYY-MM-DD'. */
  dateKey: string;
}

/** План записи хода; исполняется строго по порядку. */
export function planStepWrites(mode: StepMode, prev: StepPrev, input: StepInput): StepWrite[];

/** «Оставить без шага»: заметка, если есть, и снятие шага. */
export function planLeaveWithoutStep(prev: StepPrev, note: string): StepWrite[];

/** «Вернуть»: одна запись прежних значений. */
export function planRestore(prev: StepPrev): StepWrite[];

/** Проверка ввода формы; `null` — ошибок нет. */
export function validateStepInput(mode: StepMode, input: StepInput): 'no_step' | 'no_date' | null;
```

| Режим | План |
|---|---|
| `done`, `update`, `revive` — у сделки был шаг или дата | заметка (если не пустая) → `{ null, null }` → `{ nextStep, dateKey }` |
| `done`, `update`, `revive` — шага и даты не было | заметка (если не пустая) → `{ nextStep, dateKey }` |
| `move` | `{ prev.next_step, dateKey }` — одна запись, текст шага не меняется |
| «Оставить без шага» | заметка (если не пустая) → `{ null, null }`; шага и так не было — только заметка |
| «Вернуть» | `{ prev.next_step, prev.next_action_date }` |

- Текст шага и заметка — `trim()`. Заметка из пробелов — заметки нет.
- `validateStepInput`: кроме `move`, пустой `nextStep` → `'no_step'`; пустой `dateKey` → `'no_date'`.

## ЗАДАЧА 2 — быстрые даты и ходы дня

**2.1. `src/lib/domain/step-dates.ts`**

```ts
export interface QuickDate { key: string; label: string }

/** Четыре быстрые даты формы хода; суббота и воскресенье пропускаются. */
export function quickStepDates(now: Date): QuickDate[];
```

Три ближайших рабочих дня после сегодня и первый понедельник строго после третьего. Подписи: первая — «Пн 5 окт», остальные — «Вт 6». Месяц печатается и там, где он сменился относительно предыдущей даты. «Сегодня» — `localDateKey(now)`.

**2.2. `src/lib/domain/day-moves.ts`** — набор ходов дня не должен пересобираться при каждом рендере: сделанный ход остаётся карточкой, лимит защищает день.

```ts
export interface DayMovesState {
  /** День, на который собран набор: 'YYYY-MM-DD'. */
  day: string;
  picked: string[];
  done: string[];
  /** Слот хода на момент взятия — для строки «почему здесь». */
  slots: Record<string, MoveSlot>;
}

export function parseDayMoves(raw: string | null): DayMovesState | null;

export function reconcileDayMoves(
  saved: DayMovesState | null,
  today: string,
  computed: readonly Move[],
  existingIds: ReadonlySet<string>,
  limit: number,
): DayMovesState;

export function markMoveDone(state: DayMovesState, id: string): DayMovesState;
export function unmarkMoveDone(state: DayMovesState, id: string): DayMovesState;

/** «Взять ещё ход»: первый из `computed`, которого нет в наборе. */
export function takeOneMore(state: DayMovesState, computed: readonly Move[]): DayMovesState;
```

Правила `reconcileDayMoves`:

1. `saved` нет или его день не сегодня → `picked` — id из `computed`, `done` пуст.
2. Тот же день: из `picked` убираются сделки, которых нет в `existingIds` (закрыты, отложены). `done` — только те, что остались в `picked`.
3. Сделки `computed` со слотом `assigned`, которых нет в `picked`, добавляются в начало.
4. Добор из `computed` по порядку до `limit` — если `picked` короче `limit` и при этом либо `picked` пуст, либо не все его ходы сделаны. Все ходы непустого набора сделаны — добора нет: следующий ход берётся только кнопкой.
5. Сделанный ход из `picked` не уходит, даже если его сделки больше нет в `computed`.
6. `slots` хранит слот каждого id из `picked`: для добавленных — из `computed`, у убранных запись удаляется.

`parseDayMoves`: битый JSON, не объект, нет полей, поля не массивы строк → `null`.

**Как набор дня встречается с моделью.** `buildTodayModel` в SCREEN-1 сам зовёт `pickMoves`. В этом спринте вход модели получает необязательное поле `picked?: readonly string[]`: если оно задано, `moves` — сделки из `picked` в этом порядке (id, которых нет среди сделок, пропускаются), а строки групп и `inMoves` считаются относительно `picked`. `candidates` и `computed` модель отдаёт всегда.

Порядок в `TodayView`, без круговой зависимости:

1. `base = buildTodayModel(input, now)` — без `picked`.
2. `computed = pickMoves(base.candidates.filter((c) => !done.has(c.id)), limit)` — без сделанных сегодня: иначе «Взять ещё ход» вернёт ту же сделку.
3. `state = reconcileDayMoves(saved, today, computed, existingIds, limit)`.
4. `model = buildTodayModel({ ...input, picked: state.picked }, now)`.

До чтения `localStorage` (первый рендер) экран показывает `base`.

**2.3. `src/lib/hooks/use-day-moves.ts`** — обёртка над `localStorage`, ключ `today-moves-<день>`. Чтение — в `useEffect` после монтирования (гидрация), запись — при изменении, оба в `try/catch`: хранилище недоступно — экран работает на пересчёте, без ошибки. Ключи прошлых дней не чистить.

**Проверка:** `npx vitest run tests/unit/step-dates.test.ts tests/unit/day-moves.test.ts`.

## ЗАДАЧА 3 — форма хода: `src/components/today/TodayStepComposer.tsx`

**3.1. `src/lib/hooks/use-step-flow.ts`** — исполнение плана.

- `run(projectId, writes)` идёт по `StepWrite[]` по порядку: `note` → `useCreateNote().mutateAsync({ project_id, body })`; `project` → `useUpdateProject().mutateAsync({ id, next_step, next_action_date })`.
- Первая ошибка останавливает план и пробрасывается наружу вместе с индексом упавшего шага. Уже записанное не откатывается: заметка-итог — это факт, её место в ленте.
- Логики порядка в хуке нет — она в `planStepWrites`.

**3.2. Компонент.** Одна форма для карточки хода и для блока «Сейчас» панели (макет, кадры 4 и 9).

| Режим | Поля | Кнопки |
|---|---|---|
| `done` | итог (textarea), следующий шаг, дата | «Записать в сделку» · «Оставить без шага» · «Отмена» |
| `update` | новый шаг, дата | «Обновить шаг» · «Отмена» |
| `revive` | следующий шаг, дата | «Вернуть в работу» · «Отмена» |
| `move` | дата | «Перенести» · «Отмена» |

- Подпись поля итога: «Чем закончилось — заметка в ленту сделки, необязательно». Если шаг переносили три раза и больше — «Шаг переносился {N} раз — чем закончилось на этот раз?». Поле остаётся необязательным.
- Дата: четыре чипа `quickStepDates(new Date())`, посчитанные в момент открытия формы, и `<input type="date">`. Выбор дня ничего не пишет.
- В режиме `move` под датами — цена: «в сделке станет „перенесён {N+1} раз“», `--warning-text`. N — `useFieldMoves(id).data?.step.count ?? 0`.
- В режиме `update` над полем — последняя заметка сделки справкой: «последняя заметка, {день}: …», до двух строк. Поле нового шага пустое: автоподсказки нет.
- Кнопка записи недоступна, пока `validateStepInput` возвращает ошибку. Поля — `<label>` + `<input>`, фокус при открытии — в первое поле.
- `Esc` в форме — «Отмена». `Enter` в поле шага — запись, если форма валидна.
- Ошибка записи: строка в форме «Шаг по «{сделка}» не записан. Введённый текст сохранён.» и кнопка «Повторить». Форма не закрывается, поля не очищаются. Если упал второй или третий шаг плана — повтор исполняет план с упавшего шага, заметка второй раз не пишется.
- Время действия читает обработчик: `new Date()` в `onClick`, не из пропа рендера.

## ЗАДАЧА 4 — подключение: карточки, панель, счётчик дня

**Кнопки** — на карточке хода и в блоке «Сейчас». Primary на экране одна: у первого несделанного хода. Строки таблицы проверяются сверху вниз, первая подошедшая побеждает.

| # | Сделка | Главная кнопка → режим | Рядом |
|---|---|---|---|
| 1 | шага нет (`cls.noStep`), в любой группе и в любом слоте | «Назначить шаг» → `update` | — |
| 2 | назначено на сегодня (`cls.assignedToday`) | «Сделано» → `done` | «Перенести» → `move` |
| 3 | `fresh`, `plan` | «Сделано» → `done` | «Перенести» → `move` |
| 4 | `stale`, `risk` | «Обновить шаг» → `update` | — |
| 5 | `decide` | «Вернуть в работу» → `revive` | ссылка «Закрыть сделку — в карточке» (`projectHref`) |

«Перенести» есть только там, где он стоит в таблице: у сделки без шага переносить нечего.

Ход, назначенный звонком или встречей: «Сделано» пишет итог и следующий шаг сделки, сам звонок не закрывает. Звонок закрывается своей кнопкой «Выполнен» в блоке «Сейчас» (SCREEN-1, 4.2); не закрытый — завтра даст сигнал `call_overdue`.

«Отложить» остаётся там же, где в SCREEN-1.

**После записи** (макет, кадр 5):

- Карточка хода: «Записано в сделку · шаг {день}» / «Перенесён на {день} · в сделке „перенесён N раз“» / «Шаг закрыт · сделка осталась без шага» + «Вернуть». Номер хода — зелёный (`--success`), шаг зачёркнут.
- Строка остаётся на своём месте до перезагрузки экрана: в колонке срока «шаг {день}», ниже «записано сегодня» (`--success-text`). Для этого `buildTodayModel` получает необязательный вход `pinnedGroups: ReadonlyMap<string, TodayGroup>` — группа показа. Правила: строка стоит только в группе показа, в настоящей группе её нет; `total` и `inMoves` групп считаются по группе показа; `noStepAhead` — по настоящему классу; порядок в группе — прежний `compareByWeight`; на сделки из `picked` карта не действует. Карта живёт в состоянии `TodayView` и пополняется при записи.
- После перезагрузки вид итога на карточке сделанного хода берётся из текущего состояния сделки: шаг впереди — «Записано в сделку · шаг {день}»; шага нет — «Шаг закрыт · сделка осталась без шага». Формулировка «Перенесён на …» живёт только до перезагрузки.
- «Вернуть» исполняет `planRestore(prev)` и снимает отметку. `prev` хранится в состоянии экрана до перезагрузки; после перезагрузки «Вернуть» нет.
- Главное число в шапке списка уменьшается сразу (optimistic-правка `useUpdateProject`).

**Счётчик дня** (шапка, справа): три точки и «{сделано} из {в наборе} ходов сделано». Набор — `useDayMoves` + `reconcileDayMoves`; запись хода зовёт `markMoveDone`, «Вернуть» — `unmarkMoveDone`.

Все ходы набора сделаны — карточки сворачиваются в строку: «3 из 3 ходов сделано · {имена} — шаги записаны в сделки» и кнопка «Взять ещё ход» (`takeOneMore`). Кандидатов нет — кнопки нет.

**«Разобрать по одной»** — ссылка в свёрнутой строке «Решить судьбу»: раскрывает группу и панель первой строки. После записи по сделке этой группы раскрывается панель следующей строки группы; строк не осталось — панель закрывается.

**Снять временный путь.** `ProjectModal`, состояние `modalOpen` и кнопка «Запланировать шаг» из `src/components/today/` уходят. Проп `focusNextAction` у `ProjectModal` остаётся без потребителей — не трогать, записать в отчёт.
