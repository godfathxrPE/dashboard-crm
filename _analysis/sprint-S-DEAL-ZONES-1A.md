## ЗАДАЧА 1: примитив зоны

### Context

Зона — не карточка: у неё цветная подложка, крупный радиус и eyebrow-заголовок, а карточки
лежат ВНУТРИ неё на белом. Пять мест (три зоны × состояния) с повторяющимся набором
утилит — это класс, а не копипаст по компонентам.

### Steps

**1.1** В `globals.css`, в первый `:root` рядом с `--zone-*`, добавить `--radius-zone: 26px`.
Радиус зоны крупнее карточного намеренно: вложенность читается радиусом, а не рамкой.
В `.t-lime` переопределять не нужно — 26px общий.

**1.2** В `@layer components` (рядом с `.nav-active`) — примитив:

```css
/* Зона карточки сделки (S-DEAL-ZONES-1A). Подложка + крупный радиус; карточки
   внутри остаются белыми и отделяются тенью. Фон приходит извне через
   --zone-surface, чтобы одна и та же геометрия работала для всех трёх зон. */
.zone {
  background: var(--zone-surface, var(--zone-ctx));
  border-radius: var(--radius-zone);
  padding: 1rem;
  display: flex;
  flex-direction: column;
  gap: 0.75rem;
}
.zone-eyebrow {
  display: flex; align-items: baseline; gap: 0.5rem;
  font-size: 0.6875rem; font-weight: 700;  /* text-meta; 10px-капс запрещён S-TYPO-SCALE */
  text-transform: uppercase; letter-spacing: 0.1em;
}
.zone-eyebrow small { font-weight: 400; letter-spacing: 0; text-transform: none; }
```

`--zone-surface` ставится на самой зоне инлайн-стилем от токена (`var(--zone-work)` и т.д.) —
это НЕ хардкод цвета, значение приходит из темы. Проверить, что `audit-tokens.py` не считает
это нарушением; если считает — завести три класса-модификатора `.zone-work` / `.zone-ctx` /
`.zone-risk` вместо инлайн-переменной и сказать об этом в отчёте.

## ЗАДАЧА 3: три зоны вместо двухколонника — ТОЛЬКО для сделок

### Context

Правая колонка сейчас — один `DealContextRail` с пятью карточками. Делится на две зоны с
разными фонами и смыслом. Ширина правой колонки 320 → **356** (макет; на 1440 левая колонка
остаётся ≥ 800px, карте воронки хватает).

**Границы: зоны получают ТОЛЬКО `project.type === 'client'`.** Внедрения и internal
сохраняют нынешний двухколонник без изменений. Причина не в экономии: `ProjectDetail` —
общий файл, и на внедрении здоровье считает `getDeliveryHealth`, а не `signals.verdict`;
`useDealSignals(project)` при этом не гейтится по типу и посчитает deal-сигналы
(next_step / deadline / silence) для карточки, где их смысла нет. Покрасить зону «Риски»
внедрения `DealVerdict`-ом — применить чужую формулу к чужой карточке. Макет «Сделка v2»
внедрение не описывает, и придумывать его зонирование здесь нечем.

Практически: ветка `type === 'client'` рендерит зоны, `else` — нынешнюю разметку. Да, это
две компоновки в одном файле; альтернатива хуже.

### Steps

**3.1 `ProjectDetail.tsx`** — для `type === 'client'` сетка
`lg:grid-cols-[minmax(0,1fr)_356px]`, левая колонка — зона «Работа»:

```tsx
<section
  className="zone order-1 min-w-0 lg:col-start-1"
  style={{ ['--zone-surface']: 'var(--zone-work)' } as React.CSSProperties}
>
  <div className="zone-eyebrow" style={{ color: 'var(--accent-text)' }}>
    Работа <small className="text-text-dim">что делаем сейчас · где в воронке · задачи</small>
  </div>
  {кокпит}
  {hasNextStep && <DealNextStep project={project} signals={signals} />}
  {вкладки и их содержимое}
</section>
```

Каст `as React.CSSProperties` обязателен: кастомное свойство не входит в тип `CSSProperties`,
без него `tsc` красный.

`{hasNextStep && …}` — не сниппет ради красоты: без условия «Какой следующий шаг?» появится
на выигранной сделке. Зона «Работа» без шага (кокпит + вкладки) — нормальное состояние.

Правая колонка — две зоны, **sticky на обёртке**, не на каждой:

```tsx
<div className="order-2 flex flex-col gap-4 lg:col-start-2 lg:sticky lg:top-4 lg:self-start">
  <section className={cn('zone', healthClass)}
           style={{ ['--zone-surface']: 'var(--h-zone)' } as React.CSSProperties}>
    <div className="zone-eyebrow" style={{ color: 'var(--h-chip-ink)' }}>
      Риски <small className="text-text-dim">что может сорвать сделку</small>
    </div>
    {Здоровье} {Закреплено}
  </section>

  <section className="zone" style={{ ['--zone-surface']: 'var(--zone-ctx)' } as React.CSSProperties}>
    <div className="zone-eyebrow text-text-dim">
      Контекст <small>кто, сколько, что собрано</small>
    </div>
    {Сводка} {Стейкхолдеры} {Материалы}
  </section>
</div>
```

`lg:sticky lg:top-4 lg:self-start` перенести с `DealContextRail` на эту обёртку —
иначе «Риски» уедут при скролле ленты. `self-start` не косметика: растянутый по строке
грида элемент sticky не липнет.

**3.2 Подзаголовок зоны «Риски» — СТАТИЧЕСКИЙ.** «что может сорвать сделку», без пересказа
вердикта. Словами вердикт уже говорит `DealVerdictChip` под шагом, и это закрытая F-01
(R-09: вердикт в рабочей колонке, в рельсе только список сигналов). Динамический
подзаголовок сделал бы два словесных носителя одного факта — ровно тот дефект, который
чинили.

**Фон зоны при этом остаётся динамическим** — это ответ на F-10: уровень несёт заливка,
а не ещё один бейдж. Маппинг:

| `verdict` | `healthClass` | фон |
|-----------|---------------|-----|
| `ok` | нет | дефолт `--h-zone` = `--zone-risk-ok` |
| `new` | нет | тот же дефолт — льготный период не «внимание» |
| `attention` | `h-attention` | `--zone-risk-attention` |
| `rotting` | `h-rotting` | `--zone-risk-rotting` |

Снятие чипа и перенос слов в зону — это 1B, где в «Рисках» появится кольцо с вердиктом
внутри. Делать это сейчас значит на один спринт оставить экран вообще без словесного
вердикта.

**3.3 `DealContextRail.tsx`** — расщепить на `DealRisksZone` и `DealContextZone` либо
оставить один компонент с пропом `zone: 'risks' | 'context'`. Выбрать то, что даёт меньше
дублирования пропов; какой вариант выбран — в отчёт. Ветка delivery/internal продолжает
использовать прежний путь: если расщепление ломает его, оставить `DealContextRail` как
тонкую обёртку над двумя зонами.

**3.4** Порядок вне `lg` — `order-*`: Работа → Риски → Контекст.

**3.5 Не затянуть в «Работу»:** `ProjectChecklists` и `DealDeliveryHub` стоят МЕЖДУ шапкой
и сеткой; `ProjectTeam` — в левой колонке над вкладками и только у delivery. Вкладок больше
четырёх: помимо Активность / План / Гант / Чат есть КП и История — переносить все.
