# Claude Code Prompt — Sprint LEAD-CARD-VISUAL-1: карточка лида по согласованному макету

## Контекст

Визуал карточки лида согласован 2026-08-10 после четырёх раундов макетов (решение целиком —
в проекте «CRM Design auditor» → `claude/leads-entity-design-decisions.md`, §7). Каркас
страницы менять не нужно — он уже такой после S-LEAD-HUB-2a и S-PIPELINE-COCKPIT-1. Меняется
блок квалификации, гейт кокпита, сигналы и два состояния.

**Миграций нет. Схема `leads` не меняется.** Все шесть полей квалификации существуют:
`pain`, `budget_status`, `decision_role`, `chz_groups`, `regulatory_deadline`, `estimated_value`
(проверено интроспекцией живой БД 2026-08-10).

### Что делаем

1. Домен: правила квалификации лида — шесть пунктов, два обязательных, чистая функция.
2. Кокпит лида получает **гейт** (сейчас `gate={null}`): точки = обязательные пункты,
   «готовность 1/2», замок на «Конвертировать» держат только они.
3. Блок квалификации перестраивается в **две зоны**: «Осталось выяснить» (подложка, действия)
   и «Известно» (плотная справка).
4. Карточка «Сигналы» — исключения с формулировкой-следствием; регуляторный дедлайн ближе
   3 мес. поднимается в warning-баннер.
5. Состояния: пустой новый лид, конвертированный лид.

### Что НЕ делаем (осознанно)

- Вкладки активности из макета — фильтры уже живут чипами внутри `EntityTimeline`, компонент
  общий со сделками/компаниями/контактами. Не трогаем.
- Серверный гейт конверсии — у лида его нет и не будет (лид вне `pipeline_stages`,
  `stage_requirements` неприменимы). Замок клиентский и реально блокирует — это честно.
- Поле «Конкуренты» — такой колонки нет, в макете оно было ошибкой, шестой пункт —
  `estimated_value`.

### Красные линии

`.env` не читается · `src/types/database.ts` и `supabase.gen.ts` руками не правятся ·
миграции не пишутся · прод-БД не трогается · настройки среды владельца (localStorage, тема)
не меняются · перед билдом остановить `next dev`, если запущен.

## ЗАДАЧА 1: домен — правила квалификации лида

### Context
Чистая логика (конвенция проекта: `lib/domain/`, «сейчас» параметром, ноль запросов,
юнит-тесты в `tests/unit/**` — иначе vitest их не подхватит).

### Steps
Создать `src/lib/domain/lead-qualification.ts`:

```ts
import type { Lead } from '@/lib/hooks/use-leads'; // тип уточнить по факту (см. РАЗВЕДКА п.1)

// ═══════════════════════════════════════════════════════
// S-LEAD-CARD-VISUAL-1: квалификация лида — шесть пунктов, два обязательных.
//
// ⚠️ Обязательность — КОНСТАНТА продукта, не настройка организации: правило одно,
// а настройка добавила бы экран ради двух галок (решение §7 leads-entity-design).
// Пересмотреть, если появится направление с другой квалификацией.
//
// ⚠️ Пункта «Конкуренты» нет: такой колонки в `leads` не существует.
// ═══════════════════════════════════════════════════════

export type LeadQualKey =
  | 'pain' | 'budget' | 'role' | 'chz' | 'deadline' | 'value';

export interface LeadQualItem {
  key: LeadQualKey;
  /** Заголовок пункта — одинаковый в обеих зонах. */
  label: string;
  /** Держит конверсию. */
  required: boolean;
  filled: boolean;
  /** Значение для зоны «Известно» (null у незакрытых). */
  value: string | null;
  /** Следствие незаполненности для зоны «Осталось выяснить». */
  hint: string;
}

export interface LeadQualification {
  items: LeadQualItem[];
  missing: LeadQualItem[];          // !filled, обязательные первыми
  known: LeadQualItem[];            // filled
  filledCount: number;              // для «4 из 6»
  total: number;
  requiredMissing: LeadQualItem[];  // держат конверсию
  requiredMet: number;              // для «готовность 1/2»
  requiredTotal: number;
  canConvert: boolean;              // requiredMissing.length === 0
}
```

Правила заполненности:

| Пункт | Заполнен, когда | Значение в «Известно» |
|---|---|---|
| `pain` (обяз.) | `pain` непустая строка | текст боли (обрезать до ~60 симв. с многоточием) |
| `budget` (обяз.) | `budget_status !== 'unknown'` | `LEAD_BUDGET_STATUS_CONFIG[...].label` |
| `role` | `decision_role` непустой | `STAKEHOLDER_ROLE_CONFIG[...]?.full ?? decision_role` |
| `chz` | `chz_groups?.length > 0` | группы через запятую |
| `deadline` | `regulatory_deadline` есть | дата `ru-RU`, `day numeric / month long / year numeric` |
| `value` | `estimated_value != null` | `formatBudget(estimated_value)` |

Подсказки-следствия (не констатация): «Боль не выяснена — квалификация неполная» ·
«Бюджет не выяснен» · «ЛПР не подтверждён» · «Группы «Честного Знака» не указаны» ·
«Дедлайн маркировки неизвестен» · «Сумма не оценена».

Сортировка `missing`: обязательные первыми, внутри — порядок объявления.

Тесты `tests/unit/lead-qualification.test.ts`: `budget_status: 'unknown'` ⇒ не заполнен,
`'none'` ⇒ **заполнен** (отсутствие бюджета — тоже выясненный факт, это не пропуск);
пустая строка/пробелы в `pain` ⇒ не заполнен; `chz_groups: []` ⇒ не заполнен;
`canConvert` только при обоих обязательных; порядок `missing` (обязательные вперёд);
счётчики `filledCount`/`requiredMet` на полном и пустом лиде.

## ЗАДАЧА 2: гейт кокпита из квалификации

### Context
Сейчас `LeadDetail` передаёт `gate={null}` — точек нет, а замка на «Конвертировать» тем
более. Кокпит уже умеет рисовать и точки, и замок (S-PIPELINE-COCKPIT-1), нужно только
подать данные.

### Steps
В `src/components/leads/LeadDetail.tsx`:

1. Посчитать квалификацию один раз: `const qual = useMemo(() => qualifyLead(lead), [lead])`.
2. `gate` — **только обязательные** пункты:
   ```tsx
   gate={{
     title: 'Готовность к конверсии',
     items: qual.items.filter(i => i.required).map(i => ({ label: i.label, met: i.filled })),
   }}
   ```
   Точек будет две, подпись «готовность 1/2» — компонент считает сам.
3. `next` для статуса `qualified`:
   ```tsx
   { label: 'Конвертировать', locked: !qual.canConvert,
     onClick: qual.canConvert ? () => setConvertOpen(true) : undefined }
   ```
   ⚠️ **Отличие от сделок**: там locked-кнопка всё равно кликается (сервер — истина).
   У лида серверного гейта нет, поэтому при `locked` обработчик не передаётся —
   замок реально блокирует. Написать это комментарием рядом, иначе следующий спринт
   «починит» расхождение с кокпитом сделок.
4. Для статусов `new`/`contacted` гейт не передавать (`gate={null}`) — до квалификации
   он не имеет смысла; кнопки «Связаться»/«Квалифицировать» остаются как есть.

## ЗАДАЧА 3: блок квалификации — две зоны

### Context
Ключевая правка макета. Разделение **не по обязательности, а по «требует действия / уже
известно»**: три предыдущие итерации (колонки, полоса-прогресс, ряды с бейджами «ОБЯЗ.»)
давали дыры в сетке и инверсию веса — закрытое с зелёными галками кричало громче незакрытого.

### Steps
Заменить существующий блок «Квалификация» (правая колонка `LeadDetail`, найти по РАЗВЕДКЕ п.1)
на блок во всю ширину под парой «Следующий шаг / Сигналы»:

```
┌ КВАЛИФИКАЦИЯ  4 из 6 ─────────────────────────────────────────────┐
│ ┌ подложка --surface2 ─────────────┐  ИЗВЕСТНО                     │
│ │ ОСТАЛОСЬ ВЫЯСНИТЬ                │  Бюджет      Оценён           │
│ │ Боль / задача      [Заполнить]   │  Дедлайн ЧЗ  31 августа 2026  │
│ │ 🔒 держит конверсию              │  Оценка      1.5M ₽           │
│ │ Роль контакта      [Заполнить]   │  Группы ЧЗ   Удобрения        │
│ │ ЛПР не подтверждён               │                               │
│ └──────────────────────────────────┘                               │
└────────────────────────────────────────────────────────────────────┘
```

Требования:

- Заголовок блока: `КВАЛИФИКАЦИЯ` (`text-meta uppercase tracking-wider text-text-mute`) +
  `{filledCount} из {total}` (`text-sm font-semibold text-text-main`). Подзаголовков нет.
- **Левая зона** (`bg-surface2 rounded-[var(--radius)] p-4`, ширина ~40%):
  заголовок `ОСТАЛОСЬ ВЫЯСНИТЬ` — `text-meta uppercase font-semibold text-text-mute`
  (**нейтральный, не жёлтый**: жёлтый на экране только у реальной блокировки);
  на пункт — строка: слева имя (`text-sm font-semibold text-text-main`) + под ним `hint`
  (`text-xs text-text-mute`), у обязательных вместо hint — строка с иконкой `Lock` 11px
  и текстом «держит конверсию», цвет `var(--yellow-text, var(--yellow))`;
  справа кнопка «Заполнить» — у обязательных акцентная (`border-[var(--accent)]`,
  цвет `var(--accent-text)`), у остальных обычная (`border-border text-text-dim`).
- **Правая зона**: заголовок `ИЗВЕСТНО` тем же стилем; сетка `grid grid-cols-2 gap-x-8 gap-y-2`,
  в ячейке `метка → значение`: метка `text-sm text-text-dim`, значение `text-sm text-text-main`
  (суммы и даты — `tabular-nums`). **Галок нет.** Чипы (группы ЧЗ) не должны увеличивать
  высоту строки — задать строке фиксированный `min-h` или выводить группы текстом через запятую.
- **Все шесть закрыты** ⇒ левая зона не рендерится, правая занимает всю ширину
  (`grid-cols-3` или `grid-cols-4`).
- **Ничего не закрыто** (новый лид) ⇒ правая зона не рендерится, левая на всю ширину
  в две колонки пунктов + подсказка под ней:
  «Заполни хотя бы боль и бюджет — тогда можно квалифицировать» (`text-xs text-text-mute`).
- Клик «Заполнить»: для `pain` — инлайн-правка через `InlineEdit` (`as="textarea"`,
  мутация `useUpdateLead`); для остальных пяти — открыть `LeadModal` (`setEditOpen(true)`),
  там эти поля уже есть. Причина: боль пишется в свободной форме прямо на месте, а роль/
  группы/дата — селекты и мультиселект, им нужна форма.

## ЗАДАЧА 4: карточка «Сигналы»

### Context
Сигналы — исключения, а не дубль квалификации. Пробелы квалификации туда **не попадают** —
они живут в левой зоне блока выше.

### Steps
1. Карточка справа от «Следующий шаг» (пара уже есть в макете; если в коде её нет —
   завести рядом с фокус-панелью, `grid lg:grid-cols-[minmax(0,1fr)_22rem]`).
2. Заголовок `СИГНАЛЫ` тем же стилем, что заголовки зон.
3. Содержимое — только исключения:
   - **Регуляторный дедлайн ≤ 3 мес.** — warning-баннер: фон `--yellow-l`, иконка
     `AlertTriangle` 14px, текст «Дедлайн маркировки через N мес. — окно на пилот
     закрывается {дата}». Функция `regulatoryMonths` в файле уже есть — переиспользовать,
     порог 3 мес. вынести константой рядом.
   - **Здоровье лида** (`getLeadHealth`): `overdue-action` → «Шаг просрочен N дн.»,
     `stale`/`cold` → «Молчание N дн. — лид остывает». ⚠️ Не дублировать фокус-панель:
     она уже показывает просрочку шага и `LeadHealthMark`. Показывать в сигналах **только
     то, чего нет в фокус-панели** — сверить по РАЗВЕДКЕ п.4 и написать в отчёте, что
     решено показывать.
4. **Исключений нет ⇒ карточка не рендерится вовсе** (не «пустое состояние с текстом»).
   Тогда «Следующий шаг» занимает всю ширину.

Макет требует карточку созданной сделки: что именно родилось из лида.

### Steps
1. При `lead.status === 'converted' && lead.converted_deal_id`:
   вместо карточек «Следующий шаг»/«Сигналы» — одна карточка «Сделка создана»
   (фон `--green-l` либо обычный surface с зелёной меткой):
   название сделки (ссылка на `/deals/{id}`), стадия, сумма, ответственный, дата конверсии

   правая показывает всё, что было выяснено, заголовок «КВАЛИФИКАЦИЯ · только чтение».
3. Кокпит остаётся `locked` (уже так).
4. Кнопка «К сделке» в шапке — оставить, это навигация.
