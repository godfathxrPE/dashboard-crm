## Зачем

Спека рисует зону «Работа» стопкой: Кокпит → Следующий шаг → Доска задач → Орг. блок →
Активность. В коде под Кокпитом стоит ряд из шести вкладок (`ProjectDetail.tsx:77`,
`activity | board | timeline | quotes | story | chat`), и одновременно видна одна.

Принято (Р-A, гибрид):

```
Зона «Работа»
  ├ Кокпит стадии            (есть)
  ├ Следующий шаг            (есть)
  ├ Доска задач              ← из вкладки board, свёрнута по умолчанию
  ├ Организационный блок     ← из вкладки quotes + материалы, свёрнут
  └ вкладки: Активность · Гант · История · Чат
```

Вкладка «КП» упраздняется: её содержимое — часть орг. блока.
Вкладки «Гант», «История», «Чат» остаются вкладками — спека их не рассматривала,
а стопкой они дают четыре экрана прокрутки и хоронят всё, что ниже.

⚠️ **Компоновка общая для трёх типов проектов.** `workContent`
(`ProjectDetail.tsx:269`) — один узел на обе раскладки: у сделки он внутри зоны
«Работа», у `delivery`/`internal` — в левой колонке прежнего двухколонника
(комментарий S-DEAL-ZONES-1A прямо запрещает копию JSX). Перестройка НЕ должна
сломать вторую компоновку: у внедрения нет ни КП, ни зон, зато есть `ProjectTeam`
и вкладка «План».

## ЗАДАЧА 1 — свернуть/развернуть как общий примитив

Доске задач и орг. блоку нужен ОДИН механизм сворачивания, а не два разных.

`src/components/shared/CollapsibleSection.tsx`:
- свёрнутое состояние — одна строка: заголовок 12/700, сводка мелким, справа
  «Развернуть ▾»; развёрнутое — та же строка + содержимое под hairline;
- состояние per-виджет per-сделка в `localStorage` — ключ вида
  `deal-section:<projectId>:<sectionId>`; **чтение и запись в try/catch**, отсутствие
  значения = дефолт из пропа. Настройки среды владельца не трогаем (красная линия
  скилла: читать можно, писать — про localStorage интерфейса это и есть исключение,
  но только по своему ключу);
- `aria-expanded` на кнопке, содержимое скрывается `hidden`, а не размонтированием —
  иначе доска задач перезапрашивается на каждый разворот.

## ЗАДАЧА 2 — доска задач из вкладки в стопку

Вынести `ProjectBoard` (+ `PlanImportButton`) из ветки `activeTab === 'board'` в
`CollapsibleSection` с id `board`, дефолт — **свёрнута**.

Свёрнутая строка: «Доска задач» · счётчик задач · сводка «N в работе · M ждёт · K
готово» — числа взять там же, где их берёт доска, второго запроса не заводить.

⚠️ У `delivery` эта секция называется «План» и **не сворачивается** (у внедрения
доска — основной экран, а не приложение к сделке). Условие по `isDelivery`, как в
нынешнем лейбле вкладки.

## ЗАДАЧА 3 — орг. блок как контейнер (пустой)

`src/components/projects/DealOrgBlock.tsx` — `CollapsibleSection` с id `org`,
дефолт свёрнут. **В этом спринте внутрь переезжает ТОЛЬКО существующее:**

Свёрнутая строка: «Организационный блок» · сводка «КП v{N} · {статус} · {M} файлов».
Наполнение по спеке W4 (срок действия, «Принято/Отклонено», ожидаемый файл) —
СЛЕДУЮЩИЙ спринт S-DEAL-ORG-1, здесь только переезд.

Только для `type === 'client'`: у внедрения КП нет.

## ЗАДАЧА 4 — вкладки: убрать «КП», сохранить маршруты

`type Tab` теряет `'quotes'`. Оставшиеся: `activity | board? | timeline | story | chat`.

⚠️ `'board'` из типа НЕ удалять, пока разведка не покажет, что на него никто не
ссылается: у `delivery` доска остаётся вкладкой-«Планом».

Все входящие ссылки `?tab=quotes` (разведка, п. 1) должны вести на карточку с
РАЗВЁРНУТЫМ орг. блоком: при `?tab=quotes` в URL — разворачивать секцию `org` и
скроллить к ней, сам параметр из URL убирать (`router.replace`). Мёртвая ссылка из
уведомления полугодовой давности не должна открывать пустоту.
