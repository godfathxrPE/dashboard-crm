## КЛЮЧЕВЫЕ РЕШЕНИЯ

1. **Канал проекта задаёт привязку по умолчанию.** Это главный источник контекста, и он
   бесплатный: сообщение в канале «Ориент Продактс — внедрение» почти всегда про эту
   сделку. Если `conversation.kind === 'project'` — предзаполнить привязку этой сделкой.
   Ноль угадывания: канал знает свой `project_id` точно.
2. **Поле «Привязка» становится живым поиском, а не текстом-заглушкой.** `Combobox` с
   поиском по названию среди сделок/проектов и компаний. Пользователь всегда видит, к
   чему привяжется, и может сменить — принцип «никогда не привязывать молча» сохранён,
   меняется только то, что теперь есть ЧТО выбирать.
3. **Текст сообщения — подсказка, а не решение.** Из текста берём кандидата и
   **предзаполняем поиск** (не саму привязку, если кандидат неоднозначен). Правило:
   ровно одно совпадение по названию → предвыбрать; несколько → открыть список с
   набранным запросом и ничего не выбирать; ноль → пустой поиск. «Ориент» даёт три
   совпадения («Ориент Продактс», «Ориент Продактс — внедрение», «Пресейл Ориент») —
   это тот самый случай, ради которого я запрещал угадывание, и он решается показом
   трёх строк, а не отказом от привязки.
4. **Приоритет источников:** явный выбор пользователя → чип в сообщении (как было) →
   канал проекта → кандидат из текста. Первый непустой выигрывает.
5. **Порядок в списке — по свежести.** Сначала сделки/проекты (`projects`, сортировка по
   `updated_at desc`), затем компании. Сделка ближе к задаче, чем компания: задача
   «звонок» почти всегда про сделку в работе.

## ЗАДАЧА 1 — Хук поиска сущностей

`src/lib/hooks/use-entity-search.ts`:
```ts
export interface EntityOption {
  entityType: 'deal' | 'project' | 'company';
  id: string; label: string; sub?: string;   // sub: имя компании у сделки / «Компания»
}
export function useEntitySearch(query: string): { options: EntityOption[]; isLoading: boolean }
```
- Дебаунс 250 мс; пустой запрос → отдаёт **последние 20 сделок по `updated_at`**
  (список не должен быть пустым при открытии — человеку надо что-то видеть).
- Запрос: `projects` — `.ilike('name', '%q%')`, `.limit(20)`, тип по
  `projects.type` (`client` → `deal`, иначе `project`); `companies` — `.ilike('name',…)`,
  `.limit(10)`.
- **`ilike` с пользовательским вводом**: экранировать `%` и `_` в запросе
  (`q.replace(/[%_]/g, '\\$&')`), иначе «100%» превращается в маску. Юнит-тест на
  экранирование обязателен.
- React Query, ключ `['entity-search', q]`, `staleTime` 60 с. RLS сама режет невидимое.

## ЗАДАЧА 2 — Кандидат из текста

В `src/lib/utils/task-intent.ts` добавить к `TaskIntent`:
```ts
  nameHint: string | null;   // вероятное имя сущности из текста
```
Эвристика простая и честная: после вырезания даты и триггер-фраз взять **слова с
заглавной буквы** (кроме первого слова предложения) и кавычки-«ёлочки» — «звонок Ориент»
→ `Ориент`, «позвонить в ООО "Мукомол"» → `Мукомол`. Ничего не нашли → `null`.
Не изобретать морфологию: «Ориенту» просто не совпадёт, и это нормально — поиск
предзаполнен, человек допечатает. Тесты: имя есть / нет / несколько слов подряд
(«Аграрная Группа» → берём всю последовательность) / первое слово предложения не считается.

## ЗАДАЧА 3 — Карточка

`TaskFromMessageCard`:
- новый проп `conversation: { kind: ConversationKind; projectId: string | null;
  title: string }` (прокидывает `MessageThread`, у него он уже есть);
- поле «Привязка» → `Combobox` c `useEntitySearch`;
- начальное значение по приоритету из решения 4; под полем — строка-объяснение
  источника: «из канала проекта» / «из ссылки в сообщении» / «найдено по тексту: Ориент»
  / «выберите вручную». Это прямое продолжение «распознано: …» у даты — человек видит,
  откуда система взяла ответ;
- маппинг в `useCreateTask` прежний: `deal`/`project` → `project_id`, `company` →
  `company_id`. Контакты из поиска исключены (задача на контакт без сделки — редкий
  сценарий, чип на контакт по-прежнему работает).

## EDGE CASES

- Канал группы или общий чат: привязки по умолчанию нет, поиск пустой с последними
  сделками (решение 1 не применяется).
- Чип в сообщении и канал проекта расходятся — побеждает чип (он явнее).
- Кандидат из текста совпал с одной сделкой, но пользователь в канале другого проекта:
  побеждает **канал** (приоритет 3 выше 4) — контекст канала надёжнее строки.
- Поиск ничего не нашёл — карточка создаётся без привязки, как сейчас; это валидный
  исход, а не ошибка.
- Длинное название в Combobox — truncate, полное в `title`.
