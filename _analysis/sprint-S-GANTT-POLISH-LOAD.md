# S-GANTT-POLISH: undo, типы связей, экспорт, навигация

**Ветка:** `feat/gantt-polish`. Тип D2. Порядок задач внутри — по убыванию отдачи, можно резать снизу.

## ЗАДАЧА 1 — Undo сдвига (самое ценное здесь)

Сейчас любой драг применяется сразу, откат — только ручной драг назад. После S-SCHEDULE-1B цена
ошибки выросла: один клик двигает десяток задач.

- Внутри `commitDates` и внутри `useShiftTasks` запоминать `{ id, prevStart, prevEnd }[]`.
- Тост успеха получает `action: { label: 'Отменить', onClick: … }` → обратный батч теми же хуками.
- Окно — одно последнее действие (стек не нужен, это не редактор). Живёт до следующего коммита дат.
- Обратный батч идёт через тот же `useShiftTasks` → оптимистик и обработка частичного отказа
  уже готовы, нового кода почти нет.

## ЗАДАЧА 2 — Типы связей SS / FF / SF

- В popover ребра — селект типа рядом с уже существующим редактором `lag_days`.
- Мутация: **строго `dep_type` и `lag_days`** (менять концы ребра через UPDATE нельзя — DAG-валидатор
  048 стоит только на BEFORE INSERT, см. 062; это уже зафиксировано в комментарии
  `useUpdateTaskDependency`).
- Проверить, что enum `DepType` в БД реально содержит все четыре значения (`execute_sql` на
  `pg_enum`), иначе нужна миграция — и тогда спринт перестаёт быть UI-only.
- Семантика `earliest` расширяется в **одном** месте — `gantt-schedule.ts`, обе функции
  (`computeCascade`, `computeCpm`) начинают понимать новые типы:
  `SS: succ.start ≥ pred.start + lag`, `FF: succ.end ≥ pred.end + lag`,
  `SF: succ.end ≥ pred.start + lag`. Плюс vitest на каждый тип. Три места расчёта FS
  (warn / каскад / CPM) обязаны остаться согласованными.
- Отрисовка стрелок для SS/FF меняет точки входа/выхода (левый край вместо правого) — это самая
  муторная часть, эффект измерения рёбер придётся править аккуратно.

## ЗАДАЧА 3 — Экспорт PNG

- `html2canvas` по контейнеру Ганта, имя файла `Гант_{проект}_{YYYY-MM-DD}.png`.
- Перед снимком — временно снять `overflow` и виртуальные ограничения ширины, чтобы в кадр попал
  весь горизонт, потом вернуть. Проверить, что SVG-стрелки и CSS-переменные тем рендерятся
  (html2canvas и `oklch`/`color-mix` живут плохо — если тема на них, нужен фолбэк).
- Альтернатива, если html2canvas подведёт: печать через `window.print()` + `@media print`-стили.
  Дешевле и даёт PDF руками пользователя. Решать по факту на первом прогоне.

## ЗАДАЧА 4 — Навигация и читаемость

- Кнопка «Сегодня» + автоскролл к текущей дате при первом рендере (сейчас открывается на начале
  горизонта — на длинном проекте это пустое поле).
- Затенение выходных в `day`-зуме (фон колонки через CSS-переменную темы; **не** маркер рабочего
  календаря — праздники РФ по-прежнему вне скоупа).
- Вертикальная линия «сегодня» поверх сетки.

## VERIFY / коммит

Стандартно: `tsc --noEmit`, `eslint`, `vitest run src/lib/utils` (новые кейсы SS/FF/SF),
grep на `any` и хардкод-цвета, смоук по темам aura + fuji, зумы day/week/month.
Коммит conventional, одна фича — один коммит, чтобы Задачу 2 можно было отреверить отдельно.

Трудоёмкость: undo ~2 ч, типы связей ~6–8 ч (стрелки!), экспорт ~3 ч, навигация ~3 ч.
Риск: типы связей — средний (трогают всю математику расписания), остальное низкий.

# S-GANTT-LOAD: загрузка исполнителей (опционально)

**Ветка:** `feat/gantt-load`. Тип D2. Полспринта. Брать, только если команда реально пересекается
по задачам — иначе фича будет красивой и мёртвой.

## Идея

Строка-тепловая карта под осью дат: на каждый бакет — суммарное число одновременных задач на
исполнителя. Порог перегруза настраивается константой (`MAX_PARALLEL = 3`), превышение красится
через CSS-переменную предупреждения.

- Данные уже на клиенте: `assigned_to` в `Task`, span в `GanttTask` — новых запросов нет.
- Расчёт — чистая функция в `gantt-schedule.ts`:
  `computeLoad(nodes, assigneeById, buckets) → Map<bucketKey, Map<assigneeId, number>>`, с vitest.
- Сводные задачи **исключить** из подсчёта (иначе родитель и дети считаются дважды).
- Фильтр «показать загрузку: все / конкретный человек» — переиспользовать существующий фильтр Ганта.
- Клик по перегруженному бакету → подсветить бары, дающие перегруз.

## Чего здесь НЕТ

**Resource leveling** (автоматическая переброска задач ради выравнивания загрузки) — не делаем ни
здесь, ни в v2. Это NP-трудная задача с эвристиками, в Bryntum и MS Project она годами обрастает
настройками и всё равно даёт результат, который планировщик переделывает руками. Показать перегруз
полезно; решать за человека, кого подвинуть, — нет.

Трудоёмкость: ~4–6 ч. Риск: низкий (аддитивная строка, ничего существующего не трогает).

## Порядок и общий смысл

```
S-SCHEDULE-1B  →  S-GANTT-CPM  →  S-GANTT-BASELINE-1  →  S-GANTT-POLISH  →  S-GANTT-LOAD
   каскад          запас/float        план vs факт         шлифовка          перегруз
   (модуль)      (тот же модуль)      (первая миграция)     (опц. SS/FF)      (опционально)
```

Первые два спринта строят и переиспользуют один чистый модуль `gantt-schedule.ts` под vitest —
после них вся графовая математика Ганта лежит в одном тестируемом файле, а `GanttTimeline` остаётся
рендером. Это и есть главный архитектурный выигрыш волны, а не отдельные фичи.
