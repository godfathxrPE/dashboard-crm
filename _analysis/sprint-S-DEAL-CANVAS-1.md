## ЗАДАЧА 4 — пустая подсказка стадии перестаёт быть рамкой

**Файл:** `src/components/projects/ProjectStageCockpit.tsx`, компонент `StageGuidance`

Сейчас: у не-owner пустая подсказка не рендерится вовсе (правильно), **у owner** —
рендерится полноразмерная рамка `border + bg-surface2 + px-3 py-2` с заголовком
«ЧТО ДЕЛАЕМ НА СТАДИИ» и приглашением внутри. На карточке ненастроенной организации это
полоса во всю ширину полотна ради строки-приглашения.

**Требуется:** при `!text && canEdit` — вместо рамки тихая строка-кнопка, открывающая
тот же `InlineEdit`:

```tsx
  // Пустая подсказка у owner — приглашение, а не блок: рамка во всю ширину ради
  // одной фразы была полосой-пустышкой на каждой ненастроенной стадии.
  // Заполненная подсказка остаётся прежним блоком — у неё есть содержание.
  if (!text && canEdit) {
    return (
      <button
        type="button"
        onClick={() => setEditing(true)}
        className="inline-flex items-center gap-1.5 text-meta text-text-mute
                   transition-colors hover:text-accent"
      >
        <Lightbulb size={12} aria-hidden />
        Добавить подсказку для стадии «{stageName}»
      </button>
    );
  }
```

Раскрытие по клику реализовать **минимально**: локальный `useState` `editing`; при `editing`
рендерить существующий блок с `InlineEdit` (тот же `key={stageId}`, тот же `onSave`),
после успешного сохранения `setEditing(false)`. Ветку «текст есть» не трогать вообще.

**Инварианты, которые нельзя нарушить:**
- `if (!text && !canEdit) return null` — остаётся первой строкой, до новой ветки.
- `key={stageId}` у `InlineEdit` остаётся: без него черновик предыдущей стадии утекает в следующую.
- Ошибка сохранения у не-owner (42501) по-прежнему уходит в `toast.error` из `onSave` родителя.
- Заполненная подсказка **не** становится кнопкой и не сворачивается.

**Проверка:** на стадии без подсказки под строкой кокпита — одна тихая строка со значком
лампочки; клик открывает редактор; после сохранения появляется прежний блок с текстом.

## ЗАДАЧА 5 — мера строки в ленте активности

**Файл:** `src/components/shared/EntityTimeline.tsx`

На контейнере тела события (`className="min-w-0 flex-1 text-left"`, ~строка 304) добавить
ограничитель меры строки:

```
min-w-0 flex-1 text-left max-w-[80ch]
```

**Почему:** после задачи 2 полотно упирается в 1440, но лента всё ещё занимает его целиком;
80ch — верх нормы 45–90 знаков. `max-w-[80ch]` — не хардкод цвета и не magic number палитры,
`audit-tokens.py` его не ловит.

**Не трогать** заголовки событий, метаданные (`автор · дата`) и композер — только тело.
