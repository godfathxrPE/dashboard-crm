# Claude Code Prompt — fix-S-NOTES-2.2-tables-gate-2: пустые колонки вместо правила «ячейка-картинка»

Та же ветка `feat/notes-2-2`, тот же worktree, поверх `ee48e19`. Отдельный коммит.

## Решение гейта по риску из отчёта

Правило «ячейка с `img` без текста → вёрстка» ловит подпись письма, но ломает каталог с колонкой
фото: вся таблица уходит текстом. Заменить его общим правилом: **колонка, где у всех ячеек нет
текста, выбрасывается**. После этого:
- подпись (логотип | имя и телефон) — колонка логотипа пустая → выброшена → осталась одна колонка →
  вёрстка по существующему правилу `≤ 1 колонки`;
- каталог (фото | товар | цена) — колонка фото выброшена → GFM из двух колонок;
- таблица Outlook с пустыми колонками-отступами — отступы выброшены, данные остались.

Картинки в `notes.body` всё равно не хранятся, так что пустая колонка ничего не теряет.

## ЗАДАЧА: сетка таблицы один раз, пустые колонки, проверка по сетке

### Steps
`src/lib/text/html-to-markdown.ts`:
1. Вынести из `tableToGfm` построение сетки: `tableGrid(rows, ctx): string[][]`. Текст ячейки,
   `colspan`, экранирование `|`, отброс пустых строк, дополнение строк до общей ширины — как сейчас.
2. `dropEmptyColumns(grid): string[][]` — выбросить колонки, где все ячейки (включая первую строку)
   пустые.
3. `isLayoutTable` получает уже очищенную сетку для проверки числа колонок (`≤ 1` → вёрстка) и
   длины ячеек (> 300 → вёрстка). Признаки по DOM — `role`, вложенная таблица, `ul/ol/h*/blockquote`
   в ячейке — остаются как есть. Правило «ячейка с `img` и пустым текстом» удалить.
4. `tableToGfm` принимает очищенную сетку и только печатает GFM.
5. В вёрстке (ветка `isLayoutTable`) обход ячеек через `walk` не меняется: он идёт по DOM, а не
   по сетке.

Сетку строить один раз на таблицу: и для проверки, и для вывода.
