## КЛЮЧЕВЫЕ РЕШЕНИЯ (принять как есть)

1. **Сущность берётся ТОЛЬКО из чипа, никогда из текста.** «Ориент» в строке может
   значить «Ориент Продактс», «Пресейл Ориент» или ничего. Чип из 1e — уже
   провалидированная ссылка с id. Нет чипа в сообщении — задача создаётся без привязки,
   и в карточке подтверждения это видно явно («без привязки»).
2. **Задача НИКОГДА не создаётся молча.** Любой путь заканчивается карточкой
   подтверждения с разобранными полями и кнопками «Создать» / «Отмена». Ложная задача из
   болтовни дискредитирует фичу быстрее, чем её отсутствие.
3. **Два входа, один код:**
   - **слэш-команда в композере**: `/задача` — превращает набранный текст в черновик;
   - **действие на существующем сообщении**: иконка «в задачу» в ховер-контролах
     (рядом с реакцией/правкой) — разбирает тело этого сообщения.
   Оба ведут в одну функцию разбора и одну карточку подтверждения.
4. **Парсер дат — чистая функция с тестами, без библиотек.** Дата-fns/dayjs в проект не
   тащим ради одного разбора. Поддержать ровно то, что реально пишут:
   `3 августа`, `3 августа в 15:00`, `03.08`, `03.08 15:00`, `сегодня`, `завтра`,
   `послезавтра`, `в понедельник`, `через 2 дня`, `через неделю`, время `в 15:00` / `15:00`
   отдельно. Без года — ближайшая будущая дата. Без времени — конец дня по МСК
   (`mskEndOfDayIso`, конвенция проекта: дедлайн «сегодня» = конец дня, иначе задача
   просрочена через секунду). Всё считать в **МСК**, не в локали браузера.
5. **`source_message_id` — обратная ссылка, и она же ключ идемпотентности.** Одно
   сообщение → максимум одна задача: `unique` на колонке (partial, где not null).
   Повторный клик по «в задачу» на том же сообщении показывает существующую задачу,
   а не плодит вторую.
6. **Исполнитель по умолчанию — автор сообщения**, не тот, кто нажал. Если Иван написал
   «нужно позвонить», задача его. Менять в карточке подтверждения можно (селект команды
   уже есть — `useTeamMembers`).

## ЗАДАЧА 1 — Миграция `099_task_from_message.sql` (НЕ применять!)

```sql
alter table public.tasks
  add column if not exists source_message_id uuid
  references public.messages(id) on delete set null;

create unique index if not exists uq_tasks_source_message
  on public.tasks(source_message_id) where source_message_id is not null;

create index if not exists idx_tasks_source_message
  on public.tasks(source_message_id);
```
`on delete set null`, НЕ cascade: удалили сообщение — задача остаётся, теряется только
ссылка на источник (конвенция проекта для FK-связей, 040). Partial unique — ключ
идемпотентности из решения 5.

В шапке: зачем, что `source_message_id` заполняется только этим путём, откат
(drop index ×2, drop column).

## ЗАДАЧА 2 — Парсер (`src/lib/utils/task-intent.ts`, чистый, с тестами)

```ts
export interface TaskIntent {
  text: string;              // очищенный текст задачи (без даты и триггер-фразы)
  deadline: string | null;   // ISO UTC, посчитан в МСК
  matchedDatePhrase: string | null;  // что именно распознали — показать в карточке
}
export function parseTaskIntent(body: string, now?: Date): TaskIntent
```
- `now` параметром — иначе функция нетестируема (грабля: `Date.now()` внутри чистой
  функции). Дефолт `new Date()`.
- Месяцы русские в родительном (`января`…`декабря`), день 1–31, время `HH:MM` / `HH.MM` /
  «в 15», `15 часов`.
- Триггер-фразы (`поставить задачу`, `создать задачу`, `задача:`, `todo:`) — вырезаются из
  текста, но **сами по себе задачу не создают**: они лишь подсказка парсеру и подсветка в
  композере. Создаёт — явное действие пользователя (решение 2).
- Дата вырезается из текста задачи: «звонок 3 августа в 15:00» → text «звонок».
  Если после вырезания текст пуст — вернуть исходный без вырезания (лучше лишнее слово,
  чем задача без названия).
- **Тесты обязательны** и включают: все поддержанные формы, `31 февраля` (невалидная дата
  → `deadline: null`, текст цел), `25:00` (не время), дата в прошлом без года → следующий
  год, пустая строка, текст вообще без даты.

## ЗАДАЧА 3 — Карточка подтверждения (`TaskFromMessageCard.tsx`)

Инлайн-панель в треде (НЕ модалка — контекст сообщения должен оставаться на экране).
Поля, все редактируемые до создания:
- текст задачи (input, префилл из парсера);
- срок (`datetime-local` через `isoToDatetimeLocal`/`datetimeLocalToIso`; пусто — без срока);
- привязка: чип сущности из сообщения — сделка/проект показать по имени
  (`useEntityTitles` из 1e), компания/контакт — тоже. Несколько чипов → селект «к чему
  привязать», первый по умолчанию. Нет чипов → «без привязки»;
- исполнитель (`useTeamMembers`, дефолт — автор сообщения, решение 6);
- приоритет — не показываем, дефолт `normal` (лишнее поле в быстром сценарии).
Кнопки «Создать» / «Отмена». После создания — тост со ссылкой на задачу и сворачивание
карточки.

Маппинг в `useCreateTask`: `text`, `deadline`, `assigned_to`, `source_message_id`,
и **одна** из связей по типу чипа: `deal`/`project` → `project_id`, `company` →
`company_id`, `contact` → `contact_id`. `column_id` НЕ передавать (резолвит триггер).

## ЗАДАЧА 4 — Точки входа

- **Ховер-контролы сообщения**: иконка `ListPlus` рядом с реакцией. Видна всем, кто видит
  сообщение (задачу можно поставить и по чужому сообщению — это нормальный рабочий
  сценарий). Если у сообщения уже есть задача (`source_message_id`) — иконка меняется на
  «задача создана» со ссылкой; для этого нужен лёгкий хук
  `useTasksBySourceMessages(messageIds)` — одна выборка на ленту, как реакции и вложения.
- **Слэш-команда**: набранный в композере текст, начинающийся с `/задача ` — вместо
  отправки открывает карточку подтверждения с разбором остатка строки. Автокомплит команд
  НЕ делаем (одна команда), но покажи подсказку под композером при вводе `/`.

## EDGE CASES

- Пустой чат-драфт с `/задача` без текста — подсказка, не карточка.
- Сообщение уже имеет задачу → повторный клик ведёт к ней (решение 5), не открывает форму.
- Задача из temp-сообщения (ещё не сохранено) — иконку не показывать.
- Удалённое сообщение: `source_message_id` → NULL, задача жива (проверить, что список
  задач это переживает).
- Чип на сущность, невидимую по RLS — привязку не предлагать (у `useEntityTitles` пусто).
- Разница часовых поясов: пользователь пишет «в 15:00», подразумевая МСК — считаем в МСК
  всегда, в карточке показываем «15:00 МСК» явно.
