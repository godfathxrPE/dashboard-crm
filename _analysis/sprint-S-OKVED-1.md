# Claude Code Prompt — S-OKVED-1: отрасль компании из ОКВЭД (без AI)

Фича: тот же клик «Заполнить по ИНН» дополнительно подставляет **отрасль** — из кода
ОКВЭД, который DaData уже возвращает в ответе `findById/party`, а мы его выбрасываем.
Ноль новых провайдеров, ноль стоимости за вызов, детерминированный результат.

Ветка: `feat/okved-industry` от свежего `main` (S-INN-1 смержен).

**Разведка гейта (2026-08-03, живая БД):** 261 компания, 225 с ИНН, **245 без отрасли**
(209 из них — с ИНН: это и есть аудитория фичи). Заполненные `industry` сейчас: «Электроника» ×9,
«Производство» ×1, одно полное название ОКВЭД и **5 записей с голыми кодами** (`10.13`,
`10.13.2`, `10.13.4`, `10.26.12`). Единого словаря отраслей в проекте нет — формат задаём здесь.
Существующие значения **не мигрировать и не чинить** (см. «ЧЕГО НЕ ДЕЛАТЬ»).

**Инвариант спринта:** `okved` — факт реестра, `industry` — рабочая классификация.
Разные колонки. Код в поле «Отрасль» не писать никогда: `industry` рендерится в таблице
компаний, в CommandPalette (`sub`) и уезжает в CSV-экспорт — там нужен текст для человека.

## ЗАДАЧА 1 — миграция 103: `companies.okved`

Файл `supabase/migrations/103_company_okved.sql` (номер сверить разведкой п.1).
Шапка в стиле проекта: ЗАЧЕМ → ЧТО ЗДЕСЬ → ⚠️ → Откат. Статус применения в шапку
**не писать** — он живёт в `docs/schema.md` (конвенция с S-INN-1).

```sql
alter table public.companies
  add column if not exists okved text;

comment on column public.companies.okved is
  'Основной код ОКВЭД-2 из ЕГРЮЛ (data.okved DaData). Факт реестра: заполняется только
   lookup-ом, руками не редактируется. Человеческая отрасль — в industry.';
```

- Одна колонка, без индекса: по ОКВЭД пока не фильтруют и не группируют. Индекс заведём,

- Название ОКВЭД в БД **не дублируем**: DaData отдаёт только код, название приходит из
  локального справочника (Задача 2). Дублировать словарь в данных — гарантированный
  рассинхрон при первой же правке справочника.
- RLS не трогаем: колонка в уже защищённой таблице.

**Типы:** колонка новая ⇒ нужен реген. По конвенции проекта CC реген не делает — завести
стаб-интерсекцию в `src/types/database.ts` **по образцу `CompanyLegalFieldsStub` из S-INN-1**
(тот блок гейт уже снял — смотреть в `git show` предыдущего коммита, не в текущем файле):
`type CompanyOkvedStub = { companies: { Row: { okved: string | null }, Insert: {...}, Update: {...} } }`
плюс `& CompanyOkvedStub` в `Database`. Снятие стаба — работа гейта.

## ЗАДАЧА 2 — справочник ОКВЭД → отрасль

Новый файл `src/lib/data/okved.ts`. Чистый модуль без импортов (как `normalize.ts`) —
чтобы покрывался юнит-тестами.

Двухуровневая схема: **раздел** ОКВЭД-2 даёт базовую отрасль, **класс** переопределяет её
там, где это важно для маркировки (профиль клиентов Первого Бита — товарные группы ЧЗ).

`''`/`null`/`'ИНН'` → null, `'01'` → «Сельское и лесное хозяйство».

## ЗАДАЧА 3 — normalize.ts: достать ОКВЭД (+ контакты, если реестр их отдаёт)

В `CompanyLookupResult` добавить три поля, извлечь тем же `pick`/`str`:

```ts
  /** data.okved — основной код ОКВЭД-2. Идёт в companies.okved как есть. */
  okved: string | null;
  /** data.phones[].value — у тарифа «Подсказки» обычно пусто. Пустой массив, не null. */
  phones: string[];
  /** data.emails[].value — там же. */
  emails: string[];
```

`phones`/`emails` в ответе DaData — массивы объектов с полем `value`; сужать через
`Array.isArray` + `str(item.value)` + отброс `null`. **Обновить `NOT_FOUND`** (`okved: null`,
пустые массивы) и ветку «подсказка без `data`».

⚠️ Честно: в тарифе «Подсказки» контакты почти наверняка приходят пустыми — извлечение
пишем tolerant-кодом (~15 строк), а факт проверит гейт первым живым вызовом. Гадать,
есть они или нет, дороже, чем написать код, корректный в обоих случаях.

Тесты `company-lookup-normalize.test.ts` дополнить: ОКВЭД извлекается; отсутствие
`okved`/`phones`/`emails` в payload не роняет нормализацию и даёт `null`/`[]`.

## ЗАДАЧА 4 — клиент: подстановка отрасли

`use-company-lookup.ts` — зеркало интерфейса обновить (три новых поля).

Валидатор `company.ts`: `okved: z.string().nullable().default(null)`.

`CompanyModal.handleLookup` — дописать в существующий блок, **не переписывая его**:

- `setValue('okved', r.okved, { shouldDirty: true })` — всегда: это факт реестра.
- `industry` — **только если поле пустое** (та же логика, что у `name`):
  ```ts
  const industry = okvedToIndustry(r.okved);
  if (industry && !getValues('industry')?.trim()) {
    setValue('industry', industry, { shouldDirty: true });
  }
  ```
  Отрасль, проставленная менеджером руками, важнее выведенной из реестра — он видел
  клиента, а справочник видел две цифры.
- `email` — только в пустое поле, из `r.emails[0]`.
- `phones` — только если список телефонов формы пуст: `r.phones.map(v => ({ type: 'work', value: v, is_primary: false }))`,
  первому проставить `is_primary: true`. Нормализация уже есть в `onSubmit`.
- Тост: если подставилась отрасль — дописать в текст `· Отрасль: <industry>`, чтобы
  подстановка не была молчаливой.

Поле ОКВЭД в форме **не показывать** — это служебный код. Его место на карточке (Задача 5).
