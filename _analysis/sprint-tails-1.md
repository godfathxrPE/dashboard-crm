## ЗАДАЧА 3 — Off-by-one в просрочке сделки

**Дефект живёт в проде.** `getNextActionOverdueDays` (`src/lib/utils/deal-health.ts:85`)
сравнивает **локальную полночь сегодня** с **UTC-полуночью** `date`-колонки
`next_action_date`. В MSK (UTC+3) разница теряет три часа, и `floor` съедает сутки.

Проверено экспериментом на гейте (`TZ=Europe/Moscow`, сегодня 2026-08-10):

| Дата шага | Функция говорит | Правда |
|---|---|---|
| 2026-08-09 (вчера) | **0 дн.** | 1 дн. |
| 2026-08-08 | 1 дн. | 2 дн. |
| 2026-08-03 (неделя) | 6 дн. | 7 дн. |

То есть менеджер видит «просрочен 0 дн.» на сделке, которую просрочил вчера.
У лида это уже исправлено в 2b — `getLeadActionOverdueDays` считает через
`diffDaysKey` (нормализация на UTC-полдне, устойчиво к DST).

**Правка.** `deal-health.ts`:

```ts
import { diffDaysKey, localDateKey } from '@/lib/utils/date-helpers';

export function getNextActionOverdueDays(nextActionDate: string, now: Date = new Date()): number {
  return Math.max(0, diffDaysKey(nextActionDate, localDateKey(now)));
}
```

⚠️ `now` параметром с дефолтом — обязательно: без него функция недетерминирована и
её нельзя протестировать (ровно та же правка, что понадобилась `leadStaleness` в 2b,
когда выяснилось, что она читала `Date.now()` мимо переданного времени).

**Потребители — пройти по всем, их три:**

```bash
grep -rn "getNextActionOverdueDays" src/
```

Ожидаются `DealFocusPanel.tsx`, `TodayView.tsx` (секция «Сделки без шага») и,
возможно, фильтры/сегменты. Ни в одном не менять текст — меняется только число.

⚠️ **`getDealHealth` в той же функции НЕ трогать.** Она сравнивает
`new Date(project.next_action_date) < today` — знак сравнения от смещения не
страдает (граница суток сдвинута одинаково у обеих дат), а вот `floor` деления
страдал. Расширять правку на `getDealHealth` без своего смока — это менять условие
попадания сделки в очередь дня, чего задача не просит.

**Тест** `tests/unit/deal-health.test.ts` (создать, если нет): вчерашняя дата → 1,
недельная → 7, сегодняшняя → 0, завтрашняя → 0. Прогонять с фиксированным `now`,
не с системным временем.
