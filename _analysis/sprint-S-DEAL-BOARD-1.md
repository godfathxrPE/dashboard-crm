## ФАКТЫ, на которых держится спринт

**Ф1. `ProjectBoard` и `TaskCard` общие.** `ProjectBoard` рендерят сделка
(`ProjectBoardSection.tsx:61`) и проект-внедрение (`ProjectDetail.tsx:385`) — у внедрения
колонки самописные, их бывает больше четырёх, и переименование там нужно. `TaskCard`
рендерят `ProjectBoard`, `LaneColumn`, `AccordionLane`. **Поэтому новый вид — вариантом,
который включает только сделка.** Поведение по умолчанию не меняется ни на байт.

**Ф2. `cn()` выкидывает проектные кегли — и это делает задачи крупными.** `cn` — голый
`twMerge`; `text-body`/`text-meta` из `tailwind.config` он считает цветом и выкидывает рядом
с `text-text-*`. `TaskCard.tsx:127`: `cn('text-body leading-[1.4] text-text-main', …)` —
`text-body` (13px) выпадает, текст задачи наследует кегль родителя. На живом экране задачи
крупнее спеки именно поэтому. Это долг G-1 из ревизии 52, десять мест в `main` — ЗАДАЧА 0.

**Ф3. Колонки шире зоны.** `w-72 shrink-0` у колонки + `flex gap-3 overflow-x-auto` у ряда
(`ProjectBoard.tsx:387`): 4 × 288px + зазоры не влезают, «Готово» обрезана скроллом.

**Ф4. Под именем колонки — то же имя капсом.** `CATEGORY_LABEL[column.category]`
(`ProjectBoard.tsx`, заголовок колонки). Для самописных колонок внедрения («Дизайн» с
категорией «В работе») подпись полезна; в сделке имена колонок совпадают с категориями —
получается «Бэклог / БЭКЛОГ».

**Ф5. Приоритет вне Aura — палка сбоку.** `border-l-[3px] border-yellow` / `border-red` у
`important`/`critical`. Боковую полосу-маркер владелец отверг 09.09 («никакой сайдмаркера»).
Спека кодирует приоритет словом: «· важно».

**Ф6. Чип на карточке — имя самой сделки.** В сделке у задачи есть `project_id`, и `TaskCard`
печатает чип `task.project.name` — на карточке сделки «Лоренц снек» на каждой задаче
«Лоренц снек». Один факт, повторённый N раз.

**Ф7. Исполнителя в запросе нет.** `useProjectBoard` тянет
`*, project:projects(id, name, type), company:companies(id, name)` (`use-tasks.ts:104`).
FK `tasks_assigned_to_fkey → profiles`, в `profiles` есть `full_name`. Замер 24.09: в сделках
25 задач, у 14 задан исполнитель, исполнителей двое.

**Ф8. Приоритет — enum `normal | important | critical`** (`types/database.ts:631`).
Категории колонок — `backlog | started | paused | done | phase`.

## Отступления от спеки — решения гейта

**О1. Чекбокс остаётся.** Спека его не рисует, но это единственный способ закрыть задачу
без перетаскивания в «Готово». Убрать — регресс функции. Стоит слева в карточке, как сейчас.

**О2. Приоритет двумя словами, а не одним.** Спека знает одно «· важно». В данных два уровня:
`important` → «· важно» (`text-warning-text`), `critical` → «· срочно» (`text-danger-text`).

**О3. Инициалы исполнителя — только если исполнитель задан.** Спека печатает автора справа
всегда. Автор у всех задач один (замер: `distinct created_by = 1`) — инициалы на каждой
карточке ничего бы не различали. Исполнитель различает: его и печатаем, пусто — ничего.

**О4. Управление колонкой (карандаш, корзина) не удаляется, а прячется.** Спека его не
рисует; убрать совсем — сделка теряет переименование колонок. Проявляется на `hover` и
`focus-within` колонки. «+ колонка» в варианте сделки не рендерится.

**О5. Колонок может быть больше четырёх.** Спека — `grid 4 × 1fr`. Сетка —
`repeat(N, minmax(0, 1fr))` по фактическому числу колонок; при N > 4 — `minmax(12rem, 1fr)`
и горизонтальный скролл как запасной выход. Для сделки по умолчанию N = 4.

## ЗАДАЧА 0 — `cn()` знает проектные кегли (долг G-1)

`src/lib/utils/cn.ts`: `twMerge` → `extendTailwindMerge` (tailwind-merge 2.6):

```ts
const twMerge = extendTailwindMerge({
  extend: { classGroups: { 'font-size': [{ text: ['meta', 'body'] }] } },
});
```

Тест `tests/unit/cn.test.ts` (vitest собирает только `tests/unit/**`):
- `cn('text-meta', 'text-text-dim')` сохраняет оба класса;
- `cn('text-body text-text-main')` сохраняет оба;
- `cn('text-meta', 'text-body')` оставляет последний — конфликт кеглей по-прежнему решается;
- `cn('text-text-dim', 'text-text-mute')` оставляет последний — цвет по-прежнему решается.

⚠️ **У фикса видимый эффект на десяти местах**, кегли вернутся к задуманным:
`PipelineCockpit:163`, `LeadDetail:112`, `DealSignals:188`, `ChecklistCard:117`,
`ContactDetailHub:74` и `:431`, `TaskCard:127`, `BoardCard:144`, плюс два в
`DealStakeholders` (#111 обошёл их склейкой вне `cn`). Обходы в `CopyButton` и
`DealStakeholders` после фикса можно оставить — они не мешают; переписывать их не надо.

## ЗАДАЧА 1 — `ProjectBoard` получает вариант сделки

Проп `variant?: 'default' | 'deal'`, по умолчанию `'default'`. `ProjectBoardSection`
передаёт `variant="deal"`. Всё ниже — только при `'deal'`.

1.1 **Ряд колонок** — `grid` вместо `flex overflow-x-auto`: `repeat(N, minmax(0, 1fr))`,
    при N > 4 — `minmax(12rem, 1fr)` + `overflow-x-auto` (О5). Зазор — ноль: колонки делит
    линия, не пустота.

1.2 **Колонка без подложки.** Нет `bg-surface2`, нет рамки, нет скругления. Слева — `border-l
    border-border` у всех, кроме первой. Внутренние отступы по горизонтали — как в спеке
    (`p0 12` → `px-3`). Минимальная высота — спека 230px → в rem.

1.3 **Заголовок колонки:** точка 8px цвета категории + имя + счётчик. Подписи категории
    капсом НЕТ (Ф4). Точка — семантический токен, не акцент:

| Категория | Точка |
|---|---|
| `backlog` | `bg-border2` |
| `started` | `bg-success` |
| `paused` | `bg-warning` |
| `done` | `bg-text-main` |
| `phase` | как `backlog` (в сделке фаз нет, но тип допускает) |

1.4 **Управление колонкой** — карандаш и корзина на `hover`/`focus-within` колонки (О4).
    Редактирование имени и удаление работают как сейчас. «+ колонка» не рендерится.

1.5 **Пустая колонка** — без «Пусто». Только «+ Добавить», прижатое книзу колонки
    (`mt-auto`). Зона дропа при этом остаётся на всю высоту колонки — DnD в пустую колонку
    обязан работать.

1.6 **Колонка передаёт карточке свою категорию** — нужна для «ждём до» (ЗАДАЧА 3).

## ЗАДАЧА 2 — `TaskCard` получает вариант-фигуру

Проп `variant?: 'row' | 'block'`, по умолчанию `'row'` (всё как сейчас). Колонка сделки
рендерит `variant="block"`. Всё ниже — только при `'block'`.

2.1 **Карточка — одна фигура:** рамка `border-border`, скругление — `rounded-xl`

    карточками в колонке — спека `gap 6` → `gap-1.5`. Наведение — рамка темнеет
    (`hover:border-border2`), фон не меняется.

2.2 **Никакой полосы приоритета** (Ф5, решение владельца 09.09). Приоритет — словом в мете (О2).

2.3 **Чип проекта/компании НЕ рендерится** (Ф6).

2.4 **Строка меты** (спека: «точка 6 + дедлайн (цвет по статусу) · важно · ml-auto автор»):
    точка 6px + срок словом из ЗАДАЧИ 3 · приоритет (О2) · справа инициалы исполнителя (О3).
    Нет дедлайна, приоритета и исполнителя — строки меты нет вовсе.

2.5 **Готово** — `line-through` + прозрачность 0.6 (спека), вместо нынешних 0.45.

2.6 Чекбокс (О1), hover-действия (перенести на завтра, редактировать, удалить) и DnD —
    без изменений.

2.7 **Исполнитель в запросе:** `useProjectBoard` — добавить

## ЗАДАЧА 3 — состояние срока: чистая функция вместо `Date.now()` в компоненте

`deadlineUrgency` в `TaskCard.tsx` зовёт `Date.now()` внутри — против конвенции проекта
(время аргументом). Вынести в `src/lib/domain/task-deadline-state.ts`:

```ts
export type TaskDeadlineState = 'overdue' | 'today' | 'waiting' | 'ahead' | 'done' | 'none';
export function taskDeadlineState(
  deadline: string | null, lane: string, category: ColumnCategory | null, now: Date,
): { state: TaskDeadlineState; label: string };
```

| Условие | state | Подпись | Цвет |
|---|---|---|---|
| нет дедлайна | `none` | — | — |
| `lane = done` | `done` | дата | `text-text-mute` |
| срок прошёл | `overdue` | «просрочено · 3 сент» | `text-danger-text` |
| срок сегодня | `today` | «сегодня» | `text-success-text` |
| колонка `paused` | `waiting` | «ждём до 15 сент» | `text-warning-text` |
| иначе | `ahead` | «9 сент» | `text-text-mute` |

Порядок проверок — как в таблице: просрочка важнее «ждём». Дни считать по локальной дате,
а не по разнице миллисекунд (задача с дедлайном в 23:00 сегодня — «сегодня», не «завтра»).
Существующий `deadlineUrgency` для варианта `'row'` оставить как есть — раздел «Задачи»
не трогаем; новая функция нужна только `'block'`.

Цвет точки меты — тот же токен, что у подписи.
