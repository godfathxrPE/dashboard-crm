## С чем согласен полностью

### 1. Дыра реальна и важнее визуалов очереди

132 сделала `rejection_reason` обязательной при `rejected`, чтобы собирать срез «почему проигрываем». Срез сейчас собирается только SQL'ем. Learnings уже записали правило: «констрейнт на поле, которого не видно в UI, защищает данные впустую». Спринт закрывает ровно эту дыру, не раздувая скоуп.

### 2. Запрос менять не надо

Поле в `QUOTE_COLS` с момента apply 131 / регена типов (#84). `Quote` = Row, колонка в gen-типах есть. Второй SELECT был бы ложной работой.

### 3. Тон причины — факт, не тревога

Статус слева уже `text-red` + глиф `✕`. Второй `text-danger-text` под ним удваивает сигнал. `text-text-dim` + подпись «Причина:» — правильная иерархия. Пустой «Причина:» без текста не рисовать — то же правило, что у «Ждём».

### 4. Гард срока — положительный

«Показываем у `draft`/`sent`» переживает шестой статус. Перечисление `accepted|rejected|expired` — тот же класс, что два литерала `won`/`lost`, которые ORG-2 уже вынес из этого файла в `useIsProjectActive`. `quoteValidity` остаётся чистой: `expired` в БД из неё не пишется намеренно.

### 5. Дата в списке остаётся

Врал янтарный «действует ещё N дн.» в карточке, не сам факт «до {дата}» нейтральным `text-meta text-text-mute`. Менять список по сроку — размытие дефекта.

### 6. Тестов нет — честно

Новой функции в `src/lib/` нет. Выносить `shouldShowValidity(status)` ради двух строк — хуже, чем условие в JSX. `quote-validity` и `quote-version` уже покрыты.

## Предупреждения (желательно исправить)

### W1. Три опциональных куска в строке списка — не копировать текущий if-chain

Сейчас разделитель рисуется только при `valid_until && notes` (`QuotesTab.tsx:165–167`). Порядок «срок → причина → notes» даёт семь комбинаций (любой из трёх может отсутствовать). Наивный третий `&&` пропустит `·` между причиной и заметкой, когда даты нет, и склеит «дорогодо 12 сен».

В HOW: собрать массив присутствующих кусков и `join(' · ')`, `title` — на этот же `div.flex-1.truncate` (это и есть «строка» спринта, не весь `<li>`).

### W2. Смок «причина видна в карточке» держится на правиле активного КП

`pickActiveQuote`: `accepted` → последнее `sent` → последнее любое (`quote-version.ts:64–73`). После отклонения единственного `sent` карточка остаётся на нём (последнее любое) — смок спринта проходит. Если на сделке есть более свежий `draft` или другой `sent`, карточка уедет на него, и причина останется только в списке. Это не дыра задачи 1: карточка про «что на столе», список про историю.

Смок гнать на сделке с одним `sent` (или rejected = последнее любое). `pickActiveQuote` / `quote-version.ts` **не трогать**.

### W3. Задача 3 оставляет развилку исполнителю

«дату нейтральным тоном („срок был до {дата}“) либо не печатать ничего». Жёсткий инвариант один: у `accepted`/`rejected`/`expired` нет янтаря и слова «действует». Сюда же попадают ветки «истекло» (`text-danger-text`) и «срок не задан» — положительное условие `draft|sent` их тоже снимает.

Рекомендация в HOW, чтобы не гадать: **у не-draft/sent блок справа не печатать**. «Срок был до» на принятом КП читается как реквизит, но статус уже несёт исход, а дата остаётся в списке. Если всё же печатать дату — только `formatCalendarDate` (`valid_until` — колонка `date`, карточка уже так делает на `:147`). `formatDateNumeric` / `formatDateShort` на этой колонке уедут на сутки в минусовых зонах (learnings, S-DEAL-CHZ-1). Список по-прежнему на `formatDateShort` — **не унифицировать** в этом спринте.

### W4. Нет блока «ЖЁСТКО НЕ ТРОГАТЬ» — границы размазаны по задачам

Исполнитель-максималист легко «дорисует» причину в `QuoteModal` (формы там нет, `quoteFormSchema` поле не знает — ORG-2 так и задумал: отклонение только через карточку) или подкрутит `quoteValidity`. В HOW явно:

- `quoteValidity` / `quote-validity.ts` / его тесты
- `QUOTE_COLS`, хуки, типы, `quoteFormSchema`
- `QuoteModal` (зануление на выходе из `rejected` уже верное)
- `pickActiveQuote` / `quote-version.ts`
- `quoteStatuses` / `QUOTE_STATUS_CONFIG` / `QUOTE_STATUS_TRANSITIONS`
- свёртка `DealOrgBlock` (`КП vN · Отклонено` — без причины, так и надо)
- миграции, `docs/schema.md`
