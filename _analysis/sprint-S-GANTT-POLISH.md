## ЗАДАЧА 1 — Undo последнего сдвига дат

Сейчас любой драг применяется сразу, откат — только ручной драг назад. После
S-SCHEDULE-1B цена ошибки выросла: одно подтверждение двигает десяток задач.

### Что уже есть в коде — читать до реализации

- `commitDates` (GanttTimeline.tsx ~L715) = `updateDates.mutate(...)`, в `onSuccess`
  вызывает `proposeCascade(v.id)`.
- `proposeCascade` (~L687) **не применяет каскад молча**: показывает тост
  `Сдвинуть N задач?` с `action: { label: 'Сдвинуть' }` и `duration: 12_000`,
  пересчитывая shifts по свежему `scheduleRef` уже на клике.
- `useShiftTasks` (use-tasks.ts L396) — батч через `Promise.allSettled`,
  `meta: { silentError: true }`, тостит сам: `failed === 0` → success,
  иначе `Сдвинуто X из N — остальные отклонены (нет прав)`.

### Ruling 1 — не плодить второй тост, использовать `cancel`

Наивная реализация («тост успеха получает action: Отменить») ломается о то, что
после каждого драга уже висит тост-предложение каскада на 12 секунд. Два тоста
одновременно, про разное, с кнопками рядом — пользователь жмёт «Отменить», а
предложение каскада продолжает висеть и указывает на анкор, которого уже нет.

Sonner v2 даёт на один тост **и** `action`, **и** `cancel`. Использовать это:

```ts
toast(`Сдвинуть ${n} ${pluralDependent(n)}?`, {
  duration: 12_000,
  action: { label: 'Сдвинуть', onClick: () => { /* существующий каскад */ } },
  cancel: { label: 'Вернуть как было', onClick: () => undoLast() },
});
```

Когда зависимых нет (`shifts.length === 0`, сейчас — молчание), показывать
отдельный короткий тост только с `cancel`. Так тост на любое перемещение ровно один.

### Ruling 2 — undo каскада только при полном успехе

`useShiftTasks` не атомарен by design (см. комментарий над хуком). При
`failed > 0` обратный батч попытается «вернуть» и те строки, что не менялись,
и отрапортует об отмене того, чего не было. Undo вешать **только** в ветке
`failed === 0`. При частичном отказе — существующий error-тост без кнопок.

### Ruling 3 — chip из «Без дат» под undo не попадает

`useUpdateTaskDates` типизирован как `{ id: string; start_date: string; end_date: string }` —
**не nullable**. Драг chip'а из «Без дат» на таймлайн переводит задачу из
`null/null` в даты, и обратной операции этой мутацией не существует.

Варианта два, выбрать первый:

- **(принято)** Для undated-drag undo не предлагать вовсе. Ошибка дешёвая:
  задача видна на таймлайне, ручной возврат в «Без дат» и так есть в модалке.
- Расширять `useUpdateTaskDates` до nullable — это трогает мутацию, которой
  пользуется половина экранов, ради краевого случая. Не в этом спринте.

### Реализация

- Prev-значения собирать **явно**, до патча кеша: в `onMutate` `useShiftTasks`
  прочитать текущие `start_date`/`end_date` по id из кеша до `patchTaskCaches`
  и вернуть их в context рядом со `snapshots`. `snapshotTaskCaches` для этого
  не годится — это снимок для отката кеша, а не источник значений для записи в БД.
- Для одиночного драга prev берётся из `gt.start`/`gt.end` в замыкании обработчика
  до вызова `commitDates`.
- Хранить одно последнее действие в `useRef<UndoEntry | null>`, не в state:
  перерисовка на запись undo не нужна, а лишний рендер в драг-бёрсте — знакомая
  грабля этого файла.
- Обратный батч — через тот же `useShiftTasks`: оптимистик, обработка частичного
  отказа и инвалидация уже написаны, нового кода почти нет.
- Окно — одно действие. Живёт до следующего коммита дат, стек не нужен.

**Трудоёмкость:** ~3 ч (не 2 — из-за трёх ruling'ов выше). Риск низкий.

## ЗАДАЧА 2 — Типы связей SS / FF / SF

### Миграция НЕ нужна — и `pg_enum` тут ни при чём

`dep_type` объявлен в `048_task_dependencies.sql` L8 как

```sql
dep_type text not null default 'FS' check (dep_type in ('FS','SS','FF','SF'))
```

Это `text` + CHECK, **не** pg_enum. Запрос в `pg_enum` вернёт пустой результат —
и это не значит, что типов нет. Все четыре значения БД принимает уже сейчас,
миграция не требуется, спринт остаётся UI-only. Если нужно перепроверить —
смотреть `pg_constraint`, а не `pg_enum`.

### Объём работ честно

Это не «расширение семантики earliest в одном месте». `computeCpm` построен на
FS: forward pass берёт `EF(pred)` и двигает `ES(succ)`, backward — зеркально.
SS/FF/SF связывают **разные** концы:

```
FS: succ.start ≥ pred.end   + lag      (есть)
SS: succ.start ≥ pred.start + lag
FF: succ.end   ≥ pred.end   + lag
SF: succ.end   ≥ pred.start + lag
```

Ограничения на `end` (FF, SF) в forward pass не выражаются через один только ES:
для узла с FF-предшественником earliest finish задан напрямую, а start
восстанавливается вычитанием длительности. Это переписывание обоих проходов
`computeCpm` и правка `computeCascade`, а не добавление веток в одну функцию.

Три места расчёта (soft-warn 1a, каскад, CPM) обязаны остаться согласованными —
закон FS из CLAUDE.md распространяется на все четыре типа.

- Popover ребра: селект типа рядом с существующим редактором `lag_days`.
- **Хук придётся расширить.** Сейчас `useUpdateTaskDependency` (use-task-dependencies.ts
  L120) принимает `input: { id: string; lag_days: number }`, шлёт в `.update({ lag_days })`
  и патчит оптимистиком одно поле. Под селект типа нужно:
  `input: { id: string; lag_days?: number; dep_type?: DepType }`, сборка объекта апдейта
  только из переданных ключей, оптимистик — по обоим полям. `DepType` уже экспортируется
  из `@/types/database` и используется в `DependencyEdge`.
- Мутация — **строго** `dep_type` и `lag_days`, третьего поля не добавлять. Концы ребра
  через UPDATE менять нельзя: DAG-валидатор 048 стоит только на BEFORE INSERT
  (см. 062, уже зафиксировано в комментарии над хуком).
- Vitest на каждый тип, отдельно на forward и backward pass, в
  `tests/unit/gantt-schedule.test.ts`.
- Отрисовка: SS/FF меняют точки входа и выхода стрелки (левый край вместо правого).
  Эффект измерения рёбер правится аккуратно — сигнатура зависимостей эффекта
  уже была источником лупы дважды.

**Трудоёмкость:** ~10–14 ч. Риск **высокий** — трогает всю математику расписания
и единственный эффект, который в этом файле уже зацикливался.
Отдельный коммит, чтобы отреверить независимо от остальных задач.

## ЗАДАЧА 3 — Экспорт

### `window.print()` — основной путь, html2canvas — только с разрешения

`html2canvas` в `package.json` **отсутствует**. Правило репозитория: новые
зависимости — с явного разрешения, сначала спросить. Отдельно от этого
html2canvas плохо работает с `color-mix()` и современными цветовыми функциями,
а темы проекта построены на CSS-переменных — риск получить снимок в неправильных
цветах реален и вылезет только на прогоне.

Поэтому:

- **Делать:** печать через `window.print()` + `@media print`-стили на контейнере
  Ганта. Пользователь сам сохраняет в PDF, качество векторное, тема рендерится
  штатным движком, зависимостей ноль.
- В print-стилях: снять `overflow`, развернуть горизонт целиком, скрыть тулбар,
  фильтры и тумблер крит-пути, зафиксировать светлую тему (печать тёмной темы
  съедает тонер и читается плохо).
- **Не делать без отдельного «да»:** `npm i html2canvas`. Если PNG всё-таки
  понадобится — это отдельная задача с отдельным разрешением.

**Трудоёмкость:** ~2 ч. Риск низкий.

## ЗАДАЧА 4 — Навигация и читаемость

### Линия «сегодня» уже в коде — заново не писать

В `GanttTimeline.tsx` она есть и рисуется через `todayIdx`:

```tsx
{todayIdx !== -1 && (
  <div style={{ gridColumn: `${todayIdx + 1}` }} className="border-l border-accent" />
)}
```

`todayIdx` считается внутри `model` как `bucketIndexOf(mskDateKey(new Date()), zoom, buckets)`.
`mskDateKey` живёт в **`src/lib/utils/date-helpers.ts` (L88)**, в `gantt-schedule.ts`
MSK-хелпера нет и второй заводить не надо. Новый расчёт текущей даты не писать —
брать готовый `todayIdx` из `model`.

По линии допустима только доводка, и только если смоук её подтвердит: она уходит
под бары (z-index) или теряется на фоне сетки (толщина). Видна нормально — не трогать.

### Что действительно новое

- Кнопка «Сегодня» + автоскролл к текущей дате при первом рендере: сейчас
  таймлайн открывается на начале горизонта, на длинном проекте это пустое поле.
  Скролл — по тому же `todayIdx`, один раз при монтировании, не на каждое изменение
  модели, иначе позиция будет уезжать после каждого драга. При `todayIdx === -1`
  (сегодня вне горизонта проекта) кнопка disabled, а не скролл в никуда.
- Затенение выходных в зуме `day`: фон колонки через CSS-переменную темы.
  **Не** производственный календарь — праздники РФ вне скоупа.

**Трудоёмкость:** ~2,5 ч (линия уже есть). Риск низкий.
