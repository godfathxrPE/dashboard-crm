## С чем согласен полностью

### 1. Стартующая группа — носитель состояния, не бейдж

«Начнётся через три месяца» и «действует пять лет» — разный разговор. Рамка + подложка на `status === 'starting'`, тег «старт YYYY-MM» vs «обязательна с YYYY». Токены `--warning-l` / `--warning`, не `amber` из спеки и не `--accent` (`t-washi`). `audit-contrast.py` — правильный гейт: бледная подложка легко провалит текст.

### 2. Пункты 4 и 5 не брать

Ярлык «гипотеза по ОКВЭД» точнее спекового «проверить»: говорит, откуда данные. Скрытие не-IIoT — развилка Р-В карты, доменный вопрос. Спринт, который «заодно спрячет ERP», сломает контекст маркировки у половины воронки без решения владельца.

### 3. Подвал в одну строку

Сейчас дата снапшота — третья мысль (ещё и в `title` сирот). ОКВЭД уже в ответе хука и молчит. Спека: слева коды, справа «справочник YYYY-MM». Убрать дубль `SnapshotNote`.

### 4. Тестов нет, домен не менялся

`resolveChzProfile` и Т2 CHZ-1 не трогаем. Разметка и токены. Строка в спринте достаточна.

## Предупреждения (желательно исправить)

### W1. Задача 2 почти закрыта; дыра — одна starting-группа без `note`

Карточка `note` уже показывает. Писать второй абзац не нужно. Разведка должна ответить числом: **14 групп с note, 6 starting, 1 starting без note** — «Мука, макароны, мёд» (`since: '2026-09'`).

Это дефект данных справочника, как спринт и сказал. В этом же PR дописать `note` (волна/ассортимент — только из тех же источников шапки файла, не «по памяти»). Зеркало `supabase/functions/ai-run/chz-groups.ts` править синхронно — тест `chz-groups.test.ts` сравнивает экспорты. Не заполнять из головы датой «ну наверное 2026-09».

Если сверка с источником за спринт не влезает — пустую группу оставить, в отчёте строка «Мука без note, не выдумывал». Не блокирует подложку.

### W2. Постер спеки не получит янтарную подложку

Макет рисует «Медицинские изделия / старт 2026-09 / волна 2.0» как starting. Справочник считает группу **действующей с 2023**, волна 2.0 — в `note`. Подложка пойдёт на кондитерку / чай-кофе / радиоэлектронику / мясо / муку. Это не баг спринта: статус в словаре не пересматривать здесь (актуализация справочника — out-of-scope CHZ-1). В отчёте: «пример спеки в данных — mandatory, подложку получит status=starting».

Не мапить подложку по `since` в будущем: сломает «обязательна с 2023» с примечанием про новую волну.

### W3. Имя хука после SUMMARY-1

Карта: SUMMARY (№3) → CHZ-2 (№4). SUMMARY переименовывает `useCompanyChz` → `useCompanyCard` и ключ в `['company-card']`. Спринт уже пишет «`useCompanyCard`/`use-company-chz`» — хорошо.

Разведка: `grep -n 'useCompany' src/components/projects/DealChzCard.tsx`. Править тот идентификатор, который в дереве. `okved` в select уже есть, `inn` появится после SUMMARY — подвалу ЧЗ не нужен, не выводить.

### W4. Подвал ОКВЭД: сырой код, не массив спеки

Спека: `company.okved[]`, «ОКВЭД 32.50 · 20.20». В БД `companies.okved` — **text** (один основной), хук отдаёт `string | null`. Не сплитовать по запятой наугад. Нет кода — левая часть подвала пустая, правая (справочник) остаётся: дата снапшота не зависит от ОКВЭД.

`title` с источниками (`CHZ_SNAPSHOT_SOURCES`) перенести на правую часть подвала, иначе после снятия `SnapshotNote` вопрос «откуда цифра» исчезнет. На ветке это сознательно было текстом, не только `title`.

Формат даты — `formatCalendarDate(CHZ_SNAPSHOT_DATE)` (уже на CHZ-1), не сырой ISO и не `formatDateNumeric` без `T00:00:00`.

### W5. Действующая группа: не красить `--success` ради симметрии

Спека: действующая — `surface-2`, тег green-soft. Достаточно `bg-surface2` без рамки. Янтарная рамка только у starting. Не вводить пару «зелёный vs жёлтый» на двух группах — в восьми темах зелёная подложка легко станет «всё хорошо», хотя обязанность уже наступила и это работа, не ок.

### W6. Не ждать CHZ-1 «как в отчёте», ждать дерево

Если к старту CHZ-1 не влит — **не стартовать**. Не накатывать хвосты на main без карточки. Спринт это уже сказал.
