## КЛЮЧЕВЫЕ РЕШЕНИЯ

1. **Порядок: сообщение → потом карточка.** `/задача звонок Ориент 3 августа в 15:00`
   отправляет в канал сообщение с текстом **без префикса команды** («звонок Ориент
   3 августа в 15:00»), и уже из него открывается карточка подтверждения с
   `sourceMessageId = message.id`. Дальше путь тот же, что у иконки на сообщении — один
   код, одна семантика, unique-индекс работает.
2. **Отправка не блокирует карточку по ошибке.** Если сообщение не ушло (сеть, RLS) —
   карточку НЕ открываем, показываем тост и оставляем текст в драфте композера
   (драфты per-канал есть с 1f). Создавать задачу «в никуда» нельзя: провенанс — половина
   смысла фичи.
3. **Отмена в карточке сообщение не удаляет.** Человек написал в канал — это уже
   коммуникация, и стирать её за него нельзя. Задача просто не создаётся; повторно
   поставить её можно иконкой на том же сообщении.
4. **Текст сообщения — очищенный от команды, но НЕ от даты.** В канал уходит то, что
   человек имел в виду («звонок Ориент 3 августа в 15:00»), а вырезание даты остаётся
   внутренней работой парсера для поля «Задача». Сообщение — запись разговора, а не
   служебная строка.
5. **`/ задача` с пробелом после слэша распознаётся** (известное ограничение из отчёта
   CC — Олег на него уже наступил, три его сообщения ушли в канал текстом). Регэксп
   команды: `^/\s*задача\b` с необязательным пробелом; учесть также `/task` как синоним
   — раскладка часто не переключена. Тесты на все формы: `/задача X`, `/ задача X`,
   `/task X`, `/задача` без текста, `/` один.

## ЗАДАЧА 1 — Слэш-путь через отправку

`MessageThread`, обработчик отправки:
- распознать команду по регэкспу из решения 5, вырезать префикс;
- пустой остаток → тост-подсказка (как сейчас), сообщение НЕ отправлять;
- непустой → `sendMessage.mutateAsync({ body: rest, me, files: [] })`;
  успех → `setTaskDraft({ body: rest, sourceMessageId: message.id, assigneeId: myId })`;
  ошибка → тост, драфт композера восстановить, карточку не открывать;
- вложения при слэш-команде игнорировать — если в композере есть прикреплённые файлы,
  отправить их обычным сообщением и команду не выполнять (тост: «Файлы отправлены,
  задачу поставь иконкой на сообщении»). Смешивать два намерения в одном действии хуже,
  чем честно разделить.

## ЗАДАЧА 2 — Подсказка и синонимы

## EDGE CASES

- Слэш-команда в канале, где нет прав на запись — сообщение не уйдёт (RLS), сработает
  ветка ошибки решения 2.
- Двойной Enter / быстрый повтор: `sendMessage.isPending` уже блокирует композер —
  проверь, что блокировка распространяется и на слэш-путь.
- Сообщение ушло, карточку закрыли, повторно нажали иконку на нём — обычный путь,
  `sourceMessageId` тот же, дубль отобьёт unique.
- Текст ровно `/задача` с завершающим пробелом — считается пустым.
