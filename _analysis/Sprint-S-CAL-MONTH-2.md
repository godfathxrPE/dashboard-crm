## ЗАДАЧА 1: hairline-сетка

`MonthGrid.tsx`:

- Обе сетки (шапка и тело) — `gap: 0`. Трек-функция остаётся
  `repeat(7, minmax(0, 1fr))` (правило из `d9a49a1`: `1fr` — это `minmax(auto, 1fr)`,
  и текст в ячейке раздувает колонку).
- Ячейка: `borderRight` + `borderBottom` по `1px solid var(--border)`; последняя
  в ряду без правой, последний ряд без нижней. `borderRadius` у ячейки **убрать** —
  с границами он даёт разрывы линий на стыках.
- **Заглушки `offset` и хвоста месяца** получают те же границы и тот же фон
  выходного, если попадают на Сб/Вс, но НЕ получают `cursor`, `data-cal-day`,
  `tabIndex` и обработчиков: это не дни.
- Шапка `Пн…Вс`: разделители `borderRight` между колонками + `borderBottom` под
  всей строкой, чтобы подписи читались как заголовок таблицы.
- Всю сетку (шапка + тело) обернуть в контейнер: `border: 1px solid var(--border)`,
  `borderRadius: var(--radius)`, `overflow: hidden` — иначе крайние линии висят
  в воздухе, а скругление контейнера срежет углы сетки аккуратно.
- Выходные: заливка `--surface2` остаётся. Линия между Сб и Вс появится сама —
  монолитная плашка на две колонки распадётся, что и требовалось.

## ЗАДАЧА 2: ховер и состояния — в общий слой

`globals.css`, рядом с прочими общими правилами (НЕ внутри `.t-*`):

```css
/* S-CAL-MONTH-2: ховер ячейки дня — общий для всех семи тем.
   До этого правило существовало только в .t-aura, и в шести темах ячейка
   на наведение не отвечала вовсе (тот же класс, что --danger в S-UI-SEMANTIC-1:
   состояние общего компонента, объявленное внутри одной темы). */
.cal-day { transition: background var(--duration-fast) var(--ease-out),
                       box-shadow var(--duration-fast) var(--ease-out); }
.cal-day:hover { background: var(--surface2); box-shadow: inset 0 0 0 1.5px var(--border2); }
.cal-day[data-weekend]:hover { background: var(--surface3); }
.cal-day:focus-visible { box-shadow: inset 0 0 0 2px var(--accent); outline: none; }
```

- Ячейке добавить `data-weekend` — сегодня выходной определяется только инлайновым
  фоном, зацепиться CSS не за что.
- Инлайновый `transition: 'background 0.15s'` из `MonthGrid` **убрать** — он теперь
  в CSS вместе с `box-shadow`, две точки правды не нужны.
- Фон выходного и выбранного дня оставить в инлайне (это данные, не состояние темы),
  но ховер-подсветку в инлайн НЕ дублировать.

⚠️ **Aura не ломать.** У неё `.t-aura .cal-day:hover { background: var(--surface2) !important }`
и `border-radius: var(--radius) !important` на ячейке. Радиус с границами даст
артефакты: **снять радиус для месяца** (или переопределить в базовом слое для
`.cal-day`, если aura-правило шире). Фирменные пилюля даты и кольцо «сегодня»
(`.cal-day-num`, S-CAL-MONTH-1) — сохранить один в один.

## ЗАДАЧА 3: прогон тем

Линии `--border` в тёмных темах — полупрозрачно-белые (`rgba(255,255,255,0.12)`
у frost и т.д.), на тёмном фоне они видны, но проверить обязательно: в tidal и
aurora фон дорожек тонирован, и линия может утонуть. Если тонет — **не заводить
тема-специфичное правило**, а поднять непрозрачность `--border2` для линий сетки
одним общим токеном.

Запасной ход, если hairline покажется шумным для minimal (эстетика темы построена
на отсутствии рамок): линии через
`color-mix(in srgb, var(--border) 55%, transparent)`. Решение за владельцем по
результату смока — **в спринт не закладывать**, оставить как заметку в отчёте.

# ОТЧЁТ — S-CAL-MONTH-2

Ветка `feat/month-grid-lines`. Миграций нет. Тесты 1155 (новых не заводил — слой
CSS), lint 14 err / 34 warn — baseline. Сделаны все три задачи; одно расхождение
со спекой пришлось исправить до начала работы, второе — по результату замера.

**Про базу ветки.** Спека просит ветвиться «от свежего `main` после мержа
S-CAL-MONTH-1 и `d9a49a1`». Мержа не было: `main` стоит на `4b12a16`, а оба
коммита лежат в `feat/month-chips`. Ветвился от `d9a49a1` — содержимое ровно то,
что просила спека. Мержить в `main` сам не стал, это не моё решение.

## Что теперь на экране

Месяц — таблица с hairline-сеткой: контейнер с рамкой и радиусом, внутри линии
между днями, шапка `Пн…Вс` отделена нижней границей и разделителями. Заглушки
первой и последней недели несут те же линии и тот же фон выходного, поэтому
сетка — честный прямоугольник из полных недель, а не «ступенька» по краям.
Сб и Вс разделены линией и больше не читаются как одна плашка на две колонки.

## 🔴 Дефект спеки, который пришлось поймать до работы

Задача 2 предлагала перенести ховер в общий слой как есть:

```css
.cal-day:hover { background: var(--surface2); … }
```

**Это правило не сработало бы ни в одной теме.** `MonthGrid` ставил фон
инлайном на КАЖДОЙ ячейке — `background: isSel ? … : weekend ? … : 'transparent'`.
Инлайновый стиль бьёт любое правило таблицы стилей без `!important`, то есть
`:hover` был бы мёртвым кодом. Ровно поэтому у прежнего аура-правила и стоял
`!important` — он там не «на всякий случай».

Поэтому фон дня переехал из инлайна в CSS вместе с ховером:

```
.cal-day[data-weekend]      → --surface2
.cal-day:hover              → --surface2 + контур
.cal-day[data-weekend]:hover→ --surface3
.cal-day:focus-visible      → кольцо --accent 2px
.cal-day[data-selected]     → --surface2 + кольцо --accent 1.5px   (последним)
```

Порядок значим: `[data-selected]` стоит последним, иначе ховер по выбранному дню
подменял бы его акцентное кольцо ховерным контуром (специфичность равная —
выигрывает то, что ниже).

Побочный выигрыш: кольцо выбранного дня тоже ушло из инлайна, и аура-правило
`.t-aura .cal-day[data-selected]` (специфичность 3 против 2) наконец побеждает —
в Aura кольцо снова фиолетовое, как задумывалось в S-CAL-MONTH-1, а не акцентное.

## Второе расхождение: контур ховера — `--border-input`, не `--border2`

Спека называла `--border2`. Замер по семи темам показал, что у этого токена нет
общего для тем смысла: **в washi `--border2` (#E5DFD5) СВЕТЛЕЕ обычной линии
`--border` (#D8D2C8)**, и контур давал 1.08:1 к фону — в washi ховера снова не
было бы. Тот же дефект, который спринт и чинит, просто в одной теме вместо шести.

Взял `--border-input` — в каждой теме он подписан «интерактив-рамка ≥3:1 к
surface», то есть по смыслу это и есть рамка интерактивного элемента. Замер:

| тема | контур/фон ховера | контур/фон ховера выходного |
|---|---|---|
| aura | 3.15 | 2.84 |
| washi | 3.15 | 2.93 |
| fuji | 3.37 | 2.96 |
| frost | 4.05 | 3.64 |
| aurora | 4.08 | 3.82 |
| tidal | 3.44 | 3.42 |
| minimal | 3.09 | 2.85 |

Это одно общее правило, а не тема-специфичное — как и требует задача 3.

## Aura: что убрано и почему

Из блока `.t-aura .cal-day` ушли три вещи, все три перестали быть нужны:

- `border-radius: var(--radius) !important` — с hairline скругление рвало линии
  на стыках. Радиус теперь у контейнера сетки, углы режет его `overflow: hidden`.
- `.t-aura .cal-day:hover` — переехал в общий слой (он и был тем единственным
  ховером, из-за которого шесть тем сидели без обратной связи).
- `transition … !important` — `!important` был нужен, пока переход жил в инлайне
  `MonthGrid`; инлайна больше нет.

Фирменные пилюля даты и кольцо «сегодня» (`.cal-day-num`) — на месте, проверено
глазами: в Aura «9» по-прежнему в фиолетовом кольце.

## Сетка как прямоугольник

`MonthGrid` считает не «заглушки + дни», а массив ячеек полных недель:
`total = ceil((offset + daysInMonth) / 7) * 7`. Отсюда и хвостовые заглушки,
которых раньше не было вовсе. Границы — от позиции в прямоугольнике
(`lastCol` без правой, `lastRow` без нижней), внешние линии даёт контейнер.
Выходной определяется колонкой (`col >= 5`), а не разбором даты: при раскладке
с понедельника колонки 5 и 6 — всегда Сб и Вс.

Заглушки получают линии и фон выходного, но не получают `cursor`, `tabIndex`,
`data-cal-day` и обработчиков — это не дни. `data-cal-day` тут не косметика:
по нему `PeekPanel` отличает «клик по другому дню» от «клика мимо».

`gap` у обеих сеток снят до нуля — с ним hairline распался бы на пунктир.

## Проверка

```

```

**Смотрел глазами все семь тем** (Chrome, живая база, август 2026): minimal,

Плюс замеры вычислением, потому что глаз тут не судья:

| Проверка | Результат |
|---|---|
| Ховер во всех 7 темах | фон уходит в `--surface3` на выходном, контур `--border-input` есть везде |
| Ховер на выходном | покой `--surface2` → ховер `--surface3` (замер по каждой теме) |
| `focus-visible` | Tab с ячейки 4 на 5 → `inset 0 0 0 2px --accent`, `outline: none` |
| Выбранный день | `--surface2` + кольцо `--accent` 1.5px, peek открывается |
| Заглушки | 11 штук в августе (5 + 6), линии несут, в фокус и клики не попадают |
| Aura | кольцо «сегодня» фиолетовое, ячейки без радиуса, линии не рвутся |
| Неделя | те же 4 чипа, `.cal-day` в вёрстке недели нет вовсе |
| Команда | не менялась |

⚠️ **Ловушка замера, стоившая получаса.** Сразу после подмены темы
`getComputedStyle` отдаёт цвет ПОСРЕДИ transition — у `.cal-day` теперь переход
по `background`. Первый прогон по семи темам выдал семь одинаковых строк
(значения minimal), и это выглядело как «правило не применяется в других темах».
Между сменой темы и чтением нужна пауза длиннее `--duration-fast`.

## Заметка владельцу (в спринт не входило)

Спека допускала приглушение линий через `color-mix` для minimal, «решение за
владельцем по результату смока». По-моему, не нужно: в minimal линии
`--border` (#E5E5E8) дают 1.16:1 к фону — это уже почти предел различимости,
приглушать дальше некуда. Если структура покажется шумной, дешевле и честнее
убрать вертикали внутри недели, оставив горизонтали между неделями, — но это
другой макет, не тюнинг прозрачности.
