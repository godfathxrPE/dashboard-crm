## Отклонения от спринта

- `decideClock`: ветку «касание после срока» проверяю до ветки срыва и требую `cls.lastTouchAt`, как `classifyDeal`. Без него `classifyDeal` уходит в срыв — таймер тоже.
- `decideClock`: открытая сделка с шагом, который не впереди и не просрочен, невозможна. Для неё (и для закрытой) таймер — `none`.
- `clockCaption`: для `done` и для `none` без шага, встречи и назначения возвращает пустую строку.
- Название в плитке — не больше двух строк (`-webkit-line-clamp: 2`), полное — в `title`. Вид слота при контенте ≥ 66rem — одной строкой с многоточием. Без этого при четырёх плитках высота на 1440 была 228 px.
- Временный маркер `data-today-pick` снял вместе с CSS-правилом: других потребителей нет.

## Вопросы и риски

- Четыре плитки в строке на 1280 дают плитку 134 px и высоту 222 px. Колонка текста рядом с кольцом — около 50 px. Выше сгиба одна строка списка вместо цели 4. Решение «до четырёх в строку» стоит пересмотреть: например, перенос с четвёртой плитки при контенте < 66rem.
- `moveWhy` в `today-text.ts` больше не используется в `src` — остался только в тестах.
- `t-washi`: дуга `over` совпадает с акцентом `#C23B3B`. Отличие от акцента держат красное число и полное кольцо.

## Дополнительно

### Задача 4 — темы

Состояния `calm`/`warn`/`over`/`done` проверил подменой `data-clock` в DOM. Стекло — классом `glass-sheet` на плитке.

| Тема | Результат |
|---|---|
| `t-minimal` | Кольца различимы: `calm` `--text-dim`, `warn` охра, `over` красный. Фон стекла плитки `rgba(0,10,12,.84)` = фон шапки фокуса |
| `t-aura` | Фон выбранной плитки `rgba(3,6,10,.84)` ≠ `rgb(255,255,255)` |
| `t-washi` | Подложка полосы розово-серая. `over`: дуга `rgb(194,59,59)`, число `rgb(179,52,52)` |
| `t-frost` | Граница плитки `rgba(255,255,255,.12)` = `--border`, safety-net её не перекрасил. На стекле дуга `rgb(11,21,44)`, `done` `rgb(0,85,29)` |

Состояние `none`: тестовая сделка уже имела шаг на сегодня, поэтому записи не понадобилось. Плитка показала пустое кольцо, `CalendarClock` и «назначено на сегодня».
