## ЗАДАЧА 1 — компания и контакт в задаче: поиск по подстроке

### Причина

`TaskModal.tsx:322-336` — оба поля нативные:

```tsx
<select …>
  <option value="">— не указана —</option>
  {(companies ?? []).map((c) => <option key={c.id} value={c.id}>{c.name}</option>)}
</select>
```

Нативный `<select>` ищет **по префиксу**: набранное «фитнес» сверяется с началом
строки, а компания записана `ООО "Фитнес Десерты"` — совпадения нет, и владелец
видит, что компании «не существует». При 268 компаниях список ещё и не
прокручивается глазами.

**Решение уже есть в проекте** — `components/shared/Combobox.tsx`, он фильтрует
по подстроке (`o.label.toLowerCase().includes(search)`, строки 63-67) и ищет
дополнительно по `sub`. Им уже пользуются `CallModal`, `ProjectModal`,
`DealStakeholders`. `TaskModal` — единственный, кто остался на нативном селекте.

### Что сделать

- Компания и контакт в `TaskModal` → `Combobox`, ровно как в `CallModal`
  (посмотреть там: пропсы, `ComboboxOption`, очистка через `×`).
- Фильтрация контактов по компании (S-FIX-BATCH-1) **сохраняется** — предикат
  уже вынесен в `lib/forms/derive-links.ts`, переиспользовать его, не дублировать.
- В `sub` у компании положить **ИНН**, если он есть: поиск по ИНН — обычный
  сценарий владельца (маркировка, сверка контрагента), а `Combobox` ищет и по
  `sub` бесплатно.
- ⚠️ **Нормализация ОПФ — не делать «умный» поиск.** `includes` уже решает
  заявленную задачу: «фитнес» находит `ООО "Фитнес Десерты"`. Отдельная
  нормализация ОПФ/кавычек живёт в `supabase/functions/company-lookup/normalize.ts`
  и её клиентском дубле — трогать её здесь **нельзя**: она про дедуп по ИНН,
  у неё другой контракт, и третья копия правил ОПФ разъедется с двумя первыми.
  Если поиск по подстроке окажется недостаточным — отдельный спринт, а не здесь.
- Проверить, что `TaskQuickAdd` не страдает тем же (если там select — перевести).

## ЗАДАЧА 2 — удаление выполненных задач

### Состояние

`TasksView` не импортирует `useDeleteTask` вовсе — в списке задач удаления нет
ни в каком виде. Хук существует и работает (`use-tasks.ts:604`), им пользуются
`ProjectBoard`, `KanbanBoard`, `GanttTimeline`. Режим «Выполнено» в списке уже
есть (`showDone`, `?done=1`, счётчик `doneCount` — у владельца 79 строк).

### Что сделать

**Точечное удаление** — иконка `Trash` на строке в режиме «Выполнено»:

- Показывать по hover и `:focus-within` (паттерн проекта — «hover-only + добавить»
  в таблицах, `globals.css`, AUDIT C3), чтобы не шуметь в спокойном состоянии.
- Подтверждение — `InlineConfirm` (примитив проекта, `components/ui/InlineConfirm.tsx`),
  **не** `window.confirm`: он запрещён правилом проекта и ловится линтом.

**Массовое удаление** — кнопка «Удалить выполненные (N)» в режиме «Выполнено»:

- N — из уже посчитанного `doneCount`, в текущем скоупе (Мои/Все + источник):
  удаляется **ровно то, что видно на экране**, а не «все выполненные в базе».
  Это ключевое: владелец смотрит на отфильтрованный список, и удалиться должен он.
- Подтверждение с явным числом и скоупом в тексте: «Удалить 79 выполненных задач
  из „Личное“? Отменить нельзя».
- Удаление батчем одним запросом (`in ('id1','id2',…)`), не N запросов подряд.

### ⚠️ Что обязательно учесть

1. **Отката нет.** В схеме нет `deleted_at` ни у одной таблицы (проверено на
   гейте S-FIX-BATCH-1) — `useDeleteTask` делает физический `DELETE`. Поэтому
   подтверждение обязательно, а формулировка — честная: «Отменить нельзя».
2. **Права.** Удалять можно только то, что владелец имеет право удалять — свериться
   с RLS и с тем, как это делают `ProjectBoard`/`KanbanBoard` (там уже есть
   `canManage`-подобная проверка). В режиме «Все» чужие задачи под массовое
   удаление попадать не должны.
3. **Строки плана.** `excludePlanItems` уже режет их из списка (S-FIX-BATCH-1),
   значит под массовое удаление они не попадут — **проверить это явно** в тесте:
   выполненная строка плана с `wbs_code` + `project_id` не должна оказаться в
   наборе на удаление ни при каком фильтре.
4. **События журнала.** У удаляемых задач могут быть записи в `activity_log`
   (`task_created`, `task_completed`). Они переживут задачу и станут немыми —
   как 478 событий `task_created` без `task_id` из S-COST-TRUTH-1. Это
   приемлемо, но **записать в отчёт** фактическое число: сколько событий журнала
   ссылается на удаляемый набор.

## Критерий приёмки

| Проверка | Ожидание |
|---|---|
| Новая задача → Компания, ввод «фитнес» | находит `ООО "Фитнес Десерты"` |
| Ввод ИНН | находит компанию по `sub` |
| Контакты после выбора компании | только связанные (не сломано S-FIX-BATCH-1) |
| Клавиатура в Combobox | ↑↓, Enter, Esc — как в CallModal |
| Режим «Выполнено», hover строки | иконка удаления, подтверждение inline |
| «Удалить выполненные (N)» | удаляет ровно видимый скоуп, N совпадает со счётчиком |
| Массовое в режиме «Все» | чужие задачи не затронуты |
| Выполненная строка плана | под удаление не попадает (тест) |
| `window.confirm` | не появился нигде (линт) |
