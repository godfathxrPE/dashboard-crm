## С чем согласен полностью

### 1. Первый потребитель `--zone-*`, без миграций и без новой графики

Токены заведены в S-LIME-TOKENS-1 и до сих пор нигде не читаются. Примитив `.zone` с геометрией в одном классе и фоном через `--zone-surface` — правильный слой: не копипаст трёх подложек по компонентам, не хардкод цвета. `--radius-zone: 26px` в `:root` согласован с остальной шкалой радиусов (все `--radius*` в проекте в px).

### 2. Кокпит в «Работу» — причина R-04 снята

Комментарий в `ProjectDetail.tsx:283–284` ссылается на наезд 11 стадий в колонке 1100px. Нынешняя карта — группы `phase_group` со `shrink-0` и `overflow-x-auto` (`StageRail.tsx:76–104`). Переезд кокпита в левую колонку, чтобы «Риски» стояли вровень со стадией, — обоснован. Условие показа кокпита (`pipeline_id && stage_id && (client \|\| delivery)`) в задаче 2 названо явно.

### 3. Граница 1A / 1B

Кольцо сегментами, лайм-бюджет, «перенесён N раз», виджеты «Доска / Активность», `t-fuji` / `fix-NAV-CARRIER` — честно вынесены. `postpone_count` в схеме нет — это не догадка.

### 4. ТЕСТЫ и финальная проверка

UI-only, новой логики в `lib/` нет — строка «тестов нет» по контракту. `audit-tokens.py` + `audit-contrast.py` («не подгонять, если FAIL вырос») + смок в `t-lime` / `t-minimal` / `t-frost` — нужный набор. Коммит через `git commit -F - <<'MSG'` — не `-m`, zsh не раскроет `!`.

### 5. `audit-tokens.py` и инлайн `--zone-surface`

Спринт заранее допускает отказ сторожа и запасной путь `.zone-work` / `.zone-ctx` / `.zone-risk`. Hex в tsx нет, R1 не должен сработать; инлайн задаёт **имя токена**, не цвет. Прецедент уже есть: `StageRail.tsx:89` ставит `style={{ color: 'var(--accent-text, …)' }}`.

## Блокеры (критично — исправить до запуска)

### B1. Разведка врёт про `DealVerdict` — CC остановится на шаге 5

Спринт:

> `verdict` принимает `ok | attention | rotting`.

Live (`src/lib/domain/deal-signals.ts:29`):

```ts
export type DealVerdict = 'new' | 'ok' | 'attention' | 'rotting';
```

Четвёртое значение — не косметика: `getDealSignals` ставит `'new'` в льготный период (`graceDays`, ветка после `firstBad`, `:362`). `VERDICT_CONFIG` / `VERDICT_STYLES` знают все четыре. Порог разведки («не совпало — остановиться») сработает.

В задачу 3 вписать полный маппинг:

| `verdict` | `healthClass` | подзаголовок eyebrow |
|-----------|---------------|----------------------|
| `ok` | нет (дефолт `--h-zone` = risk-ok) | «сигналов нет — сделка в норме» |
| `new` | нет (тот же дефолт, **не** `h-attention`) | отдельная фраза про льготу, не текст `ok` |
| `attention` | `h-attention` | «есть что поправить» |
| `rotting` | `h-rotting` | «что может сорвать сделку» |

`new` ≠ `ok` на чипе («Новая» / «В порядке»). Свалить в одну фразу — снова два языка одного факта.

### B2. `ProjectDetail` общий для `/deals/[id]` и `/projects/[id]`

Файл один, `context: 'deal' | 'project'`. Сетка, рельс, кокпит — на сделке, внедрении и internal. Спринт ни разу не говорит, что делать с `type !== 'client'`.

Live-развилка, которую сниппет задачи 3 затирает:

- Здоровье сделки — `DealSignals` (и то только при `signals.length > 0`).
- Здоровье внедрения — `DeliveryHealthDot` от `getDeliveryHealth`, не от `signals.verdict` (`DealContextRail.tsx:73–82`, сборка в `ProjectDetail.tsx:223–232`).
- `DealNextStep` — только `hasNextStep = type === 'client' && status === 'open'` (`:239`).
- «Закреплено» — только сделка (`:109`).
- `useDealSignals(project)` **не** гейтится по типу: на delivery посчитает deal-сигналы (next_step / deadline / silence). Красить зону «Риски» внедрения через `signals.verdict` — чужая формула на чужой карточке.

Нужна явная вилка в спринте, один из двух вариантов:

1. **Зоны только для `type === 'client'`.** Delivery/internal оставляют нынешний двухколонник. Больше if в JSX, зато 1A не трогает `/projects/[id]`.
2. **Те же три зоны на всех типах**, но `healthClass` у delivery — от `deliveryHealth.level` (или аналога), не от `DealVerdict`; шаг не рендерится вне `hasNextStep`; «Закреплено» не появляется у delivery.

Без вилки CC либо покрасит внедрение deal-вердиктом, либо разведёт вёрстку «по обстоятельствам» — то, что разведка запрещает.

### B3. Сниппет задачи 3 рисует `DealNextStep` безусловно

Задача 2 сохраняет условие кокпита. У шага условия в сниппете нет. Live: без `hasNextStep` рельс и вкладки делят первую строку (`:237–238, 341–343`), на won/lost и на delivery шага нет.

Если вставить `{DealNextStep}` как в сниппете — карточка выигранной сделки и карточка внедрения получат «Какой следующий шаг?». Сохранить `hasNextStep` и пустую «Работу» без шага (кокпит + вкладки) — написать явно.

### B4. F-01 / R-09: вердикт снова в двух местах

`DealNextStep.tsx:19–21, 124–133` — `DealVerdictChip` под шагом, и файл прямо говорит: «Вердикт здесь ЕДИНСТВЕННЫЙ на экране… Два вердикта — воспроизведение F-01». Рельс рисует сигналы с `showVerdict={false}` именно поэтому. R-09 (`improvements/deals-layout-rationale-2026-08-24.md`): вердикт в рабочей колонке, в рельсе только список сигналов.

Спринт оставляет чип нетронутым и добавляет:

- фон зоны «Риски» по `--h-zone` (это как раз ответ на F-10 — **уровень, не бейдж**, это можно);
- **текст** eyebrow по тому же `verdict` («сделка в норме» / «есть что поправить» / «что может сорвать»).

Два словесных носителя одного факта — ровно закрытый F-01. В спринт — одно решение:

- чип под шагом **остаётся** → eyebrow зоны «Риски» статический («Риски»), без пересказа вердикта; цвет несёт только фон;

Фон зоны в обоих вариантах остаётся.
