## ЗАДАЧА 1 — действия на полосу вкладок (R-07)

**Файл:** `src/components/projects/ProjectDetail.tsx`

Кнопки `+ Задача / + Звонок / + Встреча` живут внутри блока `#deal-activity` и исчезают на
вкладках Доска / Гант / КП / История / Чат. Перенести их на полосу вкладок — видны всегда.

```tsx
<div className="mb-3 flex flex-wrap items-center gap-1 border-b border-border">
  {/* ... существующие вкладки без изменений ... */}
  <div className="ml-auto flex flex-wrap gap-1 pb-1">
    {/* три кнопки, перенесённые из #deal-activity как есть */}
  </div>
</div>
```

⚠️ **`flex-wrap` обязателен на обоих уровнях.** При рабочей колонке ~556px (1280 + открытый
`ActivityDrawer`) шесть вкладок и три кнопки не помещаются в строку: замерено в мокапе —
`scrollWidth` 725 против `clientWidth` 556. Без `flex-wrap` кнопки обрезаются справа молча.
Действия переносятся на вторую строку, вкладки не режутся.

Внутри `#deal-activity` шапка блока остаётся (иконка + «Активность»), но **без кнопок** —
`justify-between` там больше нечего разводить, оставить простой заголовок.

## ЗАДАЧА 2 — «Материалы» счётчиками в рельсе (R-08)

**Новый файл** `src/components/projects/DealMaterialsCard.tsx` — карточка рельсы.

Строки (`RailRow`, порядок фиксирован; строка не рендерится, если поле не про этот тип):

| Строка | Значение | Для кого |
|---|---|---|
| 1С:ДО | `привязан` / `привязать` (курсив, приглушённо) | только `isDelivery` |
| Заметки | `есть` / `—` (по `project.pinned_note`) | delivery и internal |
| Файлы | число из `useProjectFiles(projectId).data?.length ?? 0` | все |
| Видео | число из `useProjectVideos(projectId).data?.length ?? 0` | все |

Вся карточка кликабельна и открывает модалку из задачи 3; строка с нулём — приглушена,
но кликабельна тоже (открыть, чтобы добавить первое).

**Цена, которую надо принять осознанно:** сейчас `ProjectFiles`/`ProjectVideos` монтируются
только при раскрытии аккордеона, то есть списки не грузятся вовсе, пока их не открыли.
После этой задачи оба хука вызываются на **каждой** карточке сделки — это два запроса,
которых раньше не было.

**Не заводить `count: 'exact'`-запросы ради счётчиков.** В проекте такого паттерна нет
ни одного, а выигрыш мнимый: те же `useProjectFiles`/`useProjectVideos` нужны модалке, и
при общем ключе кеша TanStack Query отдаст ей данные без второго запроса. Один запрос на
список дешевле, чем count плюс список.

## ЗАДАЧА 4 — пустые состояния файлов и видео (F-04)

**Файлы:** `ProjectFiles.tsx`, `ProjectVideos.tsx`

Заменить собственные пустые состояния на примитив `@/components/ui/EmptyState`
(`icon` / `title` / `description` / `action`). Формулировки — что даёт файл или видео,
а не «пусто»:

- Файлы: «Файлов нет» · «КП, ТЗ, протоколы встреч — всё, что понадобится на защите» ·
  действие «Загрузить файл».
- Видео: «Видео нет» · «Записи созвонов и демо — чтобы не пересказывать словами» ·
  действие «Добавить ссылку».

⚠️ Пустое состояние **не должно занимать больше места, чем то же с данными**
(`crm-ui-designer`, антипаттерн плотности). В модалке это уже не критично, но `py-8`
у `EmptyState` для двух блоков подряд — многовато; если суммарно выходит выше списка
из трёх элементов, ужать отступ локальным классом, не правя примитив.
