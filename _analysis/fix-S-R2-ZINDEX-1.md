## Почему правка — один токен

Фактическая шкала в `src/` (посчитано, а не вспомнено):

```
z-0, z-[1], z-10        контент, элементы карточек
z-20                    сайдбар
z-30                    ActivityDrawer
z-40                    PeekPanel
z-50                    Modal, AiWorkspaceModal, AiDealModal, WeeklyReview,
                        тултипы Ганта, тосты
z-[60]                  CommandPalette, Hotkeys help
z-[100]                 ContentHeader          ← единственный обитатель полосы
z-[9999]                дропдауны внутри шапки, bulk-бар DataTable, skip-link
```

Документированная иерархия проекта отводит заголовкам **35–40**. `z-[100]` — отклонение:
он там стоит, чтобы поднять свои дропдауны над контентом, но `relative z-[100]` создаёт
стекинг-контекст, и внутренние `z-[9999]` работают **внутри** него, наружу торчит именно 100.
Чтобы дропдауны были выше контента, хватает любого значения выше `z-30`.

**Правка: `z-[100]` → `z-[35]`.** Тогда:

| Отношение | До | После |
|---|---|---|
| peek (40) vs шапка | 40 < 100 — панель под топбаром 🔴 | 40 > 35 ✓ |
| модалка (50) vs шапка | 50 < 100 — топбар поверх модалки 🔴 | 50 > 35 ✓ |
| шапка vs drawer (30) | 100 > 30 ✓ | 35 > 30 ✓ |
| шапка vs сайдбар (20) | ✓ | ✓ |
| дропдауны шапки vs контент | ✓ | ✓ (внутри своего контекста) |

Между 35 и 100 в проекте **нет ни одного элемента** — проверено перечислением выше, поэтому
других отношений правка не меняет. Не поднимать `PeekPanel` и не трогать модалки: чем меньше
чисел поменяно, тем меньше поверхность регресса.

**1.1.** `src/components/layout/ContentHeader.tsx:79`:

**1.2. Браузерная проверка — суть спринта, без неё задача не принимается.**

На **каждой** из пяти страниц с peek (`/companies`, `/contacts`, `/leads`, `/projects`,
`/tasks`): открыть панель (Space на строке или клик по строке), затем:

- клик по «Открыть полностью» → переход на карточку сущности состоялся;
- клик по крестику → панель закрылась;
- клик по строке таблицы при открытой панели → содержимое панели сменилось, перехода нет.

Отдельно на `/leads` — полный сценарий deep link, он и был исходным симптомом:

1. Space на строке → peek открылся;
2. «Открыть полностью» → `/leads?lead=<id>`, открылась модалка «Редактировать лид»;
3. закрыть модалку → URL вернулся к `/leads`, панели под модалкой нет;
4. пройти по той же ссылке повторно → модалка снова открывается.

**1.3. Проверить второе следствие.** Открыть любую модалку (например «Создать задачу») на
любой странице и посмотреть на верхнюю полосу: кнопка «Поиск», колокольчик и переключатель

правки (проверить на `git stash`) — это отдельный дефект, который правка закрывает попутно,

**1.4. Регресс дропдаунов шапки.** Открыть переключатель тем и колокольчик уведомлений:

(панель в этот момент активная поверхность), но убедиться, что он не пропал совсем и
закрывается кликом.

**1.5. `ActivityDrawer`** (z-30, только `t-aura`): открыть и убедиться, что шапка по-прежнему

```markdown
## Правила

1. **`relative z-*` создаёт стекинг-контекст.** Внутренние `z-[9999]` работают только внутри
   родителя — наружу торчит значение родителя. Поэтому дропдауну в шапке не нужно, чтобы
   шапка была выше модалок.
2. **Панель без оверлея (`PeekPanel`) обязана быть выше всего, что ловит клики мышью.**
   Она закрывается по клику снаружи (`handlePointerDown`), и любой элемент поверх её шапки
   превращает клик по ней в клик «мимо» — панель закроется, а действие не выполнится.
3. **Модалка выше панели, палитра выше модалки.** Порядок вложенности внимания.
4. Инцидент 2026-08-02: `ContentHeader` стоял `z-[100]` и перекрывал и peek, и модалки.
   Найдено `document.elementsFromPoint` по центру ссылки — стек элементов показал топбар
   выше `<a>`. Приём годится для любого «клик не работает, но элемент видно».
```

Таблицу заполнять **по факту** из разведки, а не переписывать из этого промпта: если grep
покажет иные значения — верны значения из кода, и это надо отметить в отчёте.

про структуру документации. Если нет — не выдумывать раздел.
