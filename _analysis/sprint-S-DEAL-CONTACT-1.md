## Зачем

Чтобы позвонить по сделке, сейчас нужно: список стейкхолдеров → клик по имени →
раздел «Контакты» → раскрыть виджет → увидеть номер. Четыре шага до строки,
которая уже загружена в браузер.

Спринт делает две вещи: ставит чип основного контакта с кнопкой звонка в футер
виджета «Следующий шаг» и показывает должность, телефон и почту в строках карточки
«Стейкхолдеры», попутно чиня три её дефекта.

## ЧЕГО В СПЕКЕ НЕТ — решения владельца от 13.09

### П1. Слоты ролей. Спека их не описывает — а карточка состоит из них

Спека рисует список участников. В коде поверх списка лежат СЛОТЫ ожидаемых ролей
(`src/lib/domain/role-slots.ts`, `EmptySlotLine` в `DealStakeholders.tsx:471-528`):
незакрытая роль — блок в пунктирной рамке с подписью и подсказкой. На живом экране
владельца это два блока из трёх, то есть две трети карточки.

**Слоты НЕ удалять** — `missingRequired` кормит сигнал `single_threaded`, а пустой
слот сам по себе сообщение. Но слот обязан быть ТИШЕ строки с человеком:

- одна строка вместо двух: `slot.label` и всё;
- пунктирной рамки вокруг блока НЕТ (`border border-dashed border-border2` со
  `shell` снимается), остаётся кружок с плюсом слева;
- `slot.hint` строкой НЕ печатается — уходит в `title` кнопки;
- тег роли справа — тот же примитив, что у заполненных строк.

Проверка результата: в состоянии «1 участник + 2 слота» заполненная строка должна
быть визуально тяжелее любого слота.

### П2. Счётчик в шапке остаётся счётчиком РОЛЕЙ

Спека: «Контур сделки · 4 участника». В коде (`:656-662`): «Стейкхолдеры ·
{filledCount} из {totalCount} ролей». Число людей отвечает на менее полезный вопрос
и разъезжается с сигналом. **Шапку не трогать вовсе.**

### П3. Заголовок — «Стейкхолдеры», не «Контур сделки»

«Контур сделки» — формулировка брифа, в продукте её нет. Переименования НЕТ.

### П4. Кнопка удаления участника (в спеке отсутствует, в коде ломает строку)

`:376-396` — кнопка с `X`. Строка участника размечена `flex flex-wrap`, и в 356px
имя + тег роли + кнопка не помещаются: крестик падает на свою строку и читается как
поломка вёрстки. **Удаление переезжает в группу действий на наведении** (см. ЗАДАЧА 3),
последней иконкой, отделённой отступом. Отдельной строкой кнопка не остаётся ни при
какой ширине.

### П5. Из hover-действий убрать «позвонить»

Спека (2.3) даёт три иконки: позвонить · почта · заметка. Кнопка с номером стоит в
той же строке — два способа позвонить рядом. **Иконку телефона не рисуем**, остаются
почта, заметка и удаление (П4).

### П6. Формат номера — существующий `formatPhone`, а не маска спеки

Спека просит `+7 921 445-12-08`. В продукте есть `src/lib/utils/phone.ts` →
`formatPhone()`, дающий `+7 (921) 445-12-08`, и он уже на экране лидов
(`LeadsView.tsx:190`, `LeadDetail.tsx:274`, `LeadPeekContent.tsx:75`). Единый формат
по продукту важнее маски из спеки — **берём `formatPhone`, свой форматтер не писать.**
`href` строим тем же способом, что `LeadPeekContent.tsx:71`:
`tel:${phone.replace(/[^\d+]/g, '')}`.

### П7. Цвета и размеры спеки — читать как СМЫСЛ, а не копировать

Спека написана хексами и пикселями (`#C9F25A`, `#17171C`, `h28`, `radius 8`). Конвенция
проекта (`SKILL.md`, CSS): **хардкод цветов запрещён, только CSS-переменные; единицы
rem/em/clamp, px только для бордеров ≤ 2px.** Перевод:

| В спеке | В коде |
|---|---|
| `#C9F25A` | `var(--accent)` / класс `text-accent`, `border-accent` |
| `#17171C`, ink | `text-text-main` |
| `#5F5F6A`, `#4E4E59` | `text-text-dim` |
| `#8A8A94` | `text-text-mute` |
| `#D9D9E0`, `#ECECF0` | `border-border`, `border-border2` |
| `#F4F4F6` | `bg-surface2` |
| `rgba(255,255,255,.55)` на тёмном стекле | существующие классы виджета (`--on-glass`), НЕ новый цвет |
| `h28`, `padding 0 10`, `radius 8` | `h-7`, `px-2.5`, `rounded-lg` — ближайшие токены шкалы |

Ни одного нового токена спринт не вводит.

## ЗАДАЧА 1 — `use-contact-brief.ts`: один запрос, который чинит две дыры

**Проблема, найденная гейтом.** Чип в виджете шага показывает ОСНОВНОЙ контакт
сделки — `projects.contact_id`. Но:

1. Запрос сделки тянет `contact:contacts(id, first_name, last_name)`
   (`use-projects.ts:176`) — без `phone`, `position`, `email`. Расширять этот select
   НЕЛЬЗЯ: он грузится в каждом списке сделок (та же причина, что в S-DEAL-CHZ-1).
2. `useDealStakeholders` отдаёт только строки `deal_stakeholders`. Если контакт задан
   в сделке, но в карту не добавлен (в коде это `virtualContactId`, `role-slots.ts`),
   его телефона на странице НЕТ ВООБЩЕ. Тот же пробел у `VirtualPrimaryLine`:
   `primaryContact` приходит пропсом из `DealContextRail.tsx:132` урезанным до трёх
   полей, поэтому виртуальная строка рисует имя без должности и контактов.

**Решение:** `src/lib/hooks/use-contact-brief.ts`

```ts
export interface ContactBrief {
  id: string;
  first_name: string;
  last_name: string;
  position: string | null;
  email: string | null;
  phone: string | null;
}

export function useContactBrief(contactId: string | null) // enabled: !!contactId
```

Запрос по первичному ключу: `.from('contacts').select('id, first_name, last_name,
position, email, phone').eq('id', contactId).maybeSingle()`. Ключ
`['contact-brief', contactId]` — React Query дедуплицирует оба потребителя.

Потребителей два: чип в `DealNextStep` (ЗАДАЧА 2) и `VirtualPrimaryLine` в
`DealStakeholders` (ЗАДАЧА 3, п. 3.4). `maybeSingle()`, не `single()`: удалённый или
недоступный по RLS контакт — это `null`, а не throw.

## ЗАДАЧА 2 — чип основного контакта в футере `DealNextStep`

Спека, раздел 1.2–1.4 (размещение A1-a). Файл `src/components/projects/DealNextStep.tsx`,
футер `:129-180`.

2.1 Порядок в строке футера: «Дата» → «Шаг сделан» → просрочка/переносы →
    `ml-auto` → «N дн. без касания» → чип. Класс `ml-auto` сейчас висит на строке
    «без касания» (`:172`) — он остаётся там, чип встаёт ПОСЛЕ неё.

2.2 Состав чипа: аватар-инициал, имя, должность, кнопка звонка с номером целиком.
    Кнопка — `<a href="tel:...">`, а не `<button>`: это переход, ему нужен нативный
    контекстный меню и обработка на мобильном.

2.3 Состояния (спека 1.4) — и ни одного лишнего:

| Условие | Что рисуем |
|---|---|
| `brief.phone` есть | аватар · имя/должность · кнопка звонка |
| телефона нет, есть `email` | аватар · имя/должность · почта + «копировать» |
| `contact_id === null` ИЛИ `brief === null` | **чип не рендерится вовсе**; футер кончается строкой «без касания». Ни пустого слота, ни приглашения «добавить контакт» |

2.4 Переполнение: блок «имя + должность» — `min-w-0` и перенос по словам, номер —
    `whitespace-nowrap` и `tabular-nums`. Многоточия на номере быть не может.
    Кнопка «Шаг сделан» не сжимается (`shrink-0`).

2.5 Акцент: заливка `--accent` в виджете остаётся ТОЛЬКО у метки «Следующий шаг».
    Кнопка звонка несёт акцент рамкой и иконкой, текст номера — цветом текста на
    стекле. Итог на виджет: одна заливка + один контур.

⚠️ Иерархию не трогать: текст шага (`text-xl`) остаётся крупнейшим элементом виджета.

## ЗАДАЧА 3 — `DealStakeholders`: контакты в строке, действия на наведении

Спека, раздел 2. Файл `src/components/projects/DealStakeholders.tsx`.

3.1 **Строка участника переезжает с `flex flex-wrap` на grid** (спека 2.2):
    три колонки — звёздочка / контент / роль + действия. Именно `flex-wrap` сейчас
    роняет кнопку удаления на отдельную строку (П4), поэтому замена раскладки —
    не косметика, а лечение дефекта.

3.2 Контент строки сверху вниз: имя (ссылка на `/contacts/[id]`) + тег «основной»
    у основного; должность; затем телефон ЛИБО почта:

- телефон есть → кнопка-ссылка `tel:` с номером через `formatPhone` (П6),
  отдельной строкой под должностью, номер целиком;
- телефона нет, есть почта → строка почты + кнопка «копировать»;
- нет ни того, ни другого → НИЧЕГО. Никаких «добавить телефон»: в реальной базе
  это большинство строк, и приглашения забьют карточку.

3.3 Действия на наведении (спека 2.3, с поправкой П5): почта · заметка · **удалить**
    (последней, с отступом от первых двух). Иконки телефона в группе НЕТ.
    Доступность: группа видна не только на `hover`, но и при `focus-within` —
    иначе с клавиатуры до удаления не добраться.

3.4 `VirtualPrimaryLine` (`:405-440`) получает те же должность и контакты через
    `useContactBrief(primaryContactId)` из ЗАДАЧИ 1. Сейчас эта строка — единственное
    место, где основной контакт показан без единого поля, кроме имени.

3.5 «копировать» (спека 2.5): `navigator.clipboard.writeText`, на 1.5 с подпись
    меняется на «скопировано» без скачка ширины. Паттерн и обработка отсутствующего
    clipboard — как в `TranscriptViewModal.tsx:43-46` (`try/catch`, тихо игнорируем).
    Тоста нет.

3.6 Focus-visible на карточке — контур цветом текста, НЕ акцентом (спека 2.4):
    на светлой подложке лайм не читается.

## ЗАДАЧА 4 — слот роли в одну строку

`EmptySlotLine` (`:471-528`), решение П1:

4.1 Убрать `border border-dashed border-border2` из `shell`; кружок с плюсом слева
    остаётся, он и есть маркер «не закрыто».
4.2 `slot.hint` не рендерится строкой — уходит в `title` кнопки. Заодно уходит
    `truncate` на подсказке (`:499`), из-за которого на живом экране висит
    «задаётся полем „Контакт“ сде…».
4.3 Обязательность роли остаётся цветом метки (`slot.isRequired` →
    `text-danger-text`), но на самой метке, а не на подсказке.
4.4 Высота слота ≤ высоты строки участника без контактов.
