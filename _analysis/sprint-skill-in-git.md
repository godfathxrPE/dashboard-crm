# Claude Code Prompt — S-SKILL-GIT-1: память проекта под версионный контроль

Скилл `crm-architect` — память, из которой собирается каждый спринт и по которой
проверяет гейт. Сейчас она живёт в **трёх** несинхронизированных экземплярах:

| Где | Кто читает | Как правится |
|---|---|---|
| `~/.claude/skills/crm-architect/` | Claude Code | руками / агентом, без истории |
| аккаунт Claude.ai (Customize → Skills) | **Cowork-сессии, в т.ч. гейт** | загрузкой `.skill`-пакета |
| `~/.claude/projects/…/memory/` | только Claude Code | журнал спринтов (остаётся как есть) |

**Что это стоило 2026-08-05.** Аккаунтная копия замерла на `v2.0 · 2026-07-29` и
утверждала «миграции 001–075, следующая 076», хотя в проекте 104. Гейт построил
на ней ложный вывод про несуществующий долг `docs/schema.md`, а расхождение между
копиями выяснилось только через три раунда взаимных уточнений. Правка ~3500 строк
общей памяти (S-MEM-SYNC-1) прошла вообще без ревью — проверять было нечем.

**Цель спринта:** один источник истины в git, одностороннее применение, проверяемое
расхождение. После него правка памяти становится обычным диффом, который гейт читает
так же, как код.

```
crm-architect/ в репозитории (источник, git)
        │
        ├─ scripts/skill-deploy.sh ──► ~/.claude/skills/crm-architect/   (Claude Code)
        │                         └──► crm-architect.skill (zip)          → загрузить в аккаунт руками
        └─ scripts/skill-verify.sh ──► diff: репо ↔ локальная копия
```

**Ветка:** `chore/skill-in-git` от свежего `main`.

**Жёсткие рамки:**
- Никаких изменений в `src/`, `supabase/`, миграциях. Спринт только про инфраструктуру памяти.
- Направление синхронизации **строго одно**: репо → всё остальное. Скрипта «забрать
  изменения обратно» быть не должно — он бы вернул ту самую болезнь.
- `.skill`-пакет **не коммитится** (в `.gitignore` уже есть `*.skill` — проверить).

---

## РАЗВЕДКА

```bash
cd ~/Downloads/dashboard-crm

# 1. Что сейчас в репозиторной папке (ожидание: только мусор .DS_Store)
find crm-architect -type f 2>/dev/null
git log --oneline -- crm-architect/ | head

# 2. Актуальный источник — локальный скилл (после S-MEM-SYNC-1)
ls -la ~/.claude/skills/crm-architect/ ~/.claude/skills/crm-architect/references/
wc -l ~/.claude/skills/crm-architect/SKILL.md ~/.claude/skills/crm-architect/references/*.md
head -3 ~/.claude/skills/crm-architect/SKILL.md      # frontmatter обязателен

# 3. .gitignore: .skill и .DS_Store
grep -n "skill\|DS_Store" .gitignore

# 4. Образец скрипта проекта (mktemp → санити → mv) — следовать его стилю
cat scripts/gen-types.sh
```

⚠️ Если разведка покажет, что локальный скилл **старее** репозиторного (после этого
спринта такое возможно) — источником всегда считается **репо**, а локальная копия
перезаписывается раскаткой. Обратного копирования не делать ни при каких условиях.

---

## ЗАДАЧА 1: Перенести скилл в репозиторий

1. Скопировать из `~/.claude/skills/crm-architect/` в `crm-architect/` репозитория:
   `SKILL.md` + `references/{architecture,learnings,schema,theme-system}.md`.
2. Удалить мусор: `crm-architect/.DS_Store`, `crm-architect/references/.DS_Store`.
   Если `.DS_Store` не в `.gitignore` — добавить строкой `.DS_Store`.
3. Проверить, что `SKILL.md` начинается YAML-фронтматтером (`---` / `name:` /
   `description:` / `---`) — без него скилл не грузится ни локально, ни в аккаунт.

⚠️ Ничего в содержимом файлов **не менять** — это перенос, не правка. Единственное
исключение — Задача 4, и она делается уже поверх файлов в репо.

---

## ЗАДАЧА 2: `scripts/skill-deploy.sh` — раскатка из репо

Новый файл, стиль — по образцу `scripts/gen-types.sh` (разведка №4): `set -euo pipefail`,
временный каталог, санити-проверки до перезаписи цели, `mv`/`rsync` в конце.

Что делает:

1. **Санити-проверки источника** (падать с внятным текстом, ничего не трогая):
   - `crm-architect/SKILL.md` существует и начинается с `---`;
   - все четыре файла в `crm-architect/references/` на месте и непустые;
   - в `SKILL.md` есть строка `name: crm-architect`.
2. **Бэкап текущей локальной копии** перед перезаписью:
   `~/.claude/skills/crm-architect` → `~/.claude/skills/.backup/crm-architect-<YYYYmmdd-HHMMSS>`
   (создать каталог при необходимости). Без бэкапа не раскатывать: там может лежать
   правка, которую ещё не перенесли в репо.
3. **Раскатка** в `~/.claude/skills/crm-architect/`: сначала во временный каталог,
   затем атомарная подмена. Лишние файлы, которых нет в репо, из цели **удаляются** —
   копия обязана быть точным отражением источника.
4. **Сборка пакета** `crm-architect.skill` (zip содержимого папки: `SKILL.md` +
   `references/`, без `.DS_Store` и точечных файлов) в корень репозитория.
5. **Финальный вывод** — что сделано, путь бэкапа и напоминание одной строкой:
   пакет `crm-architect.skill` нужно **загрузить руками** в Claude.ai →
   Customize → Skills, иначе Cowork-сессии продолжат читать старую версию.

`chmod +x`. Скрипт запускается из корня репозитория.

---

## ЗАДАЧА 3: `scripts/skill-verify.sh` — проверка расхождения

1. `diff -r` между `crm-architect/` (репо) и `~/.claude/skills/crm-architect/`,
   исключая `.DS_Store` и точечные файлы.
2. Совпало — сообщение «источник и локальная копия идентичны», выход `0`.
3. Разошлось — вывести дифф и выйти с кодом `1`, добавив подсказку:
   **«правь репозиторий и раскатывай `skill-deploy.sh`; обратно не копировать»**.
4. Отдельной строкой — предупреждение, что **аккаунтную копию скрипт проверить не
   может**: она сверяется только глазами в Customize → Skills, поэтому пакет
   загружать сразу после раскатки.

`chmod +x`.

---

## ЗАДАЧА 4: Закрепить правило в двух контрактах

Чтобы через месяц никто (включая нас) не начал править копии напрямую.

### 4.1 `CLAUDE.md` — новый раздел «Память проекта»

Добавить после раздела «Жёсткие правила», коротко:

- Память проекта — скилл `crm-architect`, **источник истины: папка `crm-architect/`
  в этом репозитории**.
- Правки памяти идут тем же PR, что код, и проходят гейт как обычный дифф.
- Применение: `scripts/skill-deploy.sh` (репо → `~/.claude/skills/` + `.skill`-пакет),
  проверка: `scripts/skill-verify.sh`. Направление одно; обратной синхронизации нет.
- `~/.claude/skills/crm-architect/` и аккаунтная копия — **производные**, править их
  напрямую запрещено: правка не переживёт следующую раскатку и не попадёт в ревью.
- Журнал Claude Code (`~/.claude/projects/…/memory/`) остаётся вне git — это хроника
  спринтов; общие правила из него переносятся в `references/learnings.md`.

### 4.2 `crm-architect/SKILL.md` — дополнить раздел про память

Раздел «Две памяти, и Cowork видит только одну» переименовать в **«Три хранилища
памяти и одно направление»** и дописать:

- перечисление трёх экземпляров (репо-источник, локальная копия CC, аккаунт для Cowork);
- схему раскатки из шапки этого спринта;
- прецедент 2026-08-05 одной фразой — почему правило появилось;
- правило: **после любой правки памяти — `skill-deploy.sh` и загрузка пакета в аккаунт;
  иначе гейт работает по старой версии.**

## ЗАДАЧА 5: `crm-architect/README.md`

Короткий файл (≤ 25 строк) для того, кто откроет папку впервые:

- что это (память проекта, читается Claude Code и Cowork);
- три команды: раскатать, проверить, где взять пакет для аккаунта;
- явное «правь здесь, не в `~/.claude/skills/`»;
- список файлов одной строкой на каждый: назначение `SKILL.md` и четырёх `references/*`.

## ПРОВЕРКА

```bash
# 1. Скрипты исполняемые и не падают на чистом прогоне
./scripts/skill-deploy.sh
./scripts/skill-verify.sh          # ожидание: «идентичны», код 0

# 2. Расхождение действительно ловится
echo "# проверка расхождения" >> ~/.claude/skills/crm-architect/SKILL.md
./scripts/skill-verify.sh || echo "OK: расхождение поймано"
./scripts/skill-deploy.sh          # раскатка чинит
./scripts/skill-verify.sh          # снова идентичны

# 3. Пакет собран и НЕ в git
ls -la crm-architect.skill && git status --porcelain | grep -c "\.skill" # ожидание 0
unzip -l crm-architect.skill       # SKILL.md + references/4 файла, без .DS_Store

# 4. Бэкап создан
ls -la ~/.claude/skills/.backup/

# 5. В репо приехали именно файлы, а не мусор
git status --porcelain crm-architect/
find crm-architect -name ".DS_Store"   # ожидание: пусто
```


В отчёте: что легло в репо (файлы + строки), тексты обеих санити-проверок при
намеренно испорченном источнике, вывод `skill-verify.sh` в обоих состояниях,
путь созданного бэкапа. Отдельно — **напоминание владельцу загрузить
`crm-architect.skill` в Customize → Skills**: без этого шага Cowork продолжит читать
версию, которая была в аккаунте на момент спринта.
