# Claude Code Fix — Gantt: последовательный порядок бакета «Без дат»

Проблема (Олег, прод): в Gantt задачи в бакете «БЕЗ ДАТ» идут вразнобой (4.1, 3.1, 5.1, 2.1, 6.1, 4.2 / 1.2, 2.2, …) — искать нужную невозможно. Причина: массив `undated` в `useProjectSchedule` (`src/lib/hooks/use-project-schedule.ts`, ~L158–163) наполняется в порядке выборки из БД, без сортировки. Датированные свимлейны сортируются `bySpan` (по дате — для Ганта корректно, НЕ трогать). **Миграций нет, чистый клиент.**

Контекст: номер этапа (1.1, 4.2, …) живёт в ТЕКСТЕ задачи (`task.text`), т.к. `wbs_code` на живых delivery-проектах пустой (WBS не проставлен). Порядок, который ждёт пользователь: 1.1, 1.2, …, 1.8, 2.1, 2.2, … (натурально по номеру).

## ФИКС
Отсортировать `undated` натурально (numeric-aware), чтобы «1.2» < «1.10» < «2.1». Ключ — `wbs_code` если заполнен, иначе `text` (номер в начале текста):
```ts
// в useProjectSchedule, ПЕРЕД return (после наполнения undated):
const sortKey = (t: Task) => (t.wbs_code && t.wbs_code.trim()) ? t.wbs_code : t.text;
undated.sort((a, b) => sortKey(a).localeCompare(sortKey(b), 'ru', { numeric: true }));
```
`{ numeric: true }` даёт натуральный порядок (1.2 перед 1.10, 1.x перед 2.x). Стабильность: `Array.sort` в V8 стабильна — задачи с одинаковым ключом сохранят исходный порядок.

Альтернатива (если хочется группировать строго по фазам, а не по номеру в тексте): вторичный ключ — `column.position`, потом номер. НО на этих данных номер в тексте уже совпадает с фазой (Обследование=1.x, Моделирование=2.x…), так что натуральной сортировки по тексту достаточно и она робастнее к незаданному wbs_code. Не усложнять без нужды.

**НЕ трогать:** `bySpan` и порядок датированных свимлейнов (Гант по дате — правильно); `buildTree`; фильтры.

## EDGE CASES
- Задача без номера в начале текста → сортируется среди прочих по тексту (приемлемо).
- `wbs_code` заполнен у части задач → у них ключ wbs_code, у остальных text; смешанный порядок возможен, но для v1 (wbs пуст везде) неактуально.
- Пустой бакет / все задачи датированы → sort no-op, не падает.
- Backward-compat: датированные лейны и всё остальное без изменений.
