## С чем согласен полностью

### 1. Свой запрос, одна колонка, без лимита

`useActivityLog` на активной сделке с аудитом полей (087) отдаст 50 последних событий и обрежет начало 30-дневного окна. Пульс показал бы ложную тишину слева. `select('created_at')` + `gte` + без лимита — правильная граница. `staleTime` 60 с и без realtime — тоже: одна новая строка график за месяц не меняет.

### 2. Чистая функция, `now` аргументом, дни без дыр

30 календарных дней без пропусков — смысл виджета. `Date.now()` внутри запрещён (урок `leadStaleness`). Пустой вход → 30 нулей, не падать. Хвост тишины считается — иначе «не писали 11 дней» исчезнет, потому что разрыв «не завершён».

### 3. Не `--accent`

В `t-washi` акцент равен `--red`. Активный день тепловой полосы не должен выглядеть ошибкой. Спринт это фиксирует.

### 4. Скрытие однодневной сделки без событий

Пульс на сделке «создана сегодня, журнал пуст» — шум. На сделке «создана 20 дней назад, журнал пуст» — как раз картина тишины. Условие в задаче 3.5 сформулировано узко («создана сегодня») — так и оставить, см. W3.

### 5. a11y: svg `aria-hidden` + числа рядом

График не носитель уникального смысла. Скринридеру нужны total / тишина / последнее, не path.

### 6. Тесты поведением, включая пару дней и границу 23:59 МСК

Набор кейсов правильный. Именно поэтому хелпер дня обязан быть тем, которым эта граница реально считается.

## Блокеры (критично — исправить до запуска)

### B1. Для бакетов дней нужен `mskDateKey`, не `mskMinutesOfDay`

Спринт:

> 30 дней — календарные, граница дня по МСК (в проекте вся календарная ось на `mskMinutesOfDay`, см. `lib/domain/day-windows.ts`)

`day-windows.ts` — паспорт **свободного окна рабочего дня** (минуты от полуночи, 09:00–18:00, минимум 45 минут). Карта W3 сама предупреждает: «переиспользовать осторожно, это календарная неделя, не 14-дневная шкала».

Ключ дня сделки:

```102:105:src/lib/utils/date-helpers.ts
export function mskDateKey(input: string | Date): string {
  const d = typeof input === 'string' ? new Date(input) : input;
  return new Intl.DateTimeFormat('en-CA', { timeZone: 'Europe/Moscow' }).format(d);
}
```

Им уже считают сегменты, задачи, просрочку. `mskMinutesOfDay` на ISO 23:59 МСК вернёт `1439`, а не `'YYYY-MM-DD'`. CC, пошедший в `day-windows.ts`, либо притащит недельную рамку, либо свалится в UTC-`slice(0,10)` — и кейс «23:59 МСК» станет ложнозелёным.

Сигнал `silence` считает **86400000 мс**, не календарный МСК-день (`deal-signals.ts:261`). Пульс с `mskDateKey` и сигнал будут расходиться на границе суток — это нормально и в отчёт не надо «выравнивать».

**Вклеить в задачу 1:** бакет дня = `mskDateKey(created_at)` из `lib/utils/date-helpers.ts`. `day-windows.ts` не импортировать.

## Предупреждения (желательно исправить)

### W1. 16 точек при 30 днях / 2 — офф-бай-ван спеки

Спека и спринт: «16 точек = 30 дней / 2». 30/2 = **15**. SVG макета: `M0 … L300` шаг 20 → 16 вершин (15 отрезков × 2 дня = 30). Классический счёт «точек вместо интервалов».

Тест «точка суммирует пару дней» честно даёт 15 чисел.

**Решение в спринт одной строкой:** `points.length === 15` (пары дней 0–1 … 28–29). SVG: `viewBox="0 0 280 46"` либо шаг `300/14` на 15 точек. Не паддить 16-м нулём — график сожмёт последнюю пару. В отчёте: «спека 16 — офф-бай-ван, делаем 15».

### W2. Подпись «Дни без активности · N дн.» берёт 14 дней, домен отдаёт 30

Задача 3.4: «число из `longestSilence` **в пределах этих 14 дней**». Интерфейс `DealPulse` имеет один `longestSilence` на всё окно. CC возьмёт 30-дневный разрыв и напишет «14 дн.» под полосой из 14 клеток — или наоборот.

Либо второй проход в домене (`silence14` по `days.slice(-14)`), либо виджет сам считает по хвосту. Зафиксировать: заголовок полосы = макс. разрыв **внутри 14**, спарклайн-подпись «тишина N дн.» = разрыв **за 30**, если `>= 3`.

### W3. Аналог «как PinnedNoteCard» не скрывается

`PinnedNoteCard` всегда на месте — редактор и есть пустое состояние. Правило «пульс без событий на однодневной сделке не рисовать» оставить, аналог вычеркнуть.

Явно: `total === 0` и `mskDateKey(created_at) === mskDateKey(now)` → `return null`. `total === 0` у сделки старше дня → виджет из нулей (это и есть тишина).

Карта W7 утверждает «пусто → виджет не рисуется» про закреплённое — это ошибка карты, не этого спринта.

### W4. Не склеивать N пульса с порогом `silenceDays`

Разведка просит «порог не должен разъехаться с подписью». Это разные ответы: сигнал — «тише порога org (10 дн.)?»; пульс — «какой был самый длинный разрыв». Подпись пишет измерение, не порог. Если N=4, сигнал ещё `ok` — так и должно быть. В задаче 3.3 порог отрисовки подписи `>= 3` оставить локальным, в `DEFAULT_SIGNAL_THRESHOLDS` не лезть.

### W5. Ступени полосы без `--lime`

Спека: surface-2 / lime-soft / lime / green. `--lime` в продукте нет (тема `minimal` / `t-lime` тоже на `--green`). Карта: «цвета читать по decisions, не по спеке».

```
0  → var(--surface2)
1  → color-mix(in srgb, var(--green) 22%, var(--surface))
2  → color-mix(in srgb, var(--green) 45%, var(--surface))
3+ → var(--green)
```

Прогнать `audit-contrast.py`. Не копировать `#C9F25A` / `#4C8A0B` из HTML спеки.

### W6. `RailCard` требует иконку

Спека шапки без иконки. Примитив — `icon: LucideIcon` обязателен. Взять `Activity` (уже в файле рельсы) в `title="Пульс · 30 дней"`, мета — в `action`. Не пилить второй заголовок.

### W7. Фильтр `event_type`

`useActivityLog` режет `TRANSITION_METRIC_EVENT`. Хук пульса этого не говорит. Метрика переходов и `automation_fired` набьют клетки без человеческого касания. Минимум — тот же `neq` на техническое событие перехода. Остальное (аудит полей 087) — события сделки, пусть входят: это и есть «как шла».
