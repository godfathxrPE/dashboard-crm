# Claude Code Prompt — Sprint S-TG-VOICE-1: голосовое сообщение как вход в быстрый ввод

## Контекст и цель

**Требует влитого S-TG-TASK-1.** Надиктовываешь боту голосовое — бот расшифровывает
и показывает ту же карточку разбора, что и на текст. Задача, контакт, компания —
всё, что уже умеет `ai-capture`.

### Здесь НЕТ никакого разбора

Спринт добавляет ровно одно: превращение голоса в текст. Дальше текст уходит в
**существующую** ветку свободного текста без единой развилки «а это из голоса».

Если в диффе появилась логика вида «для голосовых разбираем иначе» — значит что-то
делается неправильно. Голос — второй вход в ту же трубу, а не второй разбор.

| Компонент | Статус |
|---|---|
| `transcribe` (ASR на Groq Whisper, нарезка, вычитка) | ✅ прод (S-R3-VOICE-1, S-FIX-VOICE-1) |
| `ai-capture` с интентами contact/company/task | ✅ после S-TG-TASK-1 |
| `telegram-webhook`, ветка свободного текста, черновики, кнопки | ✅ прод |

Миграции в спринте **нет**.

## ИНВАРИАНТЫ

1. **Ветка `voice` заканчивается на строке текста.** Она вызывает ту же функцию
   обработки, что и `message.text`, — не копию её тела. Две ветки «разобрать и
   показать карточку» разъедутся при первой правке.
2. **Молча не создаётся ничего.** Как и на тексте: расшифровка → карточка → кнопка.
3. **Сбой на нашей стороне и «не разобрал речь» — разные сообщения.** Пустой
   транскрипт («тишина, ничего не распознал») предлагает повтор; отказ `transcribe`
   говорит «это на нашей стороне». Склейка двух исходов в одну строку уже стоила
   часа на балансе Claude API.
4. **Токен бота не попадает в логи.** URL скачивания файла содержит его целиком —
   логировать можно `file_path`, но не собранный URL.

## ЗАДАЧА 1: Ветка `message.voice`

**Порядок веток обязателен:**
secret-token → идемпотентность по `update_id` → `/start` → `callback_query` →
**`voice`** → свободный текст.

`voice` идёт перед текстом, но после команд: у голосового апдейта поля `text` нет
вовсе, так что перепутать нельзя, — порядок фиксируется ради предсказуемости, а не
ради разбора.

Обрабатывается **только `message.voice`.** `audio` (присланный музыкальный файл),
`video_note` (кружок) и `document` — вне скоупа: у них другой сценарий и другой
размер. На них отвечать нейтрально («Пришлите голосовое сообщение или текст»),
а не молчать.

### Алгоритм

1. Резолв `from.id` → профиль. Нет привязки → «Профиль не привязан» и выход.
2. **Лимиты, до скачивания:**
   - `voice.duration > 180` (3 минуты) → «Слишком длинное голосовое, пришлите
     покороче или текстом». Три минуты — не техническая граница, а смысловая:
     быстрый ввод длиннее трёх минут это уже не быстрый ввод, а расшифровка
     встречи, для которой в CRM есть свой путь;
   - `voice.file_size` больше порога `transcribe` → тот же отказ. Порог **взять из
     константы функции, а не вписать числом**: чужая граница, переписанная руками,
     разъедется с оригиналом (в `trans-app` так приехали вериселевы 4.5 МБ, выданные
     за лимит Groq).
3. **«Расшифровываю…»** отправить сразу, `message_id` сохранить. Молчание бота на
   несколько секунд читается как поломка.
4. `getFile(voice.file_id)` → `file_path` → скачать
   `https://api.telegram.org/file/bot<TOKEN>/<file_path>` в `ArrayBuffer`.
   ⚠️ Собранный URL в лог не писать — в нём токен.
5. Отдать в `transcribe`:

```typescript
const fd = new FormData()
fd.append('file', new Blob([bytes], { type: 'audio/ogg' }), 'voice.oga')
// Content-Type НЕ выставлять руками: FormData сам проставит boundary
const { data, error } = await service.functions.invoke('transcribe', { body: fd })
```

Telegram отдаёт голосовые в **Ogg/Opus**, Groq принимает `ogg` напрямую —
перекодировать не нужно и нечем: ffmpeg в Deno Edge Runtime нет.

6. `editMessageText` → «Разбираю…» → дальше **та же функция**, что обрабатывает
   `message.text`. Если она сейчас не вынесена — вынести (одна правка, оба
   вызывающих), а не копировать тело.

### Исходы, каждый со своим текстом

| Исход | Ответ |
|---|---|
| Текст распознан | дальше по общему пути → карточка разбора |
| Пусто / только субтитровые штампы | «Ничего не разобрал — тихо или слишком коротко. Попробуйте ещё раз» |
| `transcribe` вернул ошибку | «Расшифровка временно недоступна — это на нашей стороне. Сообщите администратору CRM» |
| Длиннее лимита | «Слишком длинное голосовое (N сек). Пришлите покороче или текстом» |

Второй и третий — **разные строки**. Первый предлагает повтор, потому что повтор
может помочь; третий его не предлагает, потому что не может.

⚠️ Пустой результат проверять **после** фильтра штампов: `whisper-large-v3` обучен
на субтитрах и на тишине выдаёт «Продолжение следует…» — формально непустой текст,
который уедет в `ai-capture` и превратится в задачу «продолжение следует».

## ЗАДАЧА 2: Вызов `transcribe` из вебхука

У бота нет пользовательского JWT — вызов идёт service-ключом.

Развилка (решается **одним curl, без секретов**): POST с заведомо невалидным телом.
**400** от тела функции значит, что шлюз пропустил; **401** — что не пропустил.

Ослаблять `verify_jwt` у `transcribe` **запрещено** — она открыта из браузера.
Не проходит service-ключ через `functions.invoke` — звать прямым `fetch` с
`Authorization: Bearer <SERVICE_KEY>`. Тот же порядок действий, что для `ai-capture`
в S-TG-3, где service-ключ прошёл.

### Prompt для Whisper

Whisper принимает `prompt` до 224 токенов — туда доменный глоссарий (Честный ЗНАК,
ЧЗ, ГИС МТ, УПД, ЭДО, 1С:ERP, Клеверенс). Без него термины приезжают на слух и
«ГИС МТ» становится «гизэмте».

Глоссарий **уже есть** в `transcribe` (S-R3-VOICE-1) — проверить на разведке, что он
применяется и к одиночному файлу, а не только к нарезанным чанкам. Если только к
чанкам — это дефект в существующем коде: зафиксировать в отчёте и починить точечно,
не переписывая функцию.

## ЗАДАЧА 3: Состояние на стороне Telegram

Голосовые приходят как `message` с полем `voice`, то есть отдельного типа апдейта
для них нет и `allowed_updates` менять не требуется.

Проверить это фактом, а не рассуждением:

```bash
curl -s "https://api.telegram.org/bot$TG_TOKEN/getWebhookInfo" | jq
```

Смотреть **все поля**, не `ok: true`: `allowed_updates`, `pending_update_count`,
`last_error_message`, `last_error_date`.

Причина отдельной задачи: `allowed_updates: ["message"]` уже стоил эпику Telegram
самого дорогого инцидента — `callback_query` отбрасывался **на стороне Telegram**,
без единого следа в логах edge, и картина не отличалась от «пользователь не нажимал
кнопку». Отдельная ловушка: повторный `setWebhook` без `allowed_updates` сохраняет
прежний список, а не открывает всё.

Если в списке `message` отсутствует — перерегистрировать вебхук **с явным полным
списком** и прочитать `getWebhookInfo` обратно. Это операция гейта, в спринте её
**не выполнять**: описать в отчёте командой, готовой к запуску.

⚠️ Токен в командах отчёта — переменной `$TG_TOKEN`, не значением.

## Что здесь сознательно НЕ делается

- **Веб-микрофон в `QuickCapture`.** За компьютером с открытой CRM набрать текст
  быстрее, чем говорить и ждать распознавания; ценность голоса — там, где клавиатуры
  под рукой нет. Вернуться, если появится спрос.
- **Хранение аудио.** Голосовое остаётся в Telegram, у нас живёт только текст в
  `source_text` черновика. Складывать `.oga` в Storage без запроса — платить за
  хранение того, что уже хранится бесплатно.
- **Вычитка транскрипта LLM.** Для реплики на 20 секунд это второй вызов модели ради
  запятых: `ai-capture` разбирает и неотредактированный текст. Пересмотреть, если
  разбор начнёт промахиваться из-за пунктуации.
- **Мультиразбор** («три задачи одним голосовым») — ограничение `ai-capture` v1,
  а не голосового ввода.
