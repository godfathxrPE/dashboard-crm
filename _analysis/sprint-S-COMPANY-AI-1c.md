# Claude Code Prompt — S-COMPANY-AI-1c: снимать теги цитирования вместо просьб не писать их

Мини-спринт по следам трёх прогонов на promptVersion 2. Миграций нет, схема не меняется,
реген не нужен. Ветка: `feat/company-ai-1c` от `feat/company-ai-1b` (`0f0b359`);
если 1b уже в `main` — от `main`, сверить `git log --oneline -1 main`.

## Что установлено фактом

Причина ретраев — **`<cite index="7-5">…</cite>`**: механизм цитирования web search API
Anthropic. Модель размечает им, откуда взяла факт. Это её служебный формат, а не грязь
со страниц, поэтому промпт его не убирает — только снижает вероятность.

Замер на трёх прогонах promptVersion 2 (против четырёх из пяти на v1):

| компания | duration | in_tokens | retried | `<cite>` в результате |
|---|---|---|---|---|
| Хороший вкус | 43 с | 74 892 | — | нет |
| Дружба Народов Нова | 53 с | 85 937 | — | нет |
| КМ | 68 с | 83 353 | ✓ | **да, обе попытки** → `shape_warning`, сырые теги в UI |

Промпт снизил частоту (4/5 → 1/3), но снял гарантию: у «КМ» разметка пережила ретрай
и доехала до пользователя. Вероятностное средство против вероятностной проблемы не
даёт гарантии — нужен детерминированный слой.

⚠️ `SHAPE_MARKERS` по-прежнему НЕ ТРОГАТЬ. Маркер `</` работает правильно: он и поймал
эти теги. Мы убираем не сигнал, а его источник — до того, как форма проверяется.

## ЗАДАЧА 1 — `stripCiteTags` в `shape.ts`

Функция живёт рядом с остальной работой над формой ответа и остаётся ЧИСТОЙ
(ни Deno, ни сети) — иначе её не покрыть vitest, как и весь модуль.

```ts
/**
 * Снимает теги цитирования web search (`<cite index="7-5">текст</cite>`), сохраняя
 * текст внутри. Рекурсивно по всем строковым значениям результата.
 */
export function stripCiteTags<T>(value: T): T
```

Требования к реализации:

- Регулярка снимает **только** `cite`: открывающий тег с любыми атрибутами и закрывающий.
  Ничего другого не трогать — `<` и `>` в тексте (диапазоны, «выручка > 1 млрд») обязаны
  выживать. Не писать «универсальный HTML-стриппер»: он съест легитимный текст.
- Обход рекурсивный, как `forEachString`: строки, массивы, объекты. Возвращается НОВАЯ
  структура, вход не мутируется (результат модели — единственная копия данных прогона).
- Осиротевший закрывающий `</cite>` без открывающего тоже снимается: модель обрывает
  разметку на границе `max_tokens`, и половина тега — самый вероятный случай.
- Схлопывать двойные пробелы, образовавшиеся на месте снятых тегов, но не трогать
  переводы строк.

**Тесты** (в `tests/unit/` рядом с существующими тестами формы):
`<cite index="7-5">текст</cite>` → `текст`; тег внутри элемента массива и внутри
вложенного объекта; осиротевший `</cite>`; строка без тегов не меняется вовсе (сравнение
по ссылке допустимо, но не обязательно); `«прибыль > 100 млн»` и `«2024 < 2025»` не
повреждаются; `null`/число/boolean проходят насквозь.

## ЗАДАЧА 2 — чистить до проверки формы

В `processRun`, для пресетов с `preset.webSearch`, прогонять `input` каждой попытки
через `stripCiteTags` **ДО** `checkResultShape`:

- первая попытка — до `claims = checkResultShape(...)`;
- вторая — там же, симметрично;
- дальше по коду идёт уже очищенный `input`, и в `result` попадает он же.

Для пресетов без `webSearch` ничего не менять: у них цитат нет по определению, а лишний
обход результата — трата на ровном месте.

⚠️ Порядок принципиален. Чистка ПОСЛЕ проверки не убрала бы ретрай (претензия уже
выставлена), чистка ПОСЛЕ записи в БД не убрала бы теги из UI. Только «до».

Ожидаемый эффект: ретраи по причине `</` в брифах исчезают полностью, `shape_warning`
с этой формулировкой больше не появляется, сырых тегов в карточке нет.

## ЗАДАЧА 3 — сократить абзац «ФОРМАТ ЗНАЧЕНИЙ»

После детерминированной чистки длинное требование в промпте бессмысленно: оно съедает
внимание модели, а гарантию всё равно даёт код. Оставить одну строку:

```
В текстовых полях — только чистый текст: ссылки ставь в source_url / url / sources,
в прозе URL не вставляй.
```

Часть про URL в прозе сохраняем — она про другое (читаемость брифа), и к цитатам
отношения не имеет.

**`promptVersion: 2 → 3`** — та же конвенция: сравнение прогонов в журнале.

## ЗАДАЧА 4 — перезамерить `WEB_RUN`

Константы оценки писались по двум прогонам и занижают вход вдвое. Факт по пяти
прогонам v2/v1 без ретрая: **75–86К входных токенов**, 2–3К выходных, 4–5 поисков.

```ts
const WEB_RUN = { inTok: 80_000, outTok: 3_000, searches: 5, retryInTok: 45_000 };
```

`retryInTok` оставить как есть — это добавка второй попытки, она замерена отдельно
и после Задачи 2 будет срабатывать редко. В комментарии обновить дату замера и число
прогонов, на которых он сделан.

Диапазон на кнопке пересчитается сам; проверить, что он остался правдоподобным
(ожидание — примерно «30–45 ₽»). Хардкодить числа в JSX по-прежнему нельзя.

## ЧЕГО НЕ ДЕЛАТЬ

- Не трогать `SHAPE_MARKERS`, `checkResultShape`, `retryTurn`, `callClaudeWithSearch`.
- Не писать общий HTML-стриппер и не снимать никакие теги, кроме `cite`.
- Не пытаться превратить `index="7-5"` в ссылку на источник: индекс указывает на
  результат поиска внутри ответа API, сопоставить его с URL из `sources` нечем.
- Не менять остальной промпт `company_brief` (блок про `chz_signals` — особенно).
- Не править данные в проде.
