# Claude Code Prompt — chore(skills): мерж через PR и канал доставки в sprint-prompt-builder

Контекст: в `sprint-prompt-builder/SKILL.md` (v2.2 → v2.3) фиксируются три правила:
мерж в main только через PR (main защищён required check `checks`, прямой push даёт GH013);
спринт-файл коммитится в ветку спринта; единый канал доставки спринта вместо противоречия
«блок в чат» / «файл в _analysis/». Меняется только `sprint-prompt-builder/SKILL.md`

## ЗАДАЧА 1: ветка от origin/main

```bash
git checkout -b chore/sprint-prompt-pr-flow origin/main
git branch --unset-upstream 2>/dev/null; true
```

Ветка создаётся от `origin/main`, а не от текущей ветки сессии. Upstream снимается:
иначе ветка будет считать своим upstream `origin/main`, и `git push` без аргументов нацелится в main.

### 3.4 Абзац «Мержит только Олег» → стандартный блок мержа

old:
~~~~
**Мержит только Олег.** Скилл не предлагает «я закоммичу» — он выдаёт вердикт и список
действий руками.
~~~~
new:
~~~~
**Мержит только Олег, через PR.** Скилл не предлагает «я закоммичу» — он выдаёт вердикт и список
действий руками. При вердикте «принято» последний пункт «Твоих действий» — стандартный блок
мержа. Гейт подставляет реальные значения из отчёта CC (ветка, путь worktree, заголовок)
и отдаёт блок **целиком, одним куском**: Олег не собирает его из двух сообщений.

```bash
cd <корень репо> &&
git push -u origin <ветка> &&
gh pr create --base main --head <ветка> --title "<conventional commit>" --body "<1–2 строки>. Спринт-файл: _analysis/<имя>.md" &&
sleep 20 &&
gh pr checks <ветка> --watch &&
git worktree remove <путь worktree> &&
gh pr merge <ветка> --merge --delete-branch &&
git checkout main &&
git pull
```

`&&` останавливает блок на первом упавшем шаге. Красный `checks` — стоп, вывод несут на гейт.
`sleep 20` даёт CI зарегистрировать проверки: сразу после `gh pr create` команда `gh pr checks`
отвечает «no checks reported» и рвёт цепочку.
Worktree удаляется до `gh pr merge`: иначе `--delete-branch` не удалит ветку, занятую worktree.
Работа шла без worktree — строку `git worktree remove` гейт убирает.
~~~~

## ОТЧЁТ

## ОТЧЁТ

Финальный ответ в чат — строго в этом формате. Стиль STE-lite:
- Предложение ≤ 20 слов. Одно предложение — один факт или одно действие.
- Активный залог, прошедшее время: «добавил индекс», не «индекс был добавлен».
- Один термин = одно значение. Сущности называй как в коде: имя файла, таблицы, функции.
- Без оценок: «отлично», «полностью», «успешно», «готово к проду» — запрещены.
  Вместо оценки — артефакт: число, вывод команды, exit code.
- Не больше 3 существительных подряд. Без цепочек «осуществление проведения проверки».
- Списки вертикальные, вложенность ≤ 1 уровня.

Сделано
- `путь/к/файлу` — что изменено. Одна строка на файл или на одно изменение.

Проверки
- `команда` → результат (0 ошибок tsc · 42 теста passed · build exit 0).

Не сделано
- Что пропущено и почему. Пусто → «—».

Отклонения от спринта
- Где сделал иначе, чем в файле спринта, и почему. Пусто → «—».

Вопросы и риски
- Не больше 3 пунктов. Пусто → «—».

Дополнительно для этого спринта: последней строкой «Сделано» укажи ветку и путь worktree
из `git worktree list` (или «без worktree») — гейт подставит их в блок мержа.
