# Claude Code Prompt — S-MEM-1: расщепить learnings.md на справочник и журнал

**Контекст.** Разведка памяти 21.08 (после S-REL-1):

| Файл | Размер | Что внутри |
|---|---|---|
| `crm-architect/SKILL.md` | 19,7 КБ | грузится ВСЕГДА при активации скилла |
| `references/learnings.md` | **166 КБ / 1866 строк** | см. ниже |
| `references/architecture.md` | 80,9 КБ | |
| `references/theme-system.md` | 29,9 КБ | |
| `references/schema.md` | 6,5 КБ | указатель, не схема |

`learnings.md` состоит из двух разных вещей:

- **строки 1–576 (47 КБ, 28%)** — тематический справочник: Supabase, Multi-tenancy & RLS,
  Auth, CSS & Themes, Z-Index, React/Next.js, CSV Export, Sprint Prompt Writing, Common Patterns
- **строки 577–1866 (119 КБ, 72%)** — **22 хронологических раздела** «Уроки 2026-08-XX (S-XXX)»,
  по одному на спринт, растут линейно и никогда не сжимаются

Проблема не в размере, а в организации: **файл написан как журнал, а читается как справочник.**
Чтобы найти «как мы делаем RLS», надо пройти двадцать разделов «Уроки от такого-то числа».
При 166 КБ файл не читается целиком — ни человеком, ни агентом; читается начало и обрывается.
Это та же болезнь, что была у роадмапа до ревизии 09.08, и лечится тем же: разделить
по назначению. Плюс хронология уже записана вторично — в `_analysis/sprint-*.md` и `gate-*.md`.

**Scope — сознательно механический.** Этот спринт **не переписывает ни одной строки текста**.
Он режет файл по существующей границе разделов и чинит ссылки. Содержательный разбор
(поднять переиспользуемое из журнала в тематику) — отдельный спринт S-MEM-2, после этого.
Причина такого деления: правка собственной памяти агента — операция с риском потери знания,
и первый шаг обязан быть **обратимым и проверяемым побайтово**.

⚠️ **Ничего не удалять.** Весь текст переезжает целиком. Проверка в ЗАДАЧЕ 3 — побайтовая.

## ЗАДАЧА 1: создать `references/journal.md` из хронологической части

### Context
Хроника спринтов сохраняется полностью, но переезжает в отдельный файл, который читается
по требованию — а не мешает читать справочник.

### Steps
1. Определи `N` — номер строки первого хронологического раздела (из разведки).
2. Создай `references/journal.md`:
   - шапка (написать руками, не копировать):
     ```markdown
     # Журнал спринтов — dashboard-crm

     Хроника уроков по спринтам, от старых к новым. Выделен из `learnings.md` в S-MEM-1
     (2026-08-21): файл разросся до 166 КБ, из них 72% — эта хроника, и справочник перестал
     читаться целиком.

     **Читать:** когда нужен контекст конкретного спринта или эпика — «что мы решили
     в S-TG-2», «почему у голоса такая нарезка». Для общих граблей перед новым спринтом —
     `learnings.md`, там тематика.

     **Писать:** урок спринта пишется сюда. Если урок переиспользуемый — не пересказывать
     его целиком в `learnings.md`, а добавить туда одну строку в тематический раздел
     со ссылкой на раздел журнала.

     ---
     ```
   - далее — **дословно** строки `N`…конец файла `learnings.md`, без единой правки.
3. В `learnings.md` оставь строки `1`…`N-1`, дописав в конец:
   ```markdown

   ---

   ## Хроника спринтов

   Уроки по конкретным спринтам вынесены в [`journal.md`](./journal.md) (S-MEM-1, 2026-08-21).
   Здесь — только тематика, переиспользуемая между спринтами.
   ```

Делай через `sed -n` / `head` / `tail`, не переписывая текст руками — так исключается
случайная правка.

### Verification
```bash
wc -l learnings.md journal.md
grep -c '^## ' learnings.md
grep -c '^## ' journal.md
head -20 journal.md
```
Ожидается: в `learnings.md` — тематические разделы + «Хроника спринтов»;
в `journal.md` — 22 раздела хроники.

## ЗАДАЧА 3: побайтовая проверка, что ничего не потеряно

### Context
Единственная гарантия при работе с памятью — сверка с оригиналом, а не «выглядит правильно».

### Steps
```bash
cd crm-architect/references
git show HEAD:crm-architect/references/learnings.md > /tmp/orig.md
# тематическая часть нового learnings.md без дописанного хвоста + журнал без шапки
head -n -6 learnings.md > /tmp/part1.md
tail -n +12 journal.md > /tmp/part2.md
cat /tmp/part1.md /tmp/part2.md > /tmp/rebuilt.md
diff /tmp/orig.md /tmp/rebuilt.md && echo "СОВПАДАЕТ ПОБАЙТОВО" || echo "РАСХОЖДЕНИЕ — разбирать"
```

Числа `-6` и `+12` подогнать под фактическое количество дописанных/добавленных строк
(хвост «Хроника спринтов» и шапка журнала). Цель — чтобы `diff` дал пустой вывод.

⚠️ Если `diff` показывает расхождения кроме шапки и хвоста — **останавливайся и не коммить**,
опиши расхождение в отчёте.

### Verification
Вывод `diff` пустой. Если нет — задача не выполнена.

## Что НЕ входит и почему

- **Содержательный разбор журнала** (поднять переиспользуемое в тематику) — S-MEM-2.
  Требует чтения 22 разделов и решения по каждому; в одном спринте с механическим
  расщеплением это смешало бы обратимую операцию с необратимой.
- **`MEMORY.md` журнала Claude Code** (24,4 КБ, `~/.claude/projects/…/memory/`) — другое
  хранилище, вне репозитория и вне видимости гейта. Своя задача.
- **`architecture.md` 80,9 КБ** — второй кандидат на расщепление, но там доля хроники
  не измерялась. Мерить в S-MEM-2.
- **`SKILL.md` 19,7 КБ** — грузится всегда, на грани разумного. Сокращение — отдельно,
  после того как станет видно, что из него реально используется.
