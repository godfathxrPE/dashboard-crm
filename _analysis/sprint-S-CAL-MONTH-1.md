## ЗАДАЧА 1: данные ячейки и фокус-полосы — чистые функции

`src/lib/domain/month-cells.ts` (без React) + тесты:

```ts
/** Чипы ячейки: сортировка (дедлайны → по времени → без времени), срез до max. */
export function sliceCellChips<T extends { startMin: number | null; kind: string }>(
  events: T[], max?: number,            // default 2
): { visible: T[]; hiddenCount: number }

/** Дедлайны сделок месяца для фокус-полосы, отсортированы по дате.
    Прошедшие относительно today — с флагом overdue (в полосе краснее/жирнее). */
export function monthDeadlines(...)
```

Правила `sliceCellChips`: дедлайн всегда виден первым (не тонет в «+N»); при
`hiddenCount === 1` показывать третий чип, а не «+1 ещё» — строка той же высоты,
но информативнее. Тесты: пусто / 2 / 3 (третий виден) / 5 (2 + «+3») / дедлайн+4.

# ОТЧЁТ — S-CAL-MONTH-1

Ветка `feat/month-chips` от `main` (`4b12a16`). Миграций нет. Сделано всё
четыре задачи; два отступления от спеки и три находки — ниже, каждое с причиной.

## Что теперь на экране

Месяц занимает всю ширину: правой панели «Выберите дату» больше нет. События
видно чипами прямо в ячейке (иконка вида, время, название), над сеткой — полоса
«Фокус месяца» с дедлайнами сделок, день раскрывается peek-панелью справа.
Счётчик под датой и уголок-треугольник удалены вместе с их правилами в Aura.

Проверено на живых данных org: август 2026 — чипы в 6, 7, 10, 14, 17 (ровно те
дни, что названы в критерии приёмки); ячейка 6-го — 2 чипа и «+3 ещё», ячейка
17-го — три чипа без «+1»; дедлайн в ячейке 7-го стоит первым. Фокус-полоса —
`7 Ориент Продактс` (красным, дата прошла), `14 Перспектива`, три дедлайна 17-го.
Июль 2026 — звонки чипами с временем МСК (12:25, 08:15, 15:54).

## Разведка: чего в проекте не оказалось

Peek-примитив нашёлся — `src/components/shared/PeekPanel.tsx` (Sprint W2d,
единственный потребитель — `DataTable`). Escape и клик мимо он умеет, но
**возврата фокуса у него не было** — спека предполагала обратное («примитив это
уже умеет — проверить, не ломать»). Проверил, не умел; дописал.

Ещё две вещи примитив не умел, и обе всплыли на первом же прогоне:

- `href` был обязательным. У дня полной страницы нет — ссылка «Открыть
  полностью» вела бы в никуда. Сделал необязательным.
- Клик по другой ячейке закрывал панель вместо смены содержимого. У строки
  таблицы (`tbody tr`) исключение было зашито в код; вынес его в проп
  `keepOpenSelector`, календарь передаёт `[data-cal-day],[data-modal-overlay]`.

## Дефект в примитиве, который разбудил этот спринт

**`PeekPanel` роняла гидрацию всей страницы.** Портал рисовался по ветке
`typeof document === 'undefined' ? null : createPortal(...)` — то есть markup
сервера и клиента расходились по построению. Пока панель открывалась только
кликом по строке таблицы, в SSR она не попадала и дефект спал. Peek дня открыт
уже в первом рендере, если в адресе есть `?date=` — и «Hydration failed because
the server rendered HTML didn't match the client» вылезло на `/calendar?date=…`.

Симптом был обманчивым: React выбрасывал дерево и перерисовывал его, а в DOM
оставалась панель от неудавшейся гидрации — на экране висел паспорт **8 июля**
при `?date=2026-07-15` в адресе и правильном `dateKey="2026-07-15"` в дереве
React. Чинится не в календаре: ветка заменена на флаг `mounted` (портал после
монтирования). После правки консоль на том же адресе чистая, выбран 15-й.

## Задача 1 — домен

`src/lib/domain/month-cells.ts`, 17 тестов (`tests/unit/month-cells.test.ts`):

- `sliceCellChips` — порядок «дедлайн → по времени → без времени», срез до `max`.
  Правило «при одном спрятанном показывать третий чип, а не «+1 ещё»» выражено
  как `length <= max + 1`. Сортировка стабильная, вход не мутируется (тест есть).
- `monthDeadlines` — фильтр по префиксу `YYYY-MM`, число месяца, флаг `overdue`.
  Сравнение строк, а не арифметика с датами: ключи дня в проекте и так строки МСК.
  `todayKey` — параметром, иначе функция нетестируема (приём `daysSince`).
- `pluralEvents` — «1 событие / 2 события / 11 событий». Пришлось завести:
  счётчика в паспорте дня раньше не было, а `n === 1 ? … : …` врёт на 2–4 и на 21.

## Задача 4 — паспорт дня

`DayPeek.tsx` на `PeekPanel`: заголовок, строка «окно после 11:30 · 5 событий»
(`formatFreeWindow` из `day-windows`, счётчик через `pluralEvents`), «+N без
времени», три кнопки создания, карточки событий. Порядок карточек — тот же
`orderCellEvents`, что у чипов: показывать один день двумя порядками на одном
экране нельзя.

Peek **не закрывается** при открытии модалки (в отличие от `DataTable`, которая
гасит свою через `peekSuppressed`): после сохранения новое событие видно в том же
дне без повторного клика. Держится на `[data-modal-overlay]` в `keepOpenSelector`;
Escape при этом закрывает только модалку — её обработчик висит на `document` и
зовёт `stopPropagation`, а обработчик панели на `window`, то есть выше по потоку.
Проверено: Esc → закрылась модалка, панель осталась; Esc → закрылась панель,
фокус вернулся на ячейку «6 число».

## Два отступления от спеки

1. **Чип задачи оставлен тинтом `bg-yellow-l` из `KIND_META`, а не
   `surface`+border**, как написано в анатомии. Иначе выбор был между «неделя
   изменилась» (жёсткий пункт приёмки, назван дважды) и второй картой видов в
   проекте. Обе цены выше, чем нейтральный фон у задач.
2. **Aura: заливка `[data-selected]` переехала с ячейки на кружок даты.**
   `.t-aura .cal-day[data-selected]` заливала ячейку `var(--purple)` целиком и
   ставила `color: #fff` — правило писалось под ячейку-цифру 44px. На контейнере
   6.75rem с чипами оно клало их на насыщенный фиолетовый, то есть ломало пункт
   «чипы читаемы» из той же таблицы приёмки. Пилюля и кольцо сохранены один в
   один, но на `.cal-day-num`; сама ячейка получает подсветку `--surface2` и
   рамку. `[data-today]` — так же. Правила `.cal-day-dot` удалены (уголка нет).

## Три находки в коде, который трогал

- **Клик по чипу всплывал в ячейку.** Спека это предвидела (`stopPropagation`),
  я забыл — поймал в браузере: клик по чипу открывал модалку И peek под ней.
  `onClick` у `EventChip` теперь принимает событие целиком. Тем же порядком
  закрыт `keydown`: Enter на чипе внутри ячейки открывал ещё и паспорт дня, —
  обработчики ячейки и карточки в peek теперь слушают только себя
  (`e.target !== e.currentTarget`).
- **Месяц клал звонки и задачи в ячейку по UTC-дате** (`date.slice(0,10)`), а
  неделя — по МСК (`mskDateKey`). Звонок в 00:30 МСК попадал у месяца во
  вчерашний день. Пока в ячейке был счётчик, расхождение видно не было; на чипе
  печатается время, и оно стало бы заметно глазом. Перевёл на `mskDateKey`.
  `meetings.date` и `projects.deadline` — колонки `date`, у них срез и есть день.
- **«Сегодня» больше не открывает peek.** Раньше кнопка наполняла панель справа;
  теперь она бы распахивала поверх сетки целую панель, о которой не просили.

## Что осталось как было — сознательно

- **Задача с временем, но без срока, в месяц не попадает.** «19:05 Звонок» 8
  августа — это задача со `scheduled_start`; неделя показывает задачи по времени,
  месяц по `deadline`. Правило доспринтовое, менять его — менять смысл месяца.
- Два дедлайна в одном дне: первый закреплён, второй может уйти в «+N». Ячейка
  месяца не список дня — полный состав виден в паспорте.
