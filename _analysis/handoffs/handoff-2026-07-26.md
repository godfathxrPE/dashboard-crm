## Рабочий цикл — не менять

Я пишу спринт-файл → Grok ревьюит → я правлю → Олег отдаёт в Claude Code → Олег приносит
отчёт → Cowork-гейт (ревью дифа; при миграциях apply + gen-types + advisors + ролевые
смоки; независимая сверка данных SQL) → Олег мержит.

**Всё, что уходит в CC, оформляется файлом в `_analysis/`**, не текстом в чате: спринт —
`sprint-*.md`, правка по итогам гейта — `fix-*.md`. В чат идёт одна строка «прочитай файл
и выполни». Это требование Олега: из чата непонятно, что именно надо делать.

Claude Code никогда не применяет миграции и не трогает прод-БД: пишет
`supabase/migrations/0NN_name.sql` и коммитит, apply — только через Cowork-гейт.
`src/types/database.ts` и `supabase.gen.ts` руками не правятся. `.env` не читаем.
Отчёты о сделанном называть отчётом, не нумерованным планом с распределением ответственности.

## Ограничения инструментов (проверено)

- Мост монтирует репо в `/sessions/<id>/mnt/dashboard-crm`, на устройстве —
  `/Users/oleg/Downloads/dashboard-crm`. **Мост не умеет удалять файлы**; при жалобах git
  на lock — `rm -f .git/*.lock .git/objects/*/tmp_obj_*` + `git gc` руками на маке.
- **Юнит-тесты на устройстве не запускаются** (`node_modules` под macOS, `device_bash` —
  Linux). Цифры тестов идут со слов CC и в отчёте гейта помечаются как непроверенные.
- MCP-реген типов не отдаёт блок `graphql_public`, который отдаёт CLI — иначе в диф придут
  28 ложных удалений.
- Вывод `generate_typescript_types` (~90 КБ) и `get_advisors` (performance, ~60 КБ)
  в контекст не читать — парсить питоном из файла.
- CDP не водит pointer-события баров Ганта (`setPointerCapture` для синтетического
  указателя не срабатывает); координаты `computer` — в пространстве скриншота, не в
  CSS-пикселях, расхождение масштаба даёт промах ~10px.
- `npm run build` при живом `next dev` убивает dev-сервер. Билд гонять последним.
