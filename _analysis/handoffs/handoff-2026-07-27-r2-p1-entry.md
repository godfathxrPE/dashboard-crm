## Грабли, которые стоили времени именно в этой сессии

**`relacl` — массив `aclitem`, `like` по склейке врёт.** Метрика
`array_to_string(relacl,',') like '%authenticated=%m%'` даёт одинаковый результат до и после
`revoke`: `%` жадно матчит через запятую и находит букву в правах **соседней** роли
(`service_role=arwdDxtm`). Разбирать только поэлементно:

```sql
select count(*) from pg_class c
join pg_namespace n on n.oid = c.relnamespace,
     lateral unnest(coalesce(c.relacl,'{}'::aclitem[])) a
where n.nspname='public' and c.relkind='r'
  and a::text like 'authenticated=%'
  and split_part(split_part(a::text,'=',2),'/',1) like '%m%';
```

**`information_schema.role_table_grants` не показывает `MAINTAIN`** — вью стандарта SQL, а
привилегия нестандартная. Запрос `privilege_type='MAINTAIN'` вернёт 0 всегда, независимо от
реальности. Зеркальная ловушка к предыдущей: одна метрика ложно-зелёная, другая ложно-красная.

**`pg_get_functiondef()` падает на агрегатах** (`ERROR 42809 "array_agg" is an aggregate
function`), причём текст ошибки не связан с запросом. Любой фильтр по телу функции — с
`p.prokind = 'f'`.

**Ключ идемпотентности из `timestamptz` строить только через `to_char(… at time zone 'UTC',
'YYYY-MM-DD HH24:MI:SS.US')`**, не `::text` — иначе session `TimeZone`/`DateStyle` разводит
ключи cron-прогона (UTC) и ручного вызова (MSK), и правило стреляет дважды за одно пребывание.

**CTE не видит собственный INSERT.** `with ins as (insert …), upd as (update … where id =
(select id from ins))` — UPDATE отработает по 0 строк: snapshot транзакции. Смоки на
INSERT→UPDATE→DELETE гнать отдельными statement'ами.

**Живое тело DEFINER-функции всегда короче файла миграции** — Postgres не хранит комментарии
в `prosrc`. Сверять по логике, не по длине.

## Ограничения инструментов (дорогие, проверены на практике)

**Из сессии git-командами не коммитить вообще.** Каждый `git commit` с моста оставляет пустой
`.git/index.lock`, который мост удалить не может, и он блокирует **локальные** команды Олега
(«Another git process seems to be running»). Файлы класть через `device_commit_files` (следов
не оставляет), а `git add`/`commit`/`merge`/`push` делает Олег. Если лок появился — `rm -f
.git/index.lock` на маке. `git push` с моста невозможен: у локальной VM нет сети (403 от прокси).

**Мост не перезаписывает отслеживаемые файлы через git** — `git checkout`/`merge` падают с
`Operation not permitted`. Но `device_commit_files` пишет и в отслеживаемые файлы нормально.

**Деплой edge-функций — только `npx supabase functions deploy` у Олега.** Из сессии не делаю:
`deploy_edge_function` требует ретрансляции содержимого файла из контекста (623 строки), риск
тихого искажения в проде AI-контура выше выгоды. `supabase` не в PATH — нужен `npx`.

**Браузерные смоки: `ref` из `find` протухает после перерисовки.** Клик по устаревшему `ref`
попадает в оверлей и закрывает модалку. Правило: `find` → клик **сразу**, без промежуточных
скроллов; после re-render — новый `find`. Координатные клики через CDP не использовать
(масштаб скриншота ≠ CSS-пиксели). Два `window.confirm` в `GanttTimeline.tsx` блокируют смоки.

**Скилл `crm-architect`:** доставляется файлом, сохранение в аккаунт не подтверждается. Проверять
в новой сессии: если он говорит «применены 001–067» — не сохранился. Его
`references/schema.md` синхронизируется вручную копированием из репо.

## Рабочий цикл — не менять

Claude пишет спринт-файл → Grok ревьюит → Claude правит → Олег отдаёт в Claude Code → Олег
приносит отчёт → **гейт Cowork** (ревью дифа; при миграциях apply + advisors + ролевые смоки;
независимая сверка данных SQL) → Олег мержит и пушит.

Всё, что уходит в CC, — файлом в `_analysis/` (`sprint-*.md`, `fix-*.md`), в чат одна строка
«прочитай файл и выполни». CC не применяет миграции и не трогает прод-БД; `database.ts` и
`supabase.gen.ts` руками не правятся; `.env` не читаем.

### Структура ответа на гейте (принята в этой сессии)

**Итог** (одна строка: принято / принято с правками / отклонено) → **Что проверено** (факты с
доказательством: SQL-результат, версия, счётчик) → **Находки** (🔴/🟡/🟢, каждая: что, чем
грозит, что делать) → **Что я поправил** (правки, внесённые на гейте, и почему) → **Твои
действия** (нумерованный список, только руками) → **Дальше** (следующий шаг и развилка).

Пустые секции опускаются; «Итог» и «Твои действия» есть всегда. На коротких ответах структуру
не навешивать.
