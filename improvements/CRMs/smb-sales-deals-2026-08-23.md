## 1. Анатомия карточек

### 1.1 Close — Lead-хаб, активность-центричный

Карточка в Close — это **Lead (компания)**, а не сделка. Сделки (Opportunities) — виджеты внутри. Двухколоночный layout:

```
┌──────────────────────┬──────────────────────────────────┐
│ ЛЕВЫЙ САЙДБАР        │ ПРАВАЯ КОЛОНКА                   │
│ · Tasks (открытые)   │ · Lead status (сверху, inline)   │
│ · Opportunities      │ · Лента активности:              │
│   (карточки сделок)  │   звонки · письма · SMS · смены  │
│ · Contacts           │   статусов · задачи · заметки    │
│ · Custom Fields      │   — хронологически, единая       │
└──────────────────────┴──────────────────────────────────┘
```

- **Правая колонка = ствол карточки.** Вся переписка, звонки, смены статусов и заметки — одной хронологической лентой; сверху тогглы-фильтры «показать только заметки / только активность пользователя X».
- **Opportunities в сайдбаре** — карточки с value, статусом, привязанным контактом, комментарием. До 1 000 на Lead. Сортировка: активные первыми (по дате создания), затем закрытые won/lost по дате резолюции. Несколько сделок на клиента — это норма модели, а не хак.
- **Поля opportunity:** status (кастомизируемые, дефолт «Demo Completed / Proposal Sent / Contract Sent / Won / Lost»), **confidence %** (вероятность → Expected Value = value × confidence), value (one-time или recurring/MRR), estimated close date (при won превращается в actual), контакт, ответственный, notes (rich text с июня 2026), файлы (с июня 2026 — attach прямо в view mode).
- **Композер письма — прямо в ленте**: иконка email в шапке (дефолт — primary contact) или на карточке контакта; можно выбрать несколько получателей.
- **Новая карточка** — создаётся практически из одного имени Lead; сайдбар и лента заполняются по мере работы. Требуемых полей у opportunity фактически два — status и value [ESTIMATED — по докам creation-флоу подробно не расписан].

### 1.2 folk — минимальная сделка, живущая в таблице/канбане

folk — «CRM, которая работает за тебя»: карточка не страница, а **side panel** поверх таблицы или канбана.

- **Deal по умолчанию — 4 поля:** Status, Deal value, Deal owner, Closed at (+ системные Created at/by). Всё остальное — custom fields (select, date, member, number, text). Это осознанный выбор: пустая сделка не пугает формой.
- Deal связывается **многие-ко-многим** с людьми и компаниями (одна сделка — несколько людей и компаний), но только внутри одной группы.
- **Канбан:** карточки с настраиваемым набором видимых полей, сумма/каунт по колонке. **Таблица** — те же сделки строками. Dashboards — поверх.
- **Профиль сделки/контакта:** связи, Notes & Reminders (с @-упоминаниями и назначением), секция реминдеров по датам; прошедшие реминдеры остаются на профиле светло-серым.
- **AI-слой:** Recap Assistant (резюме отношений по письмам/встречам/LinkedIn — формат MEDDIC/BANT/custom, on-demand + refresh) — маркетинговое «1-line summary» профиля реализовано именно им [ESTIMATED — термин с сайта, механика — Recap]; Magic Fields — AI-колонки прямо в таблице; Follow-up Assistant — отдельная секция «Follow ups».
- **folkX (Chrome extension):** захват контактов из LinkedIn и 7+ платформ в один клик — вход в CRM без формы.

### 1.3 Copper — карточка, встроенная в Google Workspace

- **Запись opportunity:** обязательны только **Name + Primary Contact**; дальше projected close date, projected revenue, pipeline/stage, кастомные поля. Терминальные статусы — Won / Lost (с loss reason) / **Abandoned** («сделка в лимбе» — пауза по просьбе клиента, отдельно от проигрыша).
- **Письма прицепляются сами:** синк почты идёт иерархически — активность/письмо на **Person** автоматически расходится на связанные **Opportunity и Company**; активность на Opportunity — вверх на Company, но не на Person; на Company/Lead/Project — никуда. Письма между сотрудниками Copper не синкаются.
- **Gmail-sidebar** — вторая карточка сделки: открыл письмо → рядом контакт, история, сделки, задачи; добавление контакта/лида из письма; attach файлов из Drive по подсказке. С 2025 в расширении — полноценный композер и отправка.
- **Карточки на канбане:** настраиваемые «Opportunity Card Fields» (какие поля и в каком порядке); флаг **Slipping** (красный — сделка без активности дольше порога), **Top Deal** (зелёный $ — value выше порога).
- **Activity log:** 3 дефолтных типа (Phone Call, Meeting, To-do) + до 30 кастомных activity types с иконками и признаком «counts as interaction» — из него считаются interaction stats и «last contacted».
- Прогресс-бар стадий на самой записи opportunity [не подтверждено — в доках описан только stage в канбане и настройка карточек].

### 1.4 Nutshell — Lead (сделка) с направляющим процессом

У Nutshell «Lead» = сделка (соединяет людей/компании с пайплайном).

- **Поля:** value, **confidence %** (0–100), estimated close, stage/pipeline, products, sources, теги. Confidence задаётся вручную при создании, на Pro **автоматически растёт** при движении по стадиям и по завершённым активностям; в forecast включается взвешивание value × confidence.
- **Timeline** — единая лента: активности, заметки, письма (двусторонний синк Gmail/O365 с приватностью по умолчанию, блоклистами HR/юристов и исключением внутренних доменов; треды на таймлайне сделки и контакта).
- **Hot lead:** ручной флаг (иконка огня на странице лида или чекбокс при создании) → **оранжевые chevrons стадий, оранжевое имя, огонь у названия**; сам pipeline-виджет на карточке становится оранжевым вместо синего; отметка пишется в timeline; команда получает нотификации; фильтр «Only hot» в списках/board/задачах. Закрытые hot остаются с огнём, но теряют оранжевый текст — открытые всегда заметнее.
- **Направляющий процесс** (исторически сильная сторона): у каждой стадии — **rep instructions** («что делать на этой стадии»), автосоздаваемые task lists, **stage goals** с автопереходом («Send a quote» → выполнено → стадия сама двигается), автостарт/автостоп персональных email-цепочек по стадии.
- **Notetaker** — voice-to-text прямо в композерах: вкладки «Log an activity»/«Write a note» на таймлайне, диалог активности, email-композер. Наговорил — получил текст заметки. Все планы; free — 5 транскрипций/мес. (Отдельно AI-слой умеет резюмировать звонки/встречи Zoom/Aircall/click-to-call.)
- **AI recaps:** «узнать, что случилось и что дальше, не открывая лид» — резюме таймлайна из списка; AI lead summaries с кастомными инструкциями (2025–2026).

### 1.5 Сколько полей видит пользователь на новой сделке

| Система | Обязательные | Видимые по умолчанию | Приём |
|---|---|---|---|
| Close | имя Lead; у opp — status+value [ESTIMATED] | сайдбар: 4 секции | пустые секции сворачиваются в заголовки |
| folk | название deal | **4 поля** + связи | всё остальное — руками добавленные custom fields |
| Copper | Name + Primary Contact | ~5–6 полей [ESTIMATED] | настройка полей карточки per pipeline |
| Nutshell | связка контакт/компания + pipeline | value, confidence, close, stage | стадийные инструкции вместо полей |

Общее: **ни одна не показывает форму из 15+ полей**. Пустая карточка — это имя + пайплайн + 3–5 полей, остальное появляется по мере работы (folk — радикальнее всех).

## 2. Механики (18)

### M1. Close — несколько opportunities в сайдбаре lead-хаба
**Как работает:** сделки — компактные карточки в сайдбаре карточки клиента; до 1 000 шт.; активные первыми, закрытые — по дате резолюции.
**UI:** value + статус + контакт + комментарий; «+» рядом с заголовком секции; rich-text заметки и файлы прямо на opportunity.
**Аналог у нас:** company-360 показывает projects(client) компании; карточка сделки — отдельная страница.
**Перенять:** на карточке сделки — блок «Другие сделки этой компании» (карточки-виджеты со статусом/суммой/стадией), сортировка active-first. Для повторных продаж внедрений (ЧЗ → ERP → сопровождение) это прямой сценарий.

### M2. Close — единая лента активности с тогглами типов
**Как работает:** звонки, письма, смены статусов, задачи, заметки — одна хронологическая лента; фильтры по типу активности и по пользователю сверху ленты.
**UI:** текущий lead status закреплён над лентой с inline-редактированием.
**Аналог:** вкладка «Активность» (EntityTimeline + композер) — есть; фильтров по типу нет.
**Перенять:** тогглы-чипы над таймлайном («звонки / заметки / система / чат»), фильтр по автору. Дёшево, сильно ускоряет чтение истории.

### M3. Close — templates + snippets в композере
**Как работает:** шаблоны писем с переменными `{{contact.first_name}}`, `{{lead.name}}`, custom-полями и Liquid-логикой (`{% if %}`, фильтры, defaults). Сниппеты — куски до 2 000 символов, вставка по **«/»** в любом поле композера; меню отсортировано по частоте использования; сниппеты тоже понимают переменные.
**UI:** дропдаун шаблонов в композере; «/»-меню как в Notion.
**Аналог:** композер в «Активности» и КП — есть; сниппетов/переменных нет.
**Перенять:** «/»-сниппеты в композере таймлайна и в КП с подстановкой полей сделки/контакта (имя ЛПР, компания, стадия, сумма). Не требует email-интеграции — работает на заметках, чате, КП.

### M4. Close — follow-up reminder на письме + AI-драфт
**Как работает:** отправляя письмо, вешаешь reminder «если не ответят за N дней»; иконка часов на письме; если ответа нет — элемент падает в Inbox, и Close **генерирует AI-драфт follow-up письма**, который можно отправить сразу или отредактировать. Ответил клиент — reminder самоочищается.
**UI:** часы на письме в ленте; AI-драфт с ✨.
**Аналог:** «Следующий шаг + дата» — ручной; «шаг сделан» — ручной.
**Перенять:** механика «касание с контролем ответа»: у активности (звонок/чат/КП отправлено) — чекбокс «ждём ответ до …»; нет отметки «клиент ответил» к дате → строка в TodayView + AI-драфт следующего касания из контекста таймлайна (наш ai-run уже умеет сводки).

### M5. Close — Pipeline Guidance: suggested actions
**Как работает:** система флагует opportunities, требующие внимания: прошёл estimated close date, сделка застряла в стадии, клиент написал — команда не ответила. К каждому флагу — **контекстное действие**: «позвонить», «написать follow-up», «обновить статус».
**UI:** подсказки в Inbox и на карточке [точное размещение на карточке — не подтверждено].
**Аналог:** health score 0–8 + датчик времени в стадии + rotting в TodayView.
**Перенять:** у нас сигналы есть, но нет **привязанного CTA**. К каждому фактору health score прикрутить кнопку: «нет следующего шага» → «Запланировать шаг», «стадия дольше нормы» → «Открыть гейт стадии», «прошёл дедлайн» → «Сдвинуть/закрыть». Сигнал без кнопки — просто упрёк.

### M6. Close — Call Assistant: транскрипт как навигация
**Как работает:** авто-транскрипция и summary звонков >30 сек; транскрипт с таймстемпами — **клик по фразе перематывает запись**; спикеры размечены; поиск по транскриптам и внутри звонка, и по всей организации через фильтры. 20 языков, включая русский. $50/мес + $0.02/мин.
**Аналог:** `transcripts` + `ai_runs` — есть; клика-перемотки и сквозного поиска нет.
**Перенять:** клик по фразе транскрипта → seek видео/записи (у нас файлы/видео на карточке уже есть); поиск по транскриптам в сегментах — дальний прицел.

### M7. Close — AI Lead Summary
**Как работает:** AI-сводка лида из недавних активностей, custom fields, opportunities, задач и контактов; кнопки 👍/👎 для качества; Pro+.
**UI:** доступна с карточки лида; используется перед звонком/письмом.
**Аналог:** AI-модалка (бриф/сводка) — есть, паритет+.
**Перенять:** мелочь, которой нет: **штамп «сводка от {дата/время}» + кнопка refresh + 👍/👎** (фидбек копить в `ai_runs` для настройки промптов).

### M8. Close — каденция видна с карточки (Workflow Runs)
**Как работает:** enrollment контакта в workflow управляется с карточки: меню «⋯» контакта → **Manage Workflows** — список ранов с текущим статусом/шагом, pause/resume, запуск нового. Активности workflow пишутся в общую ленту. Отдельного постоянного виджета «каденция» на карточке нет — управление спрятано в меню контакта.
**Аналог:** автокаденций нет; S29 — точечные правила.
**Перенять:** когда появится наш workflow-движок (P6 из close-analysis) — статус рана показывать бейджем на стейкхолдере («в каденции: шаг 2/5, пауза»), не отдельной вкладкой.

### M9. folk — сделка из 4 полей
**Как работает:** дефолт Deal = Status, Value, Owner, Closed at. Больше система не просит ничего. Все остальные поля команда добавляет сама под процесс.
**UI:** side panel, не страница; связи многие-ко-многим с людьми/компаниями.
**Аналог:** наша карточка сделки заметно богаче (и это оправдано вертикалью), completeness-бейдж подталкивает к заполнению.
**Перенять:** **progressive disclosure**: новая сделка показывает ядро (компания, сумма, стадия, следующий шаг, ЛПР) + «Показать все поля»; completeness-бейдж раскрывает остальное по мере жизни сделки. Не выкидывать поля — прятать до востребования.

### M10. folk — reminders как первокласс на любом объекте
**Как работает:** реминдер на человеке/компании/сделке: title, due date+time, **repeat** (день/неделя/месяц/квартал/год), **private/shared**, назначение нескольких тиммейтов. Появляется: на профиле (по датам), в Notification Center (Upcoming/прошедшие), **иконкой часов в таблицах и канбане**, письмом на почту. Прошедшие остаются на профиле светло-серым — история касаний.
**Аналог:** «Следующий шаг + дата» на сделке (один, без recurrence и назначений) + задачи.
**Перенять:** (а) иконка-часы на карточках PipelineBoard у сделок с назначенным шагом/датой; (б) повторяющийся шаг («раз в квартал напоминать о сопровождении»); (в) прошедшие шаги не исчезают, а остаются серой строкой в таймлайне — сейчас «шаг сделан» историю в явном виде не копит [проверить в коде].

### M11. folk — Follow-up Assistant: «разговор затих + есть незакрытый next step»
**Как работает:** AI анализирует переписку (Gmail/Outlook/WhatsApp) и детектит пары условий: диалог неактивен N дней **и** в нём остался pending next step. Нужно ≥2 недавних обмена. Тогда предлагает контакт + **готовый драфт** follow-up. Настраивается: порог неактивности, фильтры контактов, каналы нотификаций (in-app, email, на профиле). В 2025 «находит в 3× больше поводов».
**Аналог:** «Остывают» (reconnect по last_touch) — по времени, без анализа «остался ли незакрытый вопрос».
**Перенять:** это самая точная формула nudge из всех четырёх систем: **тишина × незакрытое обещание**. У нас без email тоже считается: next_step с прошедшей датой + нет активности после — уже есть (rotting); добавить третий источник — «последнее сообщение в Чате от клиента без нашего ответа» и «КП отправлено, ответа нет N дней» → секция в TodayView + AI-драфт касания.

### M12. folk — Recap Assistant: резюме в заданном формате
**Как работает:** AI-резюме отношений с человеком/компанией/сделкой из писем, встреч, заметок, LinkedIn; **формат настраивается — MEDDIC, BANT или свой**; on-demand + refresh; для подготовки к звонку и передачи аккаунта.
**Аналог:** AI-модалка (бриф/сводка) — фиксированные пресеты.
**Перенять:** формат-пресеты сводки: «SPIN-разбор», «Бриф для передачи в внедрение» (прямо в Win Wizard), «Статус для руководителя». Шаблон формата — это просто параметр промпта, дёшево.

### M13. folk — Magic Fields: AI-колонки
**Как работает:** custom-поле типа «AI» — промпт исполняется per-строка: «Deal risk: Low/Med/High + причина», «Next step suggestion», «Lead score 0–100 + объяснение одним предложением», icebreaker. Сортировка/фильтр по AI-полю. С 2026 — Auto-fill AI, поля обновляются автономно.
**Аналог:** нет (health score — детерминированные правила, и это правильно для доверия).
**Перенять:** осторожно. Один эксперимент: AI-поле «Риск сделки + почему» в списке сделок, помеченное как AI-оценка, рядом с детерминированным health score. Не смешивать с гейтами.

### M14. Copper — zero-entry: письма прикрепляются сами
**Как работает:** синк Gmail → письмо контакта автоматически ложится на Person **и** на связанные Opportunity/Company (иерархия: person → opp+company; opp → company; company → никуда). Файлы из переписки сами оказываются на записи; Gmail-sidebar показывает карточку по открытому письму.
**Аналог:** email-интеграции нет (сознательно); у нас каналы — звонки, встречи, Чат.
**Перенять:** принцип «канал сам пишет в таймлайн»: когда появится telegram/email-контур — сообщения должны авто-привязываться к сделке по контакту, без ручного «прикрепить». Урок Copper (из efficient.app): авто-синк без AI-сводки превращает ленту в помойку — сразу проектировать схлопывание тредов + AI-резюме периодов.

### M15. Copper — task automation по стадии + activity types
**Как работает:** if/then: смена статуса/стадии → авто-задача (name, activity type, owner, due date); scope — на все пайплайны или на один. Activity types: 3 дефолтных + до 30 кастомных с иконками и флагом «counts as interaction» — от него считаются interaction stats и «last contacted».
**Аналог:** S29 `stage_entered → create_task` — есть ядро; типы активностей — фиксированные таблицы calls/meetings/tasks; last_touch есть.
**Перенять:** (а) в правило добавить activity type и относительный due date («+3 дня от входа в стадию»); (б) понятие «касание» формализовать: какие события двигают last_touch (звонок — да, внутренняя заметка — нет) — у Copper это явный флаг на типе.

### M16. Copper — Slipping / Top Deal: два флага на карточке
**Как работает:** Slipping — карточка краснеет после порога бездействия; Top Deal — зелёный $ при value выше порога. Оба — на канбане, пороги настраиваются.
**Аналог:** health score (0–8) — богаче, но нюанснее читается.
**Перенять:** идею **двух бинарных маркеров** поверх шкалы: «горит» (красный, из health-факторов тишины) и «крупная» (по budget порогу org) на карточках PipelineBoard. Шкала — для карточки, флаги — для сканирования доски за 5 секунд.

### M17. Nutshell — Hot lead: ручной командный приоритет
**Как работает:** продавец вручную жмёт «огонь» → лид оранжевый везде (chevrons, имя, pipeline-виджет), отметка пишется в timeline, **команда получает нотификацию**, всюду фильтр «Only hot»; в отчётах — разрез «Priority is Hot». Закрытые hot теряют оранжевый текст, но хранят огонь.
**Аналог:** нет. Health score — вычисленный, hot — субъективное «я в это верю».
**Перенять:** флаг «горячая» на сделке: ручной, один клик, нотификация команде, запись в таймлайн, фильтр в PipelineBoard + секция-приоритет в TodayView. Дёшево (~поле + фильтр) и закрывает реальную дыру: у вычисленного скоринга нет канала «чутьё продавца».

### M18. Nutshell — stage guidance + пост-close роутинг
**Как работает:** у стадии — rep instructions («что делать»), автосоздаваемый task list, **stage goals** с автопереходом при выполнении; после закрытия — **closed-lead follow-up pipeline**: won/lost автоматически уходят в отдельный пайплайн сопровождения/реанимации.
**Аналог:** гейты у нас жёстче (server-enforced, у Nutshell — мягкое «advance when goals met»); Win Wizard закрывает won-ветку. Lost-ветки нет.
**Перенять:** (а) **guidance-текст стадии** в кокпите: рядом с требованиями гейта — короткое «что сделать на этой стадии» (колонка в stage-словаре + рендер); (б) **Lost Wizard**, зеркальный Win Wizard: причина проигрыша + «вернуться через N мес» → сделка автоматически появляется в «Остывают» к дате. У Nutshell это доказанно работающий паттерн.

## 3. Визуальные приёмы: чем достигается простота и что приносится в жертву

| | Приёмы простоты | Жертва |
|---|---|---|
| **Close** | Один ствол — лента; всё второстепенное — в сайдбар-секции; сделка — лёгкий виджет, а не страница; действия (позвонить/написать) — в один клик из шапки; минимум цвета — цвет только у статусов | Карточка бесполезна без подключённой почты/телефонии; сделка-виджет не вмещает богатый контент (файлы/notes добавили только в 2026); канбан вторичен |
| **folk** | Side panel вместо страницы; 4 поля; Notion-эстетика таблиц; иконки-часы вместо отдельных списков задач; AI прячет рутину в фон | Сделка почти без собственной глубины — истории живут на контактах; нет стадийных гейтов и процессов; отчётность слабая; для сложного B2B-цикла каркаса мало |
| **Copper** | Мимикрия под Material/Gmail — интерфейс «уже знаком»; CRM приходит в почту (sidebar), а не наоборот; два цветовых флага вместо скоринга; поля карточки настраиваются per pipeline | Активити-лента замусоривается авто-синком (главная жалоба ревью: «wished there was just an AI summary»); вне экосистемы Google ценность резко падает; ручная поддержка данных |
| **Nutshell** | Цвет как статус (оранжевый hot поверх синего); chevron-пайплайн прямо на карточке; инструкции стадии вместо пустого экрана «что дальше»; voice-вместо-набора текста | Визуально плотнее и «старомоднее» конкурентов [ESTIMATED]; много механик → больше настроек admin'а; auto-advance стадий несовместим с жёсткими гейтами |

Сквозное наблюдение: **все четыре прячут форму и выпячивают ленту+действие.** Ни у одной карточка не открывается «анкетой». И у всех «следующее касание» решается не полем, а активным механизмом: reminder с контролем ответа (Close), детектор тишины (folk), авто-задача стадии (Copper), инструкция стадии + hot (Nutshell).

## 5. Топ-7 переносимых идей для dashboard-crm

1. **«Тишина × незакрытое обещание» — умный follow-up nudge** (folk M11 + Close M4). Расширить rotting: не только просроченный next_step, но и «клиент написал в Чат — не отвечено», «КП отправлено — нет реакции N дней». Каждому срабатыванию — AI-драфт следующего касания (ai-run по таймлайну). Секция в TodayView + бейдж на карточке. ~0.5 спринта без email-контура.
2. **Guidance-текст стадии в кокпите** (Nutshell M18a). Рядом с гейтом — 1–2 строки «что делает продавец на этой стадии». Пустая новая сделка перестаёт быть немой: кокпит сам говорит, с чего начать. Словарь стадий + рендер, ~0.2 спринта.
3. **Hot-флаг сделки** (Nutshell M17). Ручной «огонь»: один клик, запись в timeline, нотификация команде, фильтр в PipelineBoard, приоритет в TodayView. Канал для чутья продавца, которого нет у вычисленного health score. ~0.2 спринта.
4. **CTA на каждом сигнале здоровья** (Close M5). Каждый фактор health score и датчик стадии получает кнопку действия («Запланировать шаг», «Открыть гейт», «Сдвинуть дедлайн»). Сигнал без кнопки — упрёк, с кнопкой — механика. ~0.3 спринта.
5. **«/»-сниппеты с переменными в композере** (Close M3). Библиотека сниппетов org с подстановкой `{{deal.*}}/{{contact.*}}`, вставка по «/» в композере Активности и КП, сортировка по частоте. Готовит почву для будущего email/telegram. ~0.3 спринта.
6. **Lost Wizard + возврат в «Остывают»** (Nutshell M18b, зеркало Win Wizard). Причина проигрыша (словарь) + «вернуться через N мес» → сделка в дату всплывает в reconnect-очереди. Закрывает жизненный цикл: won → внедрение, lost → nurture. ~0.3 спринта.
7. **Формат-пресеты AI-сводки + refresh со штампом** (folk M12 + Close M7). В AI-модалку: форматы «SPIN-разбор», «Бриф передачи внедрению» (встроить в Win Wizard), «Статус для руководителя»; штамп «сводка от {дата}», кнопка refresh, 👍/👎 в `ai_runs`. ~0.2 спринта.

**Резерв (8–10):** progressive disclosure полей новой сделки (folk M9); два бинарных флага «горит»/«крупная» на канбане поверх health score (Copper M16); voice-to-text в композере заметок через Web Speech API (Nutshell Notetaker).

**Сознательно не брать:** голосовых агентов (Chloe), автономное AI-заполнение полей (folk Auto-fill — конфликт с доверием к гейтам), auto-advance стадий (ломает server-гейты — нашу главную фичу), email-first ленту без плана схлопывания тредов (урок Copper).
