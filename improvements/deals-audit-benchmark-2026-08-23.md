## 0. Вердикт

Карточка сделки dashboard-crm по **механике процесса** — выше среднего западного уровня: кокпит стадий с server-enforced гейтами и датчиком времени сопоставим только с Zoho Blueprint (у остальных enforcement мягкий или обходится API — задокументированная дыра HubSpot), фокус-панель «Следующий шаг» — паритет с Pipedrive-паттерном, «цена пустоты» в completeness — приём, которого нет ни у кого из 17. Отставание сосредоточено в трёх зонах: **(1) сигналы без объяснения и действия** (health «Критично» — без причин, тренда и кнопки), **(2) слепая зона между активностью и полями** (транскрипты и AI есть, но не предлагают обновления полей — главный тренд 2025–2026, HubSpot Smart Deal Progression GA), **(3) деньги одной цифрой** (бюджет без состава КП, прогноз без слоя уверенности). Визуально карточка спокойная, но пустые состояния занимают больше места, чем данные, а красный горит на новой сделке двух дней от роду — ложный сигнал.

Счёт визуального аудита: **0 Blocker · 2 High · 4 Medium · 3 Polish**.

## 2. Главные паттерны рынка 2025–2026 (сквозь 17 CRM)

1. **AI мигрирует из «кнопки сбоку» в ткань карточки — но только через предложения.** HubSpot Smart Deal Progression (GA март 2026): транскрипт → предложенные апдейты полей/задачи/письмо → apply одним кликом. Salesforce Agentforce (Winter '26): предлагает stage/next steps, HITL + **whitelist полей** (пришли к нашему же паттерну `set_field` whitelist). Clarify: «never auto-updates your records» — всё через suggestions. Attio: HITL-превью + confidence + citations. Консенсус всех: **тихой записи в поля не делает никто** — только предложение с объяснимостью и источником.
2. **Rule-based здоровье реабилитировано.** Monday Deal Insights (2026, beta) — не ML, а каталог явных сигналов (нет ЛПР / единственный контакт / тишина N дней / стагнация) с настраиваемыми порогами. Pipedrive Pulse официально «not AI — fixed rules and time triggers». ML-скоринг (Zia, Freddy, HubSpot deal score) требует истории closed-won, которой у команды 5–15 нет — оба вендора признают это порогом автовключения. Наш health 0–8 — актуальная архитектура; отставание в **подаче**: тег-вердикт + топ-причина + тренд + CTA + фидбэк (формула Freddy).
3. **Стадия — контейнер знаний, а не только гейт.** Salesforce Path: Key Fields + Guidance for Success на каждой стадии; Nutshell: rep instructions per stage; Zoho Blueprint During: попап перехода собирает поля/чеклист/заметку. У нас гейты сильнее всех, но стадия молчит о «зачем и как».
4. **История изменений — штатная вкладка.** Pipedrive Changelog (field-level), Salesforce Opportunity History (Stage/Amount/Probability/Close Date автоматически), Zoho Stage History с длительностями, Close Event Log (авг 2026). Наша `stage_transitions` пишется с 078 — но UI нет.
5. **Деньги сделки = состав, слой уверенности и сигнал прочтения.** Line items с автосуммой — у всех; forecast category поверх стадий (Salesforce Pipeline/Best Case/Commit) — самый дешёвый прогнозный слой; трекинг просмотра КП (HubSpot окт 2025, Pipedrive Smart Docs) — самый дешёвый buying-signal.
6. **Очереди вместо списков.** Pipedrive Pulse: триада Follow-ups / Overlooked / Opportunities с quick actions и hide; folk Follow-up Assistant: «разговор затих × незакрытое обещание»; Close Inbox. Наш TodayView уже unified — не хватает разбивки на очереди и механики «скрыть».
7. **Плотный спокойный UI имеет формулу.** Twenty [COMPUTED из кода]: база 13px, 3 веса, 4 серых текстовых роли одной 12-шаговой шкалы, границы светлее текста, фоновые перепады ~1%, тени только на оверлеях, бейджи «фон шаг 3 / текст шаг 11» одной палитры. Attio: «The best version always has less in it than the one before»; лиловый маркер = данные машинного происхождения.

## 3. Рекомендации (приоритизированы)

> Эффорты — в спринтах CC. Детальная механика каждой — в файлах §6 (ссылки в скобках).

### P0 — флагман

**R-1. Слой AI-предложений по полям сделки** (~1 спринт) — [HubSpot §2.10, ai-native §М3/М10/М14, Salesforce §4]
Пресет `meeting_protocol`/разбор транскрипта возвращает structured JSON `{field_updates, tasks[], followup_draft}` → полоса предложений на карточке: «Из встречи 21.08: бюджет → 2,4 млн; срок → Q4» → диф «старое → новое» с per-field Accept/Reject → apply одной транзакцией через существующий whitelist. `ai_suggestions (org_id, project_id, source_ref → ai_runs, field, old, new, status)`; отклонённое не возвращается. Фундамент готов: transcripts, ai_runs + outcome (S-AI-OBS-2), AI Hub, whitelist. Это ровно тот паттерн, который HubSpot довёл до GA, а Salesforce — до whitelist-конвергенции с нами. Закрывает главный тренд без email-интеграции.

### P1 — сигналы и знание стадии

**R-2. Health v2 — сигнальная панель** (~0.6) — [zoho-fresh-monday §3, HubSpot §2.8, smb §M5]
Разбить 0–8 на именованные сигналы (нет шага / единственный стейкхолдер / тишина N дней / стагнация в стадии / просрочен дедлайн); вердикт-тег («Новая / В порядке / Требует внимания / Киснет») + топ-причина + **CTA на каждом сигнале** («Назначить шаг», «Добавить ЛПР») + grace-period новых сделок + история скора (лог при изменении, спарклайн). Пороги per stage — тем же резолвером, что уже кормит датчик кокпита (`useDwellThresholds` → `resolveStageNorm`), вторую формулу не заводить. Закрывает F-01/F-02.

**R-3. Пульс-очереди в TodayView** (~0.5) — [Pipedrive §2.12, smb §M4/M11]
Три вкладки с каунтерами: «Follow-ups» (сегодняшние шаги, реакции) / «Упущенные» (просрочки, тишина N дней) / «Новые без шага»; quick actions на карточке очереди; `dismissed_suggestions` для «скрыть до завтра». Всё rule-based поверх готовых `getDealHealth`/`compareByNextAction`.

**R-4. Guidance стадии в кокпите** (~0.3) — [Salesforce §2.1, smb §M18, роадмап A3 — рынком подтверждён]
Org-таблица `(org_id, stage_id, guidance)` (стадии — глобальный словарь, атрибуты — отдельной таблицей): 2–4 строки «что делает продавец на этой стадии» + ссылки на регламенты ЧЗ/шаблоны КП; рендер в кокпите рядом с гейтом. Пустая новая сделка перестаёт быть немой. Позже — «создать задачи по плейбуку».

**R-5. Вкладка «История»** (~0.7) — [Pipedrive §5.2, Salesforce §2.14, Zoho §M5]
Лента `stage_transitions` (кто/когда/длительность, cumulative time при возвратах, бейдж «пинг-понг») + field-level changelog по whitelist полей (`field_changes`, generic-триггер) + push count дедлайна («дата переносилась ×N»). Снимает споры «кто сдвинул дедлайн» и даёт AI-пресет «траектория сделки».

### P2 — деньги и стейкхолдеры

**R-6. Line items в КП + автосумма** (~0.6) — [Pipedrive §5.4, HubSpot §2.11]
`quote_items (quote_id, name, qty, unit_price, discount_pct, kind: license|work|hardware|support)`; сумма derived; accept → budget как сейчас. Плюс отчёт «структура выручки по kind» — для ниши (лицензии 1С / работы / оборудование / поддержка) это и есть отсутствующий продуктовый каталог, без каталога.

**R-7. Активное КП (Start Sync) + трекинг просмотра** (~0.7 суммарно) — [Salesforce §2.13, Pipedrive §5.3, HubSpot §2.12]
(а) У сделки много КП, ровно одно `is_active`; budget следует за активным, смена — событие timeline. (б) Публичный маршрут `/q/[token]` → `viewed_at` + счётчик; событие «КП открыто» в timeline, health-сигнал и карточка в Follow-ups («КП открыто вчера — позвони»). Слепая зона sent→accepted закрывается самым дешёвым buying-signal рынка.

**R-8. Forecast category поверх стадий** (~0.4) — [Salesforce §2.8, zoho-fresh-monday §M12]
Поле `forecast_category (pipeline|best_case|commit|omitted)` с дефолтом от стадии и ручным override; сводка «Commit / Best Case / Pipeline» на overview; группировка PipelineBoard по категории. Одно поле — язык прогноза без ML. (Альтернатива Pipedrive-стиля — `probability_override` отдельным полем; выбрать одно, рекомендация — category: она читается менеджментом.) ⚠️ Не трогать `probability` — его пишет триггер.

**R-9. Стейкхолдеры: primary + вовлечённость** (~0.4) — [Salesforce §2.11/§2.7, ai-native §М7]
Счётчик активностей per стейкхолдер за 30 дней (из timeline по contact_id) + подсветка single-threaded («вся активность на одном человеке») — сигнал в Health v2. Primary уже вычисляется из contact_id — остаётся счётчики и warning.
